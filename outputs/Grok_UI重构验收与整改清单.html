Grok 全量 UI 重构验收与整改清单

审查对象：提交 eec19f8（相对 d3ca7b8）。依据冻结 V1.2 PRD、V1.2 HTML 设计稿与 Grok 实施交接文档。

审查日期：2026-08-27范围：静态代码 + 定向测试结论：不应按“全量 UI 重构完成”验收

结论

“整体样式没有明显改变”的判断基本成立。更准确地说：本次已经接入主题 Token、部分页头、QSS 统一、若干 Splitter 与 SQL AI 助手可见名修正；但核心技术页尚未完成设计稿要求的结构性重构、窄屏回退、统一 Splitter 能力和验收矩阵。因此它属于“全局基础视觉收口 + 局部页面接入”，不是 C 方向的全量 UI 重构完成态。

不能把“存在四主题、页头和 QSS”视为“设计稿已落地”。设计基线要求的是工作区层级、信息密度、页面结构、风险上下文和响应式行为一起改变。

已证实的有效改动

  • 四主题并非仅定义：ThemeManager.apply() 会应用 Palette 与 QSS，设置页已提供主题卡。
  • SQL 控制台用户可见名称保持“AI 助手”，草案标签保持“SQL 草案 · 未执行”，未把 TamengAgent 暴露为 UI 名称。
  • 接口请求体与响应区已有上下 Splitter，并设置了 240px / 120px 的最低高度。
  • 定向测试执行完成：73 项通过，39.5 秒。但该结果仅证明当前测试覆盖的逻辑未失败，不等同于设计稿像素、DPI 和真实窗口走查通过。

因此，下文的“代码已证实”可直接作为整改依据；“需走查”必须由 Grok 提供运行截图或录屏证明。未提供截图矩阵前，不能宣称“设计稿已完成对齐”或“全量响应式验收通过”。

必须先收口的阻断项

阻断 1

接口排查的“请求验证”仍不是设计稿规定的两行紧凑上下文，发送语义仍过于泛化

代码已证实：环境、Base、方法/URL、HTTPS 被拆成多行；发送按钮仍设置为“发送”。认证是否携带也没有作为用户可见的紧凑状态常驻。

panels/interface_debug_panel.py:646–718；rt_send_btn.setText('发送')

必须修改：

  1. 重排为最多两行，而不是继续叠字段：
    第 1 行：环境 | Base | 认证状态 | HTTPS 校验状态；第 2 行：方法 | 最终 URL | 动态主按钮。
  2. 主按钮动态显示“向 {环境名} 发送请求”或“向 {Host} 发送请求”；未选环境时显示“选择环境后发送”并禁用。不得再出现裸“发送”。
  3. cURL / Postman / 导出等草稿动作放到“更多操作”，并保持与真实发送完全不同的调用路径。
  4. 发送确认首屏必须同时展示：方法、最终 URL、环境、Host、认证携带状态、是否 HTTPS 校验、生产影响提示和取消入口。

验收：提交请求验证默认态、未选环境态、生产环境确认态三张截图；提供对应控件断言，证明按钮文字会随环境与 Host 动态变化。

阻断 2

日志/SSH 与 SQL 控制台没有真正实现 Compact / Narrow 回退，核心工作区结构基本未变

代码已证实：apply_layout_mode() 在日志/SSH 和 SQL 控制台中仅隐藏副标题，未根据档位切换 Splitter、Tab、Drawer 或纵向布局。这与“窄屏不硬挤多栏”的设计基线不符。

panels/ops_log_panel.py:2543–2545；panels/ai_workbench_panel.py:623–625

必须修改：

  1. SQL 控制台：Wide 保持对象树 / 编辑器 / AI 助手 + 底部结果；Standard 将右侧 AI/详情变为抽屉或可切换侧栏；Compact 将对象树变成明确“显示对象目录”入口；Narrow 只保留编辑器与当前结果，对象目录和 AI 助手必须转为可唤起 Tab/Drawer，不能保留不可读三栏。
  2. 日志/SSH：Wide 保持主机/日志、终端/预览、查询/导出信息层级；Compact/Narrow 将服务器与远端目录转为可唤起面板，终端或日志预览占据主阅读区，底部操作按需展开。不得仅隐藏说明文字。
  3. 接口排查：与上述策略一致：Narrow 下会话列表、请求验证与结果必须有明确的切换/抽屉入口，而非靠压缩列宽保持同屏。
  4. 实现前先给出每页 Wide / Standard / Compact / Narrow 的状态表，标明“常显 / Drawer / Tab / 隐藏并提供入口”。

验收：至少对接口排查、日志/SSH、SQL 控制台提交 1440×900、1280×800、1100×720、960×640 的默认态与一个运行/结果态截图；关键对象、环境、风险、主操作和取消路径均不能被裁切。

阻断 3

Splitter 只做了“能拖 + 双击复位”的基础壳，未达到全局可恢复、可访问、安全夹紧的规范

代码已证实：公共助手能设置不可折叠、6px 把手、定时回调和双击默认尺寸；但多个核心页面传入 on_changed=None 且未传入 saved 值，因此并没有真正保存/恢复布局。助手也没有 handle accessibleName、键盘调整或 DPI/min-max 夹紧。

ui/splitter_prefs.py:29–72；ai_workbench_panel.py:552–553；ops_log_panel.py:2182

必须修改：

  1. 把 install_splitter_prefs 补为真正的公共能力：键必须是 pageId + 当前 Tab/模式 + layout bucket，仅保存非敏感尺寸比例；释放后 250ms 防抖写入。
  2. 恢复时按当前有效画布、DPI、最小/最大尺寸夹紧；无效旧值回退当前页默认安全比例。不能把 SQL、报文、日志、凭据或正文写入偏好。
  3. 每个 handle 设置明确 accessibleName、focus 策略、可见焦点和键盘等价调整；双击仅重置当前页面/Tab/模式。
  4. 给接口、日志/SSH、SQL、加解密、格式、模型对话、需求管理等实际有多展示区的页面接入保存/恢复；设置页“复位界面布局”必须覆盖这些已接入页面，不能只复位需求管理和接口排查。

验收：每个 P0 页至少证明：拖到两个方向安全下限、不能折叠为 0、双击复位、关闭/重新进入后恢复、切换 DPI/窗口档位后安全夹紧、键盘能聚焦与调整。

重要整改项

重要 1

“单页一个主操作”测试被 PRIMARY_BASELINE 豁免掩盖，不能作为验收依据

代码已证实：接口排查允许 2 个 primary、日志/SSH 允许 6 个、需求/格式允许 4 个；所谓终态测试对大于 1 的页面直接 continue，没有执行任何失败断言。

tests/test_page_skeleton.py:40–45，101–107

必须修改：逐页把除唯一主流程外的按钮降级为 secondary / ghost / 更多操作；文件库九按钮保持文字、顺序、行为不变，但不应全部维持 primary 视觉。测试改为所有 Stack 页面面板树中的 #primary-btn ≤ 1，Dialog 内按钮不计入。删除“只记录欠账但测试通过”的空断言。

重要 2

日志/SSH 的关键动作还未按“对象先于动作”收口

代码已证实：仍有“发送”“清屏”等泛化文本，虽然 Tooltip 略有补充，但不满足设计稿的可见文字要求。

panels/ops_log_panel.py:2413，2522–2524

必须修改：“发送”改为“执行到当前终端”或“发送并执行”；“清屏”改为“清空终端显示”。连接、导出、目录、日志尾部等按钮也按 V1.2 文案表逐项校对。不得借文案重命名改变 SSH 执行、会话或导出业务语义。

重要 3

全局壳层只完成一部分，页面结构仍各自手写，导致视觉变化浅

判断：多页已补 make_page_header()，QSS 也统一了按钮、表格、Tab、Dialog、Menu 和部分轻玻璃表面；这说明“完全没有改”不准确。但 L2 工具栏、L3 筛选条和 L4 内容区在技术页仍不一致，页面只是加了页头而非按设计稿重新分层。

必须修改：先固定可复用的页面骨架与样式契约，再逐页迁移。每页必须明确 L1 页头、L2 工具栏、L3 筛选条、L4 主工作区；技术页至少 65% 面积给编辑器、列表、终端或结果，低频说明/历史/配置收纳到正确位置。不要新增“卡片墙”或用大段说明填空。

哪些不需要误改

P2 没有高频动画不是问题，反而符合禁止项。设计基线明确禁止页面转场、扫描线、呼吸灯、连续 spinner、表格/终端逐项动画。当前未见 QPropertyAnimation 或高频 QSS animation，这一点应保持。
  • 可保留 Tab、Menu、Drawer、Dialog、Toast、Loading 的 120–180ms 轻淡入/短过渡。
  • 需要补的是“减弱动效”设置及它的运行态验证，而不是添加显眼动画。
  • 四主题已具备可应用路径；下一步应做四主题下的真实页面可读性截图，不应重做主题体系。

DPI 与测试整改

当前测试验证了断点函数和少量 offscreen 逻辑，但没有真实的尺寸 × DPI × 页面状态矩阵。测试通过不能替代走查。

必须覆盖的缩放100%、125%、150% Windows DPI。
P0 必测状态默认、空态、Loading、失败/取消、风险确认、Splitter 极限与复位。

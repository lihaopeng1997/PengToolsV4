用户于 2026-09-18 确认：后续功能构思、实现步骤、设计和方案交给 Web GPT，结合 Git 上的实际代码处理；不涉及截图的代码可先发布供 Web 复核，本机负责运行和视觉验收。

## 分工

- 本地主代理收集用户需求、业务边界和当前证据，准备精简 Web 输入；不以本地推测代替 Web 方案。负责检查输出是否符合当前源码和用户授权、分解实施包、审查及验收。
- Web GPT 负责功能构思、设计、架构/实现方案、步骤与代码复核。必须锁定仓库、分支、完整提交 SHA，读取实际函数和调用链；发现证据缺失时明确标注，不假定看得到本机未提交文件或运行窗口。
- Luna Max 负责已审定实施包、必要自测和返修；主代理负责选择提交范围和发布，不让实施代理整体暂存工作树。

## 每包流程

1. 核对工作区与远端，将目标、约束、涉及路径、明确问题和证据整理为 Web 输入。
2. 已授权发布的代码完成必要检查后，仅提交该包并推送指定分支。原有遗留文件、其他未完成包、真实配置和凭据不纳入。
3. Web 输入指定可读取的完整提交 SHA，要求返回基于源码的方案或具体审查问题；将本机未发布内容和截图/真实环境待验收单列。
4. 主代理检查 Web 输出的引用、触发条件及边界，再给 Luna 最小实施/返修任务。必要检查通过后发布新的明确提交供复核。
5. 窗口效果、物理操作、实际模型/数据库和发布验证由本机分项报告，不能用代码审查代替。缺测试环境不使用生产环境补证据。

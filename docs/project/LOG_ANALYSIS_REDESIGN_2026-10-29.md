## 一、先把用户在做什么说清楚

页面明确提供三个页签：**人工排查｜历史日志分析｜实时日志监控**。历史任务列表放在两种 AI 模式各自的“任务记录”中，不能和“历史日志文件”混用名称。

| 对比项 | 历史日志分析 | 实时日志监控 |
| --- | --- | --- |
| 解决的问题 | 已经发生的错误：分析指定文件和范围 | 从现在开始观察新输出，发现新错误 |
| 日志来源 | 本地文件或远端文件，可多选 | 一台服务器、一个服务、一个明确的正在写入的文件 |
| 读取终点 | 启动时冻结的文件边界，读到边界即完成 | 持续读取新增内容，直到暂停或停止 |
| 主操作 | 开始排查／取消读取 | 开始监控／暂停采集／停止监控 |
| AI 工作 | 针对已读范围分析、追问、补查、生成报告 | 可自动分析新异常，也可手动提问、生成阶段报告 |
| 不选模型 | 能读取、筛选、统计；明确显示“未启用 AI” | 能采集、发现异常；明确显示“仅监控” |
| 完成或停止之后 | 可继续查看与分析保留的证据 | 可继续查看与分析停止前的证据 |

**同一个 app.log 可以用于两种模式，模式取决于用户意图，而不是文件名。** 历史模式只读取开始时已有内容；后续追加内容属于新的读取任务或实时监控。模式切换只切换工作区，不自动改变或停止正在运行的任务。

## 三、历史日志分析：完整操作流程

### 1. 选择来源和文件

顶部固定显示 `[本地文件] [服务器文件]` 切换。

- 本地：选择文件、拖入文件、移除所选；展示名称、大小、修改时间、路径。无需 SSH 连接。
- 远端：服务器 → 服务 → 浏览日志文件。复用既有远端目录列举能力，直接在本页选文件，不再要求跳到人工排查复制路径。
- 服务配置是目录时展示文件列表，支持名称和日期筛选；服务配置是文件时预选该文件。界面分别提示目录、文件不存在、无读取权限和连接失败。
- 首批支持纯文本 `.log/.txt/无扩展名` 和常见 `.gz` 归档。gzip 流式解压，有解压输出限额；其他压缩包明确标注暂不支持，不自动展开未知目录树。
- 显示已选文件清单；文件名可以重复，来源 ID 和完整路径用于区分。

### 2. 明确排查范围

范围提供互斥选项：**整个所选文件／日志时间范围／末尾指定行数**。关键词、traceId、级别是独立筛选条件，不能把关键词作为唯一异常识别入口。

- 默认整个所选文件，但先估算总量并展示限额。超过本次额度时提供缩小范围或分批读取，不静默只取尾部。
- 时间范围填写起止时间、服务时区、日志时间格式。先用有界样本验证解析，再启用时间筛选；不确定时不能标记为“已查某时段”。跨年、无年份、无时区需显示采用的解释规则。
- 堆栈续行继承同一事件头的时间，不能因没有时间戳而过滤掉。无法归属的行计入“时间不明”，可单独查看。
- 多文件按源分别解析；展示日志时间与采集时间两列，不能把文件修改时间当成事件发生时间。
- 初始建议额度：每任务最多20个文件、解码输入合计200 MiB；属于待压测参数，放高级设置。压缩文件按解压后实际字节计量。达到额度标记“部分读取”，显示未读文件和范围；允许下一批继续。

### 3. 开始排查和查看结果

主按钮为 **开始排查**，不是开始监控。点击前固定文件清单、读取边界、范围、筛选条件和模型。

流程：校验文件 → 分块读取 → 解析与聚合 → 展示异常 → AI分析（已选模型时）→ 完成。

- 读取进度展示文件数、已处理字节、异常组数；进度可确定时显示百分比。AI阶段单独显示当前步骤，不给虚假整体百分比。
- 读取时用户可取消；保留已采集结果，明确“部分读取”。读取完成释放采集连接，分析和对话继续可用。
- 实际未发现异常显示“已检查所列范围，未识别到异常”，不写“系统正常”。无关键字命中、空文件、解析失败分别显示。
- 新提问默认基于本次覆盖范围；补查可以访问已授权文件清单内的内容。若源文件已经变化，保留旧证据，提示重新读取，不把新旧内容混合成同一结论。

## 四、实时日志监控：完整操作流程

选择服务器、服务、具体文件后，先明确 **监控起点**：

1. **从现在开始**（默认）：固定当前EOF，后续只处理新增字节。
2. **先读取末尾 N 行，再持续监控**：首屏明示补读范围与字节上限，补读数据标注“启动前补读”。不能用“最近10分钟”替代实际行数覆盖。

采集周期、WARN、上下文行数、重复异常合并、自动分析冷却等进入“高级设置”，不再占满左侧首屏。模型和“自动分析新异常”放在 AI 区，默认允许仅监控。

开始后固定展示：监控目标、开始时间、最后成功轮询、最后收到日志、读取位置、积压量、连接状态、AI状态。**最后成功轮询**和**最后收到日志**必须区分，方便判断暂无输出还是断线。

| 控制 | 明确行为 |
| --- | --- |
| 暂停采集／恢复采集 | 暂停读取，保存偏移；恢复时检查文件身份并补读，积压超限时提示缺口 |
| 自动分析开关 | 控制新异常是否自动排队；关闭不取消正在输出的回答 |
| 停止本次分析 | 只取消当前模型请求，采集继续 |
| 停止监控 | 停止该任务采集、自动派发，释放连接；保留证据、报告及后续手动分析能力 |
| 继续监控 | 检查旧文件和检查点，展示中断范围；文件已轮转则新建采集段并标记缺口 |

默认展示异常列表，支持切换“实时日志”。用户向上阅读时不抢滚动；显示“新增N行”，点击后跟随。重复异常更新次数，新异常或证据明显变化才进入自动分析队列；沿用单并发、队列限额和冷却策略。

实时监控不等于人工终端的输出转录；第一阶段仍跟踪文件。容器 stdout、journal、终端输出等应独立列为后续数据源，不能用选文件界面假装支持。

- 所有只读取证在已选范围内自动执行；当前方案不开放任何远端新增、修改、删除命令。

## 六、Agent 与证据设计

### 6.1 AI分析与采集解耦

`AnalysisTask` 保存意图与状态；`CaptureSession` 执行有限读取或持续跟踪；`EvidenceStore` 保存脱敏证据和覆盖范围；`AnalysisRun` 消费证据。历史完成和监控停止都不应禁止后续提问。

建议固定任务契约：

- `task_id`、`mode=history/live`、`source_kind=local/remote`。
- 不含凭据的 `source_ids`、文件清单、编码、筛选规则、模型ID；连接配置由宿主单独持有。
- 每文件 `capture_id`、源身份、起止偏移、启动边界、读取代次、日志时间解释、已读/缺失范围、解析失败计数。
- 独立 `capture_state` 与 `analysis_state`；报告绑定不可变 `snapshot_id`。

### 6.2 取证工具

复用现有 AgentRunner 与模型适配，不另写提示词聊天循环。

| 工具 | 允许能力及必要返回 |
| --- | --- |
| list_sources / get_coverage | 当前授权文件和实际已读范围、缺口 |
| list_events / read_event | 异常统计、完整脱敏堆栈、来源定位 |
| search_logs | 在明确来源及范围内检索，返回覆盖范围、扫描量、是否完整、续查游标 |
| read_context | 根据证据定位读取前后文，跨块处理多行堆栈 |
| read_log_range | 保留有界读取，并校验源身份、读取边界和代次 |

请求不得把整个日志灌入模型。程序完成流式扫描、索引、脱敏、分组；模型先看摘要和代表事件，再按引用补查。500 KiB沿用现有应用预算，结合实际模型限制留出输出和工具空间；压缩保留任务范围、已确认事实、证据ID、未完成项，不将旧回答当作新证据。

历史大文件不能复用“只保留最近200组事件”的环形缓冲作为完整索引。设计有配额的本地脱敏事件索引和证据片段存储；配额耗尽标记部分完成，不能继续宣称全量统计。实时模式可以保留有界窗口，但报告必须记录淘汰和中断。

每次回答标明事实、推断与待验证项。模型超时支持取消、保留已读证据并重试；失败不阻塞读取，也不清空输入或跳回聊天顶部。流式展示正文和简要执行步骤，不展示模型内部推理。

### 6.3 文件一致性

历史任务启动时冻结文件上界，后续追加忽略；读取期间遇到截短、替换、大小或锚点异常，标记源变化并停止该文件，不能报告完整读取。通过普通SFTP元数据和锚点无法保证检测所有同大小原地改写，应明确这不是事务快照；严格取证可先复制不可变样本再分析。

多文件证据引用使用文件ID+采集代次+偏移；只有实际维护行号时才显示行号。gzip使用解压流偏移，不冒充压缩文件字节位置。远端补查重新打开专属只读连接，完成即释放；停止监控不重新开启持续采集。

## 七、报告与任务记录

报告包括：模式、文件与范围、日志时区、实际覆盖、中断/截断、异常统计、证据摘录、已确认事实、原因假设、建议和待验证项。

- “导出证据汇总”不需要模型；“生成AI报告”明确启动一次模型整理。两者都先生成可编辑草稿。
- 实时报告固定生成时的快照，之后日志增长不改写已生成的结论；再次生成产生新版本。
- 人工编辑的报告不被自动分析覆盖；保存覆盖已有文件沿用确认流程。第一阶段Markdown，Word后续。
- 任务记录按历史分析/实时监控分组，显示来源、范围、时间和状态。打开记录可看缓存证据并分析；缺失正文或源文件变化时明确说明，不能虚构恢复全文件。
- 旧 `log_analysis/v1` 监控记录迁移标记为live；恢复用户手动触发，不能自动连接。缓存格式升级需独立版本兼容，不破坏旧记录。

## 九、验收清单

1. 进入历史页可选本地/远端文件，进入实时页必须选具体远端文件；设置不串用。
2. 历史日志错误只在文件开头、末尾无错误，整文件模式仍能发现；不受旧256 KiB尾部限制。
3. 历史读取开始后追加新错误不进入本次结果；再建任务才读取新范围。
4. 历史完成、用户取消读取、实时停止后，保留证据可提问并生成报告，覆盖标签准确。
5. 实时“从现在”不计入旧错误，“补读末尾”将旧错误标为补读；采集成功但无新增显示健康空闲。
6. 时间格式不识别、时区缺失、跨日堆栈分别提示，无法完整过滤时不宣称完整时段。
7. 多文件同名不串来源；本地/远端文件替换、截短、轮转均有可见异常和范围记录。
8. gzip超出解压额度、超长行、无末尾换行、跨块中文和堆栈处理有界且可取消。
9. 读取1000组不同异常，达到配额有明确续批或部分完成提示，不能只剩最后200组却标全量。
10. 模型不可用时读取和统计正常，超时可停止；自动分析关闭、停止当前分析、停止采集三者行为独立。
11. 快速切换任务或停止后迟到输出不串页；手动阅读不抢滚动，Enter与输入法选词正确。
12. 报告引用可定位、范围与次数准确，人工草稿不被覆盖；旧缓存打开不自动连服务器。
13. 现有人工终端、文件浏览和导出可用，AI任务连接状态不误用人工会话状态。

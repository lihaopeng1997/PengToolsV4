# 后续开发 AI 的完整接手提示词

与[需求 AI 提示词](AI_REQUIREMENTS_PROMPT.md)、[开发与复核规范](DEVELOPMENT_AND_AI.md)配套使用。将下文和需求 AI 输出的完整任务一起交给开发 AI；不要只转发一句“按照设计改”。本文不是本轮 UI 已完成的声明，进展以交付 SHA、[实施记录](../ui/prism-implementation-2026-09/STATUS.md)和[缺口清单](../ui/prism-implementation-2026-09/ACCEPTANCE_MATRIX.md)为准。

## 复制以下正文给开发 AI

你是 PengToolsHub 的开发负责人。请按附带需求完成代码、验证和交接，再把可复核的交付交回需求 AI。不得用“建议后续实现”替代当前已授权工作，也不得把需求 AI 的推测当成已经验证的源码事实。

### 1. 接收任务并核对基准

先读 AGENTS.md、docs/project/README.md、PRODUCT_AND_SOURCE.md、DEVELOPMENT_AND_AI.md，以及本任务需求。涉及晴空棱镜时还要读 V2.1 规格和整个原型目录。报告实际仓库、分支、完整 HEAD SHA、远端状态及已有工作区修改；需求给定 SHA 与当前不同，先检查相关差异，不自动重置、切 main 或合并分支。

确认需求至少包含：问题与复现、用户期望、批准范围、不变合同、源码调用链、实施落点、可观察验收和交付要求。缺少的信息能由源码确认就自行补证；涉及功能、数据、线程所有权或外部副作用的实质冲突，记录具体证据，继续处理不依赖冲突的部分，不擅自扩大范围。

本轮已确认的是只保留 calm 单主题、重做既有 UI、保留业务逻辑。以下不是已经批准的改动：Redis/MongoDB AI 请求改线程、SQL 查询清空旧结果行为变更、全自绘系统边框、全部工作台转网页。普通“继续”不能替代这些具体范围的确认。有关 NoSQL 的可开发草案在 NOSQL_AI_WAITING_HANDOFF.md。

### 2. 先核实真实功能，再修改展示

对涉及的页面列出入口控件、菜单、快捷键、启用条件、槽/回调、业务方法、参数、保存字段和刷新点。异步任务列出开始、完成、失败、取消、迟到结果、隐藏与销毁。只在证据足够时给出结论，不能根据类名猜功能。

UI 调整复用现有控件与动作，保留 model/document、选择、撤销、展开状态、滚动、列宽、排序、草稿和已保存 splitter 偏好。原型里的假数据仅用于隔离预览；原型中的完成按钮、进度数字和设计展板不能成为新增生产接口。

发生规格冲突时，在交付中写清旧行为、目标条款、用户决定和处理结果。例如 LD-04 要求保留旧结果，而原 _run_sql(reset=True) 会清空结果，必须明确边界，不能仅为动画直接改动数据模型。

### 3. 按当前技术栈实施

- Vue 3 / TypeScript / Vite 用于轻量全局界面；PyQt 保留密集工作台、数据库、SQL、SSH、捕获和文件交互。先复用现有能力，不因视觉风格引入新框架。
- 主题、响应式和导航分别以 ui/theme_manager.py、ui/layout_metrics.py、ui/navigation_model.py 为权威。区分主窗宽与实际内容宽，不另造不一致的断点或色表。
- Bridge 位于 ui/，由调用方注入业务数据；不得让前端直接读本地文件、数据库或任意调用 Python。不引入 CDN 或公共服务。
- Vue 源码与 resources/webui/vue/ 正式产物同次交付；只通过构建生成产物，不手改压缩文件。
- 动效不控制业务完成、取消、禁用或百分比。隐藏时停装饰刷新，恢复时复用原实例；减弱动态时保持状态文字和真实进度。不要增加等待动画的强制最短播放时间。
- 修改只覆盖任务相关路径。保留原有用户数据、配置、凭据、会话、未提交内容和阶段报告，不为获得干净工作区做破坏性清理。

### 4. 验证要与改动风险一致

先运行受影响面的最小有效测试，发现真实回归再扩大范围。不要默认全量发现或打包。现有隔离入口可运行：`python scripts/diagnostics/prism_web_runtime.py --test-module tests.test_<area>`；实际 WebEngine 验证使用 Windows 平台，不能把离屏平台错误改成生产启动策略。只使用临时配置、fake 服务和模拟数据，不连接真实生产系统。

Vue 修改运行 typecheck；嵌入资源修改还要运行 build:embedded、verify:embedded。纯 Qt 修改无需为了形式运行无关前端构建。所有交付检查 git diff --check。

展示修改必须实际查看对应状态：正常/空/长内容/禁用/失败/执行中，按任务覆盖展开、收起、低宽、大字号、中英文及滚动可达。动画检查实际相位变化、隐藏暂停、减弱动态和关闭清理，不能只查 keyframes 字符串。测试范围与未覆盖项一并报告。

截图附逻辑窗口尺寸、DPR、字体设置、页面/页签、模拟数据说明和采样源码基准。旧截图、模板图、静态索引和测试名称都不是当前行为通过的证明。模拟屏幕矩形不能冒充真实双屏；初始状态截图不能冒充完整模块验收；没有实际测量不能声明 CPU、内存、启动耗时或帧率达标。

### 5. 交付给需求 AI 复核

完成后先检查最终 diff、工作区和目标分支。提交及推送按任务授权和仓库规则执行，提交/推送前核对远端；不强推，不把网络报错后的“Everything up-to-date”当成功，核对远端实际 SHA。

最终交付正文必须包含：

```markdown
# DEV-交付：需求编号与具体结果
需求编号/版本：
原始基准分支与完整 SHA：
最终本地提交 SHA：
远端分支与实际 SHA（或明确未推送原因）：

## 实际变化
问题触发、修改后的行为、涉及文件/类/组件。
哪些业务合同通过何种证据保持；是否新增依赖。

## 逐条验收
|需求/验收编号|实现落点|命令或操作|实际结果|证据|未覆盖项|
|---|---|---|---|---|---|

## 验证边界
测试环境、运行与退出结果、截图/DPR/模拟说明。
未运行、失败、原有失败、待用户决定、待人工验收分别列出。

## 需求 AI 下一步
请从最终 SHA 读取实际代码和 diff，对照需求独立检查调用链、
状态恢复、布局、数据与生命周期；给出通过/返工/待证据，
不要根据本交付总结直接判定完成。
```

若需求 AI 返工，逐条确认编号、根因、改动及新证据；完成后再次提交复核。需求 AI 要求超出原范围时，先对照用户目标判断是否为当前缺陷的必要修复，不能把新增业务藏进返工。

### 6. 同步交接材料

更新与任务相关的需求、源码索引、实施记录和验收缺口。记录用户批准的规则变化及替代条款；不把旧审核日期写成当前 SHA，不把“已录制”改写成“已验收”。需求文档描述目标，开发文档描述实施与证据，两者发生差异时必须说明原因和授权来源。

本轮晴空棱镜仍有缺口时保持未完成；不要把它们包装成以后才需要处理的新需求。后续新增功能、微调、缺陷也按“需求 AI 定义 → 开发 AI 实施 → 需求 AI 读代码复核 → 返工或接受”的同一闭环执行。

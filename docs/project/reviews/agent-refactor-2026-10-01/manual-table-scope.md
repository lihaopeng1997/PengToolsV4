## API and behavior

`BoundManualTableScope.capture(service, tree_target, node, tree_generation, manual_target, choice)` resolves the actual live `ObjectTreeService` registry entry without opening a database connection. Tree generation belongs to the directory namespace; it is not compared with the manual tab generation. The captured value binds the complete immutable manual target and connection choice to the verified raw table reference.

Pass the captured value as `table_scope=` to `create_manual_session(...)` or `ManualRelationalProviderFactory`. The factory re-resolves the signed node before profile loading, checks the complete profile choice, and revalidates immediately before and after secret resolution. After the connector returns, the factory always transfers that driver to the session owner instead of closing and discarding a possibly live connection. The driver validates before configuration and every ordinary SQL/cursor operation, so a reference that expired inside connector code yields a cleanup-only driver: direct execute, batch, savepoint creation, commit, and rollback fail before opening a cursor or touching the transaction; owner-thread close remains available. Session owners must retain the driver before calling `configure_manual_commit()` and must retry a failed close on that same owner. A successful configuration marks the existing transaction handle usable; a later tree refresh blocks new statements but does not block the explicit commit/rollback decision for that already-open transaction. Configuration rechecks the live reference after autocommit setup and around Oracle schema verification/change.

For Oracle and OceanBase Oracle mode, the service/database remains separate from the signed schema. The driver quotes the exact raw schema identifier, sets `CURRENT_SCHEMA` only on the new manual connection when needed, and verifies the result on that same connection. Scoped MySQL modes pass a transient profile copy whose database comes from the signed table reference; stored profile data and its revision are not mutated. The existing no-scope factory path remains unchanged.

`ManualRelationalDriver.executemany(sql, rows)` uses the driver instance’s existing connection and rejects calls from outside the thread that created it. It returns the cursor to normalize DBAPI return-value differences, closes cursors on failures, and converts provider diagnostics to stable error codes without exposing vendor diagnostics. It never commits, rolls back, retries, or enables partial-error mode. OceanBase Oracle ODBC numeric `:N` binds are converted into ordered `?` binds while ordinary quoted text/identifiers, Oracle q/Q/nq alternative-quoted literals, and SQL comments are left untouched; unsupported/missing numeric values and unterminated alternative quotes fail before a cursor is opened.

The dedicated table/import owner must call this driver API from its own persistent owner lane and continue to manage the session transaction explicitly. The frozen `ManualSession` API itself was not extended with a queued batch method; manual ChangeSet apply continues through its existing queued session path.

## Driver contract evidence

The [PyMySQL cursor reference](https://pymysql.readthedocs.io/en/latest/modules/cursors.html) documents `executemany` inputs as a sequence of sequences or mappings and a return value of affected row count or `None`. The [python-oracledb cursor API](https://python-oracledb.readthedocs.io/en/latest/api_manual/cursor.html) accepts sequence/dictionary row binds and returns `None`; its `batcherrors` option defaults to `False`. Accordingly, this adapter does not opt into continuation-after-row-error.

Microsoft’s [ODBC parameter-array documentation](https://learn.microsoft.com/en-us/sql/odbc/reference/develop-app/using-arrays-of-parameters?view=sql-server-ver17) says that whether rows before or after an error are executed is data-source-specific. The wrapper therefore makes no cross-driver all-or-none claim: it returns a stable error code without exposing vendor diagnostics and leaves transaction handling to the explicit owner. No automatic rollback is attempted after a batch error.

Oracle’s [alternative quoting syntax reference](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/Literals.html) defines `q`/`Q`-quoted text and paired delimiters, including brackets, braces, angle brackets, and parentheses. The OceanBase Oracle batch scanner recognizes those forms and the `NQ` national-character form so `:N` text inside the literal is not mistaken for a bind. This is an Oracle language reference; it does not independently establish that every OceanBase server/ODBC combination accepts each quoting variant.

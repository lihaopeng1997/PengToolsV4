## Read-only completion/drain review — 2026-10-07

The import lifecycle and concise workspace-close copy have root source acceptance (30 lifecycle tests followed by six changed-copy/notice tests); ManualQuery/Main seams are now released for the next serialized implementation. This paragraph is a plan update, not evidence that history integration exists.

Legacy `workbench_shutdown_cleanup` disconnects completed/failed UI slots. History therefore needs an app-service-owned completion sink bound at `_start_db`, retained through actual worker `finished`, independent of those UI slots. A cancelled legacy worker may suppress a terminal result; without explicit result evidence, record UNKNOWN after actual finish, not a fabricated CANCELLED. Manual `_watch_future` must deliver immutable matching capture/result to its history sink before `_deliver` can discard stale Tab/request UI events. Finalize each request only once. Pagination updates the original query capture, and only exact matching payload counts are used.

Main already waits for manual/import owners before `_request_workbench_panel_cleanup`. That method may add the app-history drain after all legacy/workbench owners are quiescent, then wait for queued saves and every controller's actual finished-backed cleanup Future before closing the shared store. Stopping the service on the first cancellation request would lose late final records. Keep startup, tray, close-action selector and Agent cleanup ownership untouched.

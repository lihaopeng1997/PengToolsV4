This audit covers the 22 real navigation IDs `0–13, 16–23` from the working tree on branch `dev/2026-09-23`, baseline HEAD `818fba72bf437de9bd49fcd5b198fb1270096a53`. The runtime construction probe uses the production `MainWindow` navigation/factory and the panel class returned by each route. It creates one route per bounded process with `QT_QPA_PLATFORM=windows`, `WA_ShowWithoutActivating`, temporary config/data paths, settings supplied in memory with `persist=False`, a disabled WebShell, stopped panel timers, and blocked socket/subprocess launch calls. It suppresses `InterfaceDebugPanel.on_panel_activated`, which can manipulate a system proxy/listener. The construction probes do not click visible buttons, menu actions, or tabs, and do not start database, SSH, AI, browser, or file workflows. A nonzero blocked-call counter is a probe failure, not an action result.

The four geometry samples are the requested client-window sizes 960×640, 1100×720, 1280×800, and 1440×900 logical Qt pixels. A synthetic value is inserted into an editable field with its signals blocked where possible; dashboard and requirement use their production in-memory render paths with synthetic rows. These fixtures measure construction, action availability, clipping ancestry, scrollbar reachability, menus/tabs, and selected long-text bounds. They do not verify persistence, remote service success, database behavior, or output correctness.

## Layout repairs and targeted regression

The module pass found two concrete ancestor-layout clips and an English caption truncation. The authorized presentation changes are local to `panels/docx_panel.py` and `panels/gateway_panel.py`:

- Docx path and multi-button row wrappers now retain the minimum derived from their child layout, preventing a 35-DIP wrapper from clipping 36-DIP child actions.
- Gateway's vertical splitter mode derives the result pane floor from its real child layout minimum and reapplies it from that baseline on mode changes. This prevents the previous 180-DIP floor from clipping the embedded JSON Clear/Copy footer by 3 DIP without accumulating height across orientation changes.
- Gateway's horizontal splitter mode now derives the result pane's width floor from the embedded JSON viewer's path/action row natural size hint and its containing margins. It resets the floor in vertical mode and recomputes after layout, language, font, and style changes. It leaves the shared `JsonViewer`, global orientation policy, and splitter preference store unchanged.
- Docx caption labels wrap the full localized text and recompute their local height for the current font; English16 and Chinese16 no longer silently truncate labels. No global field metric or shared `JsonViewer` behavior was changed.

`python -m unittest tests.test_prism_embedded_action_geometry -v` passed all 7 tests. It exercises the wrapper floors, Gateway mode round trips and scroll reachability, embedded toolbar intrinsic fit and path separation, live font/language/width changes on the same widget, unchanged standalone `JsonViewer`, and Docx English/Chinese caption bounds, wrapping, and action fit. Copy-path and copy-JSON callbacks run against a mocked clipboard; expand/collapse/clear use synthetic viewer content. The final home-button language repair also passed `python -m unittest tests.test_lazy_panel_home_locale -v` (1 test); it cold-starts from synthetic English settings, creates lazy Docx/Gateway routes, verifies the Home button text/tooltip, switches en→zh→en, and clicks Home exactly once without socket or settings writes. `python -m py_compile scripts/diagnostics/prism_module_completeness.py panels/gateway_panel.py tests/test_prism_embedded_action_geometry.py` passed.

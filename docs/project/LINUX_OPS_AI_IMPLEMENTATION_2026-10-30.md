## 使用入口

进入 **日志排查 → AI 日志与系统排查**，顶部直接选择：

- **历史日志分析**：本地或服务器文件，选择文本或 `.gz`；读取整个启动范围、末尾指定行数，或者按指定日志时区筛选年月日时间范围。点击“开始读取历史文件”。
- **Linux 实时监控**：选择已有服务器即可开始；服务、进程、端口和磁盘阈值在“配置服务、端口与告警阈值…”中填写。勾选“同时跟踪所选日志文件”后可组合采集日志。
- **仅实时日志**：保留从现在开始跟踪文件新增内容的轻量入口；启动前尾部补读仍是最多256 KiB。

采集和 AI 分开运行。没有选择模型时可以采集、查看证据并生成证据汇总报告；使用 AI 时在右侧选择并确认模型，手动发送问题，或开启“自动分析新异常”。历史任务开启自动分析后，在有限读取结束时派发一次总结。

入口控制新任务的创建方式；“任务记录”选择当前分析对象。已启动任务的来源不会因界面设置变化而改变，AI 按任务范围取证。切换入口不自动停止其他任务。

## 已实现的读取、监控与分析能力

| 范围 | 本次源码行为 |
| --- | --- |
| 历史文件 | 最多20个文件、合计200 MiB解码输入；冻结启动时边界；流式读取和gzip解压；检测截短、替换和锚点变化 |
| 时间筛选 | 解析带年月日的标准日志时间；续行继承前一个头的时间；无法判断时间的行单独计数，不能声称时段完整 |
| 历史搜索 | 临时SQLite保存脱敏、有界行索引；每行最多4096字符，关键词搜索返回来源和附近行；不依赖最后200行 |
| 范围上限 | 字节、索引、事件或证据容量达到限额时明确显示“部分读取”和原因；保留已取得证据及尚未读完的文件状态，报告带上覆盖限制 |
| Linux资源 | CPU两次计数取差、可用内存、swap、负载、所选磁盘空间与inode；首次或计数失效时CPU显示未知/预热 |
| 服务/进程/端口 | 固定只读命令查询所选systemd服务、进程名、监听端口；进程列表仅PID、名称、CPU、RSS，不读取环境变量和完整命令行 |
| 采样失败 | 非零退出、空的必需内容、无法解析、断线均显示未知；缺失值不参与停止/恢复判断；断线重置计算窗口并重连，连续5次连接失败停止系统采样 |
| 规则 | CPU/内存/磁盘阈值可调，持续时间及恢复回差；资源至少两次有效样本且达到持续时间，服务/进程/端口至少连续两次有效样本；未知样本清除待确认窗口 |
| 任务停止 | 停止自有系统与日志连接、取消当次分析和自动派发；停止前证据仍可手动分析、提问和生成报告 |
| Agent取证 | 复用现有Runner、模型适配和500 KiB应用预算；系统快照、最近60次资源窗口、异常分页、事件、历史索引、日志片段及已选服务journal补查；校验任务及目标范围 |
| 写操作 | 首批只有查询工具；修改、删除、安装、清理、kill和重启只给建议，没有任意shell执行入口 |
| 报告 | 证据汇总与AI整理分别提供；Markdown可编辑、保存；AI返回期间如果人工修改草稿，保留新答案在对话，不覆盖人工稿 |
| 缓存 | 缓存打开不重新连接；继续查看和分析保留证据；原始行索引仅当前运行有效，缓存搜索明确只查已保存事件证据 |
| 界面 | 历史与Linux监控直接页签入口；系统视图填满结果区域；异常标题列随宽度填充；指标和证据刷新保留滚动位置；人工终端“未连接”状态不再出现在AI页 |

## 代码位置

- `tools/log_analysis/history.py`：有限扫描、文件边界、时间过滤与脱敏索引。
- `tools/log_analysis/system.py`：有时限/限输出的只读采集、未知状态、规则、系统任务与限定journal补查。
- `tools/log_analysis/collector.py`、`events.py`：增量文件读取与采集连接；来源隔离及堆栈聚合。
- `tools/log_analysis/service.py`、`runtime.py`：采集与分析生命周期分开，串行AI队列和只读工具。
- `tools/log_analysis/cached.py`、`report.py`：离线证据、报告、缓存额度。
- `ui/log_analysis/workspace.py`、`file_picker.py`：原生工作区及异步远端文件选择。
- `panels/ops_log_panel.py`：懒加载入口和退出收尾。
- `tests/test_linux_log_workspaces.py`：新增历史、系统、停止、连接、报告及界面边界测试。

## 现阶段边界

- 软件退出后不再采集；没有Linux端常驻服务和24小时后台承诺。
- 系统保留最近360次样本，AI一次取最近60次资源窗口；没有完整时序数据库、图形趋势和自动定时报表。
- 服务journal补查是当前末尾最多80行，不能声称覆盖整个故障时段。
- 旧方案中的拖入文件、可配置时间解析模板、完整历史索引跨重启恢复、从检查点继续扫描等不是本批交付；当前通过重新选择文件建立新任务。
- 远端文件身份采用大小、修改时间和尾部锚点检测，无法保证替换/轮转间隙绝对不重不漏。超长行和每行索引截断均有限额。
- 采集周期最小5秒；单条命令默认8秒上限，慢命令会延后本轮完成，其余未取得项目显示未知。磁盘通常30秒更新一次。
- 本次未验证具体Linux发行版、systemd/ss权限、挂载点卡顿及4任务长期压力；未验证真实千问模型输出和延迟。需要内网复测。

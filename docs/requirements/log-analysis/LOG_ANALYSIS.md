# 日志排查与 Linux 系统观察

当前行为以 `tools/log_analysis/`、`ui/log_analysis/` 和 `panels/ops_log_panel.py` 为准。下面是这些模块现在承担的工作，不是某一次离线测试的验收结论。真实 SSH、真实模型和安装包需要单独复测。

## 入口

日志排查里的 AI 工作区有三种任务：

- 历史日志：本地文件或服务器文件，含文本和 gzip。可以读启动时冻结的范围、尾部行数，或按带年月日的日志时间筛选。
- Linux 实时监控：选择已有服务器即可采样 CPU、内存、负载、磁盘和 inode，以及所选服务、进程、监听端口。可以同时跟踪一个日志文件。
- 仅实时日志：从现在起跟踪文件新增内容。启动前尾部补读最多 256 KiB。

采集和模型分析分开。没有模型时仍可采集、看证据和生成证据汇总。使用模型时要在右侧选择并确认。自动分析新异常是单并发队列，同类异常有间隔限制。暂停采集和暂停 AI 是两件事。停止任务会停掉本任务自己的连接和分析，已采集证据仍可继续提问。软件退出后不再采集，没有常驻远端代理。

## 取证与模型

分析复用现有 Agent 运行器和模型适配。工具是只读的：事件、覆盖范围、有界日志片段、历史索引、系统快照和最近资源窗口、已选服务的 journal 末尾。没有任意 shell，也不提供删除、安装、结束进程或重启。修改类建议只写在回答里。

发给模型的内容和采集预览可以分别清洗。常见凭据字段、Cookie、Bearer、私钥块和请求响应正文标记会打码；这不是对任意业务日志格式的保证。思考过程按每一轮分析显示，只留在界面，不写入对话消息，也不写回模型历史。最终落盘的助手消息是经过校验的最终文本；流式正文只是临时气泡，以 `<`、`{` 或代码围栏开头的工具信封不会推到界面上。

上下文有应用侧字节上限。模型服务端窗口无法从现有配置自动得知，较小窗口仍要联调。

## 范围与缓存

历史任务最多 20 个文件、合计有解码上限，并在启动时冻结边界。截短、替换和锚点变化会记下来，但不能保证轮转间隙绝对不重不漏。时间无法判断的行单独计数，不能把筛选说成完整时段。搜索用当次运行的有界脱敏索引；从缓存打开时只查已保存事件，不重新连接。

事件在内存里有组数和单组证据上限。超限、积压和截断显示在状态和报告的覆盖限制里。缓存放在应用数据目录的 `log_analysis/v1`，保存脱敏事件和检查点，不保存连接凭据。清理缓存需要确认，不删除远端日志。本地任务检查点可以单条删除。

报告是可编辑的 Markdown。证据标签按该任务是否打码写成脱敏或原文。人工改过的草稿不会被后到的 AI 报告覆盖。

## 代码

| 路径 | 职责 |
|---|---|
| `tools/log_analysis/collector.py` | 增量读取、检查点、轮转锚点和有限重连 |
| `tools/log_analysis/history.py` | 有界历史扫描、时间筛选和脱敏索引 |
| `tools/log_analysis/system.py` | 只读系统采样、告警规则和 journal 补查 |
| `tools/log_analysis/events.py` | 多行堆栈、重复计数和脱敏 |
| `tools/log_analysis/runtime.py` | 只读工具、上下文预算和回答流式防护 |
| `tools/log_analysis/service.py` | 采集与分析队列、取消和检查点 |
| `tools/log_analysis/report.py` | 报告草稿和缓存配额 |
| `ui/log_analysis/workspace.py` | 原生工作区、思考分轮和临时回答 |
| `panels/ops_log_panel.py` | 懒加载入口和退出清理 |

人工日志页、终端和多机截取仍走原有入口，不和这条分析连接抢会话。

## 尚未当作完成的部分

没有 Linux 端常驻服务，也没有 24 小时后台或完整时序库。journal 补查只是当前末尾有限行。发行版差异、权限不足、磁盘卡顿和长时间多任务压力没有在这份说明里被验收。早期离线测试记录过一批合成数据和假连接用例，那些数字只属于当时的工作区，不能代替当前树或真实环境的复测。

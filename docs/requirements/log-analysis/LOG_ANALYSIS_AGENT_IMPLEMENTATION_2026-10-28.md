## 入口与操作

日志排查 → **AI 排查 / 实时监控**。原人工页、终端、多机截取以及此前新增的“导出后打开”流程均保留。

1. 选择已配置的服务器、服务及具体日志文件，核对编码。服务配置为目录时，先在原人工页浏览到具体文件，再填入绝对路径。
2. 默认从末尾观察新增内容；需要分析已有错误时勾选“补读尾部最多256 KiB”。开始时确认目标与缓存位置。
3. 选择并确认内网模型，提问或选择异常分析。勾选自动分析后，新异常进入单并发队列。模型等待不阻塞采集。
4. 在异常列表右键可以复制证据、复制 traceId、查看上下文、分析或生成报告。
5. 报告先作为可编辑 Markdown 草稿展示，点击保存才落盘。重新生成前确认替换人工编辑。
6. 暂停采集与暂停 AI 分开；停止关闭独立连接。再次打开软件后，历史任务需要手动恢复。

## 数据及长任务边界

- 默认每2秒读取，单次256 KiB；事件保留200组，每组证据最多64 KiB；超长行、淘汰与积压显示在状态栏。
- 内存一次打开最多保留20个任务；最多4个运行任务。报告保留每事件最近5版分析。
- 缓存位于应用数据目录下 `log_analysis/v1`，只保存脱敏事件和检查点，不保存连接凭据、最近原始日志或全量文件。7天/200 MiB达到上限提示，清理需确认；不会自动删除远端日志或报告。
- 对话仅保留最近6轮作为请求历史，较早历史省略带提示；界面保留有界历史文本。单轮 Agent 调用复用现有自动压缩。固定目标与证据通过任务快照和工具重新取得，不能把历史回答视为当前证据。
- 500 KiB 是应用字节上限。当前模型配置没有通用服务端上下文窗口字段，无法自动获知所有内网部署的 token 上限；较小服务端窗口仍需真实模型联调。
- 任务暂停、停止、恢复、软件退出均不能视作持续监控。SFTP锚点不是可靠 inode；内容相同的替换或两次轮询间完成的截断再增长，不能保证识别，报告明确覆盖限制。
- 日志时间自动解析、时间区间筛选、跨服务 traceId 关联、事件趋势和 Word 导出未在本次开放；当前统计使用本机观察时间。按字节补查及关键词工具不会伪装成完整时间范围查询。
- 脱敏覆盖常见凭据字段、Cookie/Bearer、私钥块、请求响应正文标记和手机号/身份证样式；未知业务日志格式需内网复核，不能保证任意格式均识别。

## 内网复测建议

用授权测试日志依次追加普通行、完整Java堆栈、重复错误和第二种错误码；检查次数与前后文。随后测试暂停/恢复、轮转、断网、慢模型和停止。首次测试可关闭自动分析，确认脱敏后的证据再启用。

出现问题时记录任务操作和时间，并反馈 `data/logs/agent_diag.log` 及其轮转文件。新增事件名以 `log_monitor_`、`log_analysis_`、`log_file_generation_` 开头，仅记录任务哈希、阶段、字节数、重试和错误类型，不记录日志正文或凭据。

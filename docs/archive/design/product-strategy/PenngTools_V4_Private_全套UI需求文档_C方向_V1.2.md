## 0. 执行摘要

PenngTools 是供内网研发、测试、交付及运维人员使用的离线专业工具集合。当前痛点不是某个模块功能缺失，而是模块入口、页面层级、动作命名、风险反馈、空配置状态和窗口缩小时的体验不一致，导致用户需要依赖记忆判断「去哪里」「能否执行」「会影响什么」。

本规格确认采用 **C「专业工具箱中枢」**：

- 用一套稳定的应用壳统一导航、页头、工具栏、筛选、状态、空态、确认和响应式收纳；
- 保留专业模块的最佳工作形态，不将 SQL、接口、日志和 SSH 强行卡片化或线性化；
- 流程型页面可局部采用轻量的任务步骤；异常排障页面可局部采用脱敏调查摘要，但二者不成为全产品的强制前置模型；
- 不扩大敏感信息留存，不引入云同步、遥测、浏览器内核、在线 CDN 或账号体系。

首批设计优先保障三条 P0 链路：

1. 接口异常：会话筛选/阅读 → 解密或格式化 → 请求验证；
2. 日志/SSH 排障：选择主机 → 定位日志 → 只读查询或终端执行 → 导出/交接；
3. 升级交付：需求 → 升级准备 → SQL/交付材料 → 日报。

# 1. 问题陈述

## 1.1 要解决的问题

PenngTools 目前同时承载需求、SQL、接口、网关解密、SSH/日志、日报、配置及轻工具。不同模块存在以下一致性问题：

- 用户进入后需要先记住模块名称，难以从当前目标、最近工作或任务类型快速进入正确工作区；
- 高密度专业页的操作、状态、风险级别和内容区层次各异，导致用户难判断当前对象、动作副作用和下一步；
- 「发送」「执行」「清空」「删除」「更新」等泛化动词未始终说明对象、目标、影响范围与可恢复性；
- 无服务器、无 SQL 连接、无模型、无发版月份等首次使用状态会出现空下拉，无法引导配置路径；
- 960×640 或高 DPI 场景下，少数长按钮和多窗格页面存在压缩、截断或菜单语义弱化风险；
- 捕获会话、证书信任、远端执行和本地快照删除等高风险反馈未完全统一为可验证的安全提示模式。

## 1.2 服务对象与问题规模

主要受影响者是需要在多个技术与交付模块之间切换的内网工作人员。该问题影响所有可见页面；其中接口、日志/SSH、SQL 控制台、升级准备和需求管理为高影响页面，因为它们涉及外部目标、敏感数据或交付产物。

当前没有行为埋点，不以未经验证的使用频率声称精确基线。本规格采用「任务走查、静态控件门禁、运行态截图和评审样本」作为第一阶段测量方式。

# 2. 目标用户

## 2.1 主要用户

| 用户 | 核心任务 | 主要痛点 | UI 优先级 |
|---|---|---|---|
| 研发/测试工程师 | 发送接口验证、查看响应、格式化与解密、执行 SQL 草稿 | 不清楚请求是否真实发送、目标环境及敏感信息范围 | P0 |
| 运维/生产支持 | 连接 SSH、查询日志、截取证据、导出排查结果 | 容易混淆「填入命令」与「执行命令」、多会话定位成本高 | P0 |
| 交付/需求负责人 | 管理需求、整理 SQL、生成发版材料、同步日报 | 上下文散落在多个页面，未完成事项与产物难回收 | P0 |

## 2.2 次要用户

| 用户 | 核心任务 | UI 要求 |
|---|---|---|
| 内网模型使用者 | 配置模型、测试连接、连续对话、生成 SQL 草案 | 明确模型配置前置条件和聊天记录本机明文边界 |
| 数据准备人员 | 生成证件/VIN 测试数据、复制或导出 | 单一主任务、参数明确、结果可复制 |
| 新加入协作人员 | 查看已有需求、接口模板、日志线索和日报 | 空态给下一步、术语一致、避免内部缩写 |

## 2.3 核心用户故事

1. **作为测试工程师**，我希望在发送请求前看到环境、Host、方法、URL 与认证状态，以便确认这是否为真实外部请求。
2. **作为运维人员**，我希望明确区分生成/填入命令与执行到当前 SSH 终端，以便避免误触远端操作。
3. **作为交付负责人**，我希望从需求上下文进入升级准备、SQL 交付和日报，而不必反复寻找模块入口。
4. **作为首次使用者**，我希望空配置下拉直接告诉我需要新增什么、从哪里新增，以便不用猜测空白控件的含义。
5. **作为处理敏感数据的用户**，我希望系统持续说明哪些数据仅在内存、哪些数据会保存在本机，以便按风险选择操作。

- 不以收集用户行为数据为指标来源；本项目禁止引入遥测。

# 4. 产品目标与非目标

## 4.1 目标

1. 建立统一、可渐进接入的应用壳和页面骨架。
2. 将全部页面归入「多窗格技术工作台」「流程工作区」「轻工具/专注工作区」三类，分别适配密度与响应式规则。
3. 让每个关键动作在首屏或确认框上明确对象、目标、影响与恢复条件。
4. 为无数据、无权限、错误、加载、完成、敏感信息、离线与小窗口状态提供可复用规范。
5. 为设计评审和后续实现提供页面级验收标准，而非仅提供视觉示意。
6. 让所有符合定义的展示模块可在安全尺寸下通过分隔条或表头列边界调整展示比例与列表可见量，同时保持关键上下文、风险状态和主操作可见。

## 4.2 非目标（Non-goals）

- 不在 V1 引入账号、权限体系、云同步、多人实时协同、遥测、在线更新、插件市场或浏览器内核；
- 不把所有模块改造成任务流或案件系统；
- 不改变既有业务逻辑、接口协议、敏感数据生命周期或文件格式；
- 不默认保存抓包原文、Token、Cookie、网关密钥、明文或 SSH 命令输出；
- 不在本规格中承诺代码重构、打包、测试执行或发布日期。
- 不提供正文、编辑器、终端、表格单元格、按钮、字段、导航项、确认框内容或卡片内部元素的自由拖拽/排序；仅允许 QSplitter handle 与 QHeaderView 列边界承担展示尺寸调整。
- 不通过展示区拖拽改变业务数据、筛选条件、内容顺序、运行任务、网络/远端动作、SQL/请求/命令内容或敏感数据生命周期；不做跨设备/云端布局同步。

## 4.3 范围管理

- V1 只定义现有可见页面及关联弹窗的统一体验和优先页面形态。
- 新增一个全局能力，必须同步移除一个重复入口、重复状态或延后到 V2。
- V2 停车场：本地收藏规则、脱敏调查摘要、个性化布局、离线效率统计、全局命令搜索扩展。

# 5. 设计总原则

1. **全局统一，模块专业**：统一壳层和语言，保留专业页面的信息密度。
2. **对象先于动作**：动作必须表达操作对象；涉及远端时再表达目标。
3. **结果优先于装饰**：日志、响应、SQL、终端、校验结果获得主要阅读空间。
4. **安全事实真实**：提示必须与真实数据生命周期、执行路径和恢复行为一致。
5. **逐步披露**：默认显示当前任务所需内容，高级、低频或危险操作进入上下文明确的“更多”。
6. **单页一个主操作**：主操作位于页头右侧或当前工作区右上；同一视区不竞争。
7. **中文优先，技术英文可括注**：例如“请求头（Headers）”“参数（Params）”“请求体（Body）”。
8. **小窗口不牺牲关键上下文**：不能通过缩小字体、截断文本或隐藏主操作解决拥挤。

# 6. 全局信息架构

## 6.1 一级导航

| 分组 | 模块 | 设计目的 |
|---|---|---|
| 工作台 | 工作台、最近、常用工具 | 恢复最近工作，提供低成本入口 |
| 交付管理 | 需求管理、升级准备、接口文档更新、日报 | 覆盖从需求到交付材料的流程型任务 |
| 接口与诊断 | 接口排查、加解密、格式工具、SQL 控制台 | 提供高密度技术排障和验证工作区 |
| 运维工作台 | 命令库、日志排查/SSH | 提供连接、查询、日志和命令风险分层 |
| 数据与测试 | 证件类型、车辆 VIN | 提供单任务测试数据生成 |
| 智能与偏好 | 模型对话、设置 | 管理本地模型与应用偏好 |

### 导航规则

- 宽屏显示图标与文字；紧凑/窄屏仅图标时必须提供完整 Tooltip 与可访问名称。
- 侧栏折叠不改变当前模块、内容或运行中的任务。
- 不使用“账户”描述个人菜单；推荐“应用菜单与偏好”。
- 最近与收藏仅记录模块/非敏感上下文，不记录敏感正文、密钥或认证信息。

## 6.2 全局应用壳

所有页面均采用以下四层骨架：

1. **L1 页头**：图标、页面标题、说明、页面状态、唯一主操作；
2. **L2 工具栏**：与当前对象直接相关的常用操作；
3. **L3 筛选条**：搜索、筛选、排序、环境/日期等上下文选择；
4. **L4 内容区**：表格、树、编辑器、结果、卡片或多窗格主工作区。

### 页头规则

- 标题说明“在哪里”，副标题说明“能做什么/数据边界”；
- 右上最多一个实色主操作；最多两个次要文字操作，其余收纳；
- 当前环境、连接状态、敏感状态、未保存状态使用文字 + 图形/色彩共同表达；
- 主操作不可因窗口变窄被隐藏；其文字必须完整或替换为上下文明确的动作菜单项。

## 6.3 通用状态

| 状态 | 必备内容 | 示例 |
|---|---|---|
| 初始空态 | 标题、原因、下一步、可达入口 | “尚未配置数据库连接。新建连接后可扫描结构、执行当前 SQL。” |
| 依赖未满足 | 上级对象、禁用原因、下一步 | “请先选择服务器，再选择服务和日志目录。” |
| 加载中 | 正在处理的对象、可取消性、结果位置 | “正在扫描「测试库」结构，可取消；完成后显示在对象目录。” |
| 错误 | 明确原因、保留输入、可恢复动作 | “无法连接 10.0.0.8:1521。请检查网络、端口与凭据后重试。” |
| 完成 | 完成对象、数量/位置、下一步 | “已导出 3 个 SQL 交付文件。打开输出目录。” |
| 敏感 | 数据范围、显示/保存边界、清理路径 | “敏感字段仅在当前应用会话显示；完成后清空本次会话。” |
| 未保存 | 当前对象、保存/恢复含义 | “当前日报未保存，草稿仅自动缓存于本机。” |

# 7. 三类页面工作区规范

## 7.1 A 类：多窗格技术工作台

**适用页面**：接口排查、日志排查/SSH、SQL 控制台、需求管理、格式工具 JSON/XML/SQL 子工作区。

### 布局规则

- 核心采用 2 至 3 个可拖拽窗格，避免把对象列表、编辑区和结果强行上下堆叠；
- 左侧为对象/会话/目录，中间为当前工作内容，右侧或底部为详情、验证、结果、风险说明；
- 当前对象、环境、连接状态和目标始终固定在可见区域；
- 不把主结果折叠到“更多”；低频辅助动作可收纳。

### 低频收纳位

- 窗格工具栏末尾的“更多操作”；
- 当前对象右键菜单；
- 详情/结果区的二级菜单；
- 窄屏时右侧详情抽屉、底部结果 Tab。

## 7.2 B 类：流程工作区

**适用页面**：升级准备、接口文档更新、加解密、日报、环境签提交弹窗。

### 布局规则

- 以“选择/输入 → 校验/预览 → 生成/提交”组织；
- 页面保留轻量步骤提示、阻塞信息和产物位置，但不新增强制流程实例；
- 主操作始终是当前流程的下一步，例如“生成升级材料”“更新接口文档”“保存日报”；
- 校验、预览、草稿、复制、打开目录等作为次级操作。

## 7.3 C 类：轻工具/专注工作区

**适用页面**：工作台、证件类型、车辆 VIN、命令库、模型对话、设置、悬浮快捷工具。

### 布局规则

- 以单一高频任务为中心，默认单列或参数—结果双列；
- 高级参数、导入导出、历史管理、重置与删除进入次级工具栏或菜单；
- 轻工具不要求创建任务、案件或项目；
- 模型对话虽属轻工具，必须保留会话列表、模型状态和本机明文历史边界。

## 7.4 通用可拖拽展示区规则

### 定义与适用范围

- **展示模块**指同一页面中承载列表、树、表格、原始文本、编辑器、终端、日志、响应/结果、预览或详情检查器的独立可阅读区域。
- 当两个或以上展示模块在同一容器内同时可见，必须使用 **QSplitter handle** 调整模块比例；表格列宽仅允许通过 **QHeaderView 列边界** 调整。
- 单一展示模块已独占工作区时不得伪造无意义分隔条；固定页头、工具栏、筛选条、单行字段、按钮栏、风险确认内容和核心状态条不得成为可拖拽挤压对象。
- 禁止劫持正文、编辑器、终端、表格单元格或按钮区域的鼠标拖拽；其原有选择、编辑、滚动、复制和输入行为优先。

### Handle 与表头交互

- QSplitter handle 的**命中范围为 6–8px**，视觉分隔线为 **1–2px**；hover/focus 需用克制边界高亮和对应 resize 光标提示可调整，禁止持续动画、扫描线或装饰性发光。
- 分隔条必须可键盘聚焦，并提供用途明确的 accessibleName，例如“调整会话列表宽度”“调整 SQL 结果高度”；焦点不得只依赖颜色。
- 双击当前 QSplitter handle 时，重置**当前页面 + 当前 Tab/模式**的默认安全比例；不得重置其他页面、Tab、筛选或业务数据。
- 双击 QHeaderView 列边界时，仅按当前列内容适配该列宽；不得改变其他列顺序、筛选、表格选择或行数据。

### 保护、恢复与本机偏好

- 实现必须设置 `setChildrenCollapsible(False)`；任何展示模块均不得拖为 `0px`、完全不可见或低于本章/第 8.3 节的最小尺寸。
- 用户拖拽只改变展示空间比例与列表可见量；不得触发请求发送、终端执行、SQL 执行、保存、清空、删除或敏感数据展示状态改变。
- 仅可保存**本机布局偏好**：以“页面 ID + 当前 Tab/模式 + 窗口档位”作为键，保存 splitter 比例、允许的列宽与折叠状态；禁止保存 SQL、请求报文、日志、凭据、Token、Cookie、密钥、聊天内容或业务正文。
- 在 handle `release` 后以 **250ms 防抖**持久化；恢复时按当前 DPI、有效画布和 min/max 尺寸夹取。窗口档位、DPI 或模块结构变化导致旧比例不合法时，恢复夹紧后的比例；仍不合法则回退当前页/Tab/模式默认布局。
- 每个支持拖拽展示区的页面必须提供“恢复默认布局”入口；该入口仅重置当前页面/Tab/模式本机展示偏好，不删除任何业务数据、草稿、会话或配置。

### 响应式回退与关键上下文

- Wide / Standard 支持并列展示区拖拽；Compact 仅在两个主展示区均满足最小值时保留并列；Narrow 不能满足下限时，次展示区转为 Tab、Drawer 或底部抽屉，禁止把三栏硬压成不可读布局。
- 在 Narrow 下，用户仍可调整已打开的纵向展示区、底部抽屉或安全分隔比例；不承诺所有展示模块同时并列常显。
- 顶部环境/范围、风险与敏感状态、当前对象、主操作、取消路径、运行/失败状态和错误恢复信息不得随 splitter 拖动被隐藏、裁切或转入抽屉。

# 8. 响应式、信息密度与高频区域规格

> **证据状态**：本章所有断点、面板最小尺寸和收纳规则均为【拟议设计规格】，用于全套 UI 设计与验收；它们不是已采集的用户设备分布、效率数据或性能结论。后续需以脱敏任务走查、截图矩阵和真实可用性验证校准。

## 8.1 逻辑有效画布、DPI 与支持边界

- 所有尺寸均指 Qt **逻辑像素 / 应用有效 client area**，不含 Windows 外部标题栏；研发须先确认既有 `960×640` 是否为有效画布，并在实现前统一换算口径。
- **推荐最小支持窗口为 1100×720 逻辑有效画布**，用于保证双主展示区、主详情与高频输入/输出的默认可读性。小于该尺寸时不得继续压缩关键控件；应限制最小窗口或提示“请扩大窗口后继续”，禁止静默裁切。
- 若仍支持 **960–1099×640–719**，必须以“显式紧凑模式”运行：只保留一组主工作区组合，其他展示模块转换为 Tab、Drawer 或底部抽屉；不得维持不可读的并列三栏，也不得以缩小字体或隐藏顶部环境/风险/主操作来换取空间。
- 逻辑画布需在 Windows `100% / 125% / 150%` DPI 下分别验收。保留 960×640 的逻辑画布预计需要约 960×640、1200×800、1440×960 的物理可用区域；这是缩放换算，不代表设备分布。

## 8.2 宽度/高度分档与内容保留

| Compact | `1100–1279` | 约 56px 窄导航轨 + 双窗格或约束下堆叠 | 标题、主输入、主输出/结果、状态、首要动作与取消；导航可显式打开 | 完整导航标签、高级参数、历史/帮助、详情检查器、低频列/按钮 |

| 逻辑有效高度 | 布局规则 |
|---:|---|
| `≥800` | 可保留页头、工具条、双主窗格及可切换底部终端/详情区；不得用大面积空白替代结果区。 |

## 8.3 高频输入、输出、列表与终端最小可用尺寸

| 区域 | Wide / Standard 并列状态 | Compact / Narrow 堆叠或主区状态 | 规则 |
|---|---|---|---|
| 单行高频输入 | 高 `36–40`，可编辑宽 `≥240` | 同左；不足时独占一行 | 标签常驻；占位符不能作为唯一字段名；命中区不小于 `36×36` |
| 多行输入/代码/请求编辑器 | 主编辑区宽 `≥520`、高 `≥240` | 全宽优先，编辑区宽 `≥360`、高 `≥240` | 行号、状态、错误定位不得挤压正文；高级参数进入可展开区 |
| 主输出/响应/校验结果 | 主详情区宽 `≥520`；结果区宽 `≥420`、高 `≥220` | 全宽优先，结果区宽 `≥420`、高 `≥220` | 输出保留结果摘要、复制/导出边界与错误恢复；原文内部滚动但状态不裁切 |
| 高频列表/树/日志表 | 侧列表/树宽 `240–280`；宽表建议全宽 `≥640` | 全宽优先，宽 `≥360` | 行高/表头 `36–40`；至少露出约 6 行；时间、状态、对象/结果等核心列不自动隐藏 |
| 终端/命令输出 | 宽 `≥480`、高 `≥220` | 标签或可唤起底部抽屉；打开后全宽且高 `≥220` | 等宽字体、复制与清空边界、运行/退出态持续可见；最小档不与输入/输出组成三块常驻 |
| 上下分割编辑/结果 | 编辑区高 `≥240`、结果区高 `≥220` | 保留同样下限；不能满足时切换 Tab/Drawer | 双击横向 handle 仅重置当前页面/Tab/模式的默认高度比例 |
| 可调整表格列 | 名称列 `≥160`、时间列 `≥140`、长文列 `≥220`、状态列 `≥56` | 核心列仍保留；非核心列可收纳 | 仅 QHeaderView 列边界可拖拽；双击只适配当前列 |
| 任务摘要/状态条 | 单行高 `≥32` | 单行摘要常驻，详情进入抽屉 | 显示当前任务、运行/失败状态和下一步；不得只靠颜色/图标 |

## 8.4 收纳、抽屉、弹窗与分割规则

### 分割（Splitter）与表头列边界
- QSplitter handle 用于同一任务中并列或上下展示的列表、树、表格、原始文本、编辑器、终端、日志、响应/结果、预览及详情检查器；不得劫持正文、编辑器、终端、表格单元格或按钮区的拖拽行为。
- handle 命中范围 `6–8px`、视觉线 `1–2px`；hover/focus 提示可调整且鼠标使用对应 resize 光标。实现必须 `setChildrenCollapsible(False)`，每区受第 8.3 节最小值保护，不能拖至 `0px` 或裁切关键上下文。
- 双击 handle 重置当前页面 + 当前 Tab/模式默认比例；表格仅允许 QHeaderView 列边界拖拽，双击仅适配当前列。名称/时间/长文/状态列分别服从 `160/140/220/56px` 下限。
- 仅保存本机 splitter/列宽偏好，以页面 + Tab/模式 + 窗口档位为键；handle release 后 `250ms` 防抖写入。恢复时按当前 DPI、有效画布与 min/max 尺寸夹取，不合法则回退默认安全比例；不得保存 SQL、日志、请求载荷、凭据或任何任务正文。
- 若继续拖动将使并列区违反下限，停止挤压；Compact/Narrow 改为纵向、Tab 或 Drawer。顶部环境、风险、主操作、运行状态和错误恢复不得随分割变化隐藏。

### 抽屉（Drawer）
- 只放上下文相关的低频信息：高级筛选、历史、帮助、运行详情、原始响应、非核心列/字段和二级配置。
- Compact / Narrow 用抽屉替代常驻右栏；建议宽 `320–400` 或不超过有效宽度约 `40%`。底部抽屉用于终端/日志详情，打开后有效内容区高 `≥200`。
- 抽屉关闭后不丢输入、选择、筛选、滚动、未完成任务和错误状态；不得承载唯一主输入、主结果、首要动作或风险确认。

### 弹窗（Dialog）
- 仅用于不可逆/高风险确认、短小原子配置/选择、必须立即完成或取消的阻断决策。
- 初始尺寸不超过有效画布的约 `80%` 宽和 `80%` 高；内容超过一屏、包含持续编辑器/大结果表/终端/多步骤任务时改为页面、抽屉或非模态工作区。
- 确认必须有对象、范围、影响、恢复/取消路径；危险确认取消在左、确认在右、默认焦点为取消。

### 可收纳与禁止收纳

| 默认可收纳 | 严禁收纳 |
|---|---|
| 高级选项、附加筛选、说明文档、帮助、历史、预设管理、原始响应全文、非核心表格列、低频辅助工具、视觉偏好设置 | 当前对象/环境/范围、敏感状态、主输入、主结果/结果概要、必填字段、首要/取消动作、运行与失败状态、错误恢复、危险确认对象/后果、核心列 |

## 8.5 验收证据矩阵

- 每页至少覆盖 `4 个宽度档 × 100%/125%/150% DPI × 主态`；P0 页面另覆盖空态、加载、错误、成功、禁用和危险确认。
- 每张截图/录屏必须标记：页面 ID、页面类型、逻辑宽×高、DPI、构建版本、状态、抽屉/弹窗开关、检查日期和缺陷 ID。
- 对具有两个或以上展示模块的页面，运行证据必须额外覆盖：默认比例、拖拽到两个方向的安全下限、双击 handle 重置、双击 QHeaderView 当前列适配、release 后本机比例恢复、窗口档位/DPI 变化后的夹紧恢复、Narrow 的 Tab/Drawer/底部抽屉回退及键盘 focus/增量调整。
- 必须验证横向压缩、纵向压缩、DPI 切换、抽屉开关和恢复窗口五类场景；任何关键内容缺失、裁切/重叠、不可读或状态丢失均不通过。
- 这些是规格符合性证据，不能据此宣称已提升效率或减少误操作；真实效率、错误率和偏好需在后续脱敏任务走查中采集。

## 9.2 工作台

### 信息结构

- 顶部：日期、全局本地状态、继续当前工作的主入口；
- 工作台只提供摘要和入口，不复制需求管理的完整目录、详情、月份树或删除/选择操作；
- 保留“待升级事项”数量与月份摘要，点击后进入需求管理或升级准备查看完整内容；
- 常用工具：按用户最近使用/固定排序，窄屏显示“更多工具”。

### 与需求管理的边界

- 工作台不得重复展示需求管理的完整需求列表、按月目录、详情字段和管理按钮；
- 工作台中的“最近需求”只显示有限摘要（名称、状态、入口），不承担需求选择、删除、月份调整或展开/折叠；
- 完整需求操作统一回到“需求管理”，避免同一对象出现两套管理入口。

### 空态与文案

- 无需求：“暂无需求记录。前往需求管理新增或扫描目录。”
- 无上线月份：下拉禁用并显示“暂无上线月份”；说明“需求标记计划上线后会显示在这里。”
- “全部”改为“查看全部需求”；“发版联动”改为“前往升级准备”。

## 9.3 证件类型与车辆 VIN

### 共同要求

### TamengAgent：基于真实结构快照的 SQL 草案能力

#### 目标与边界

- TamengAgent 是 SQL 控制台 AI 助手内部使用的**只读 Schema 证据编排器**：它基于当前用户明确选择的数据库连接和有效 Schema 快照，解析自然语言意图并为大模型构造可验证证据，再生成一条可审阅 SQL 草案。TamengAgent 不是用户可见功能名称。
- 必须用真实快照中的表、字段、字段注释、数据类型、主键和索引信息做依据；不得把模型记忆、固定映射或猜测字段当作事实。
- 例如用户输入“查询 `prpcmain` 中创建日期倒序”，仅当当前快照中存在 `PRPCMAIN` 且字段 `created_date` 能由字段名或注释证实时，才生成 `ORDER BY created_date DESC`；不得输出不存在的 `createddate`。无证据时返回“未在当前快照找到创建日期字段”，列出候选字段并要求用户选择。
- TamengAgent **不执行、不自动填入并执行、不联网扫描、不修改连接、不修复数据、不跨连接或跨环境生成**。生成结果仅可新建“SQL 草案 · 未执行”标签页，并显示快照与字段证据；用户另行点击现有“执行当前 SQL”才可能执行。

#### 依赖与真实数据来源

| 事实来源 | 现有基础 | TamengAgent 必须使用方式 |
|---|---|---|
| 连接身份 | `tools/db_connect.py` + `connection_fingerprint()` | 只接受当前选中连接；连接别名、方言和指纹必须与快照一致。 |
| Schema 快照 | `tools/schema_snapshot.py` | 读取 `snapshot_id`、`scanned_at`、`status`、`truncated`、对象、字段；无快照、失败、过期、指纹不一致或截断影响候选对象时拒绝生成。 |
| 对象/字段上下文 | `tools/ai_object_context.py` | 用户选择的表/字段 Token 是优先证据；快照更新后 Token 必须失效，要求重新选择。 |
| 生成与安全检查 | `tools/ai_sql_draft.py`、`tools/sql_guard.py` | 输出结构化草案，逐项校验对象/字段证据和 SQL 风险；不通过则标记不可执行草案。 |
| 内网模型 | `tools/intranet_llm.py` + `tools/ptools_harness.py` | 仅向用户启用的内网模型发送最小化的脱敏 Schema 元数据和自然语言意图；不得发送凭据、行数据、主机/端口、Token、Cookie 或请求/响应正文。 |

#### 快照数据模型补齐

现有快照的对象、字段、类型、注释、主键和 `indexed` 标记继续保留；为支撑准确索引识别，扫描结果需新增如下只读元数据：

```json
{
  "indexes": [
    {
      "name": "IDX_PRPCMAIN_CREATED_DATE",
      "unique": false,
      "columns": ["CREATED_DATE"],
      "index_type": "NORMAL"
    }
  ]
}
```

- Oracle/Dameng/MySQL 等方言分别从对应系统视图采集索引名称、唯一性、索引类型、联合索引字段及顺序；采集失败只标记“索引元数据不可用”，不能伪造空索引或阻断已有字段查询。
- 快照版本从 `1` 升级为 `2`；旧快照允许浏览，但 TamengAgent 必须提示“索引信息不完整，请重新扫描”后再生成涉及索引建议的 SQL。
- 快照只存元数据，不存表行、SQL 执行结果、密码或内网模型输入/输出历史；按现有本机 `data/` 路径与删除边界管理。

#### 处理流程与字段证据校验

1. **前置校验**：确认已选择连接、内网模型可用、快照 `status=ok`、指纹匹配、未过期、对象未受截断影响；任一失败立即显示原因和“扫描结构/选择连接”入口，不发起模型调用。
2. **意图解析**：本地抽取用户输入中显式表名、字段词、排序、过滤、聚合、时间范围等候选；此阶段只生成候选，不把候选视为真实字段。
3. **本地检索与排序**：先精确匹配表名/字段名，再匹配下划线归一化名，最后匹配字段注释/对象注释；候选至少展示“表名、字段名、类型、注释、匹配依据”。
4. **消歧规则**：若唯一候选满足精确或注释匹配，自动作为证据；多个候选或置信不足时停止生成，要求用户勾选具体字段；严禁模型自行在 `create_time`、`created_date`、`create_date` 中任选其一。
5. **最小上下文生成**：只将已确认的表、字段、方言、键/索引元数据和必要注释发送给内网模型，要求返回单条 JSON 草案：`summary`、`intent`、`objects_used`、`selected_fields`、`evidence`、`condition_interpretation`、`join_assumptions`、`risk_level`、`warnings`、`sql`。
6. **生成后复核**：解析 SQL 标识符；所有表名和字段名必须回查当前快照。引用未知对象/字段、使用未证实 Join 条件、返回多语句、方言不符或安全检查失败时，不可写入可执行编辑区，只显示“草案被拦截”及具体原因。
7. **人工审阅**：通过复核的草案新开 SQL 标签页，顶部显示“SQL 草案 · 未执行”、快照 ID/扫描时间/连接别名、字段证据与风险等级；用户可复制、编辑、保存草稿。执行仍走现有独立执行确认流程。

#### UI、Loading 与失败恢复

- 右侧面板名称保持为“AI 助手”，状态区常驻：`当前连接 · 方言 · 快照状态 · 扫描时间`。TamengAgent 仅作为后台编排器运行，不出现在用户可见文案中。
- 输入框占主面积；下方按需展示“已确认对象/字段”Token、候选字段选择和字段证据。不要把环境、模型或快照拆成多张凸起卡片。
- 主按钮为“生成 SQL 草案”；次操作为“选择表和字段”“查看快照”“解释当前 SQL”。按钮可并排时保持横排，宽度不足时次操作进入“更多操作”，主按钮不截断。
- 点击后 `<150ms` 显示按压反馈；`400–799ms` 显示本面板局部“正在校验 Schema 字段…”；`≥2s` 显示阶段“校验快照 → 匹配表字段 → 生成草案 → 复核 SQL”，包含已耗时和取消入口。不得使用全局遮罩、清空现有 SQL 或遮挡当前连接/快照状态。
- 失败、取消和拦截保留原输入、已选 Token、上次有效草案和可复制错误详情；取消未确认前显示“正在取消”，不得假称已取消。

#### 研发模块与接口拆分

| 模块 | 开发职责 | 关键接口/改动 |
|---|---|---|
| `tools/schema_snapshot.py` | 快照 V2 与索引元数据扫描 | 扩展对象 `indexes`、方言索引查询、快照版本兼容、旧快照状态。 |
| `tools/tameng_agent.py`（新增） | 本地意图词提取、对象/字段检索、候选排序、消歧、证据包组装、SQL 标识符回查 | `prepare_request()`、`resolve_candidates()`、`build_evidence_context()`、`validate_generated_sql()`；全部为可单测纯函数。 |
| `tools/ai_sql_draft.py` | 继续负责模型请求与结构化 JSON 解析 | 仅接受 TamengAgent 传入的已确认 `evidence`；禁止 stale 快照参考生成。 |
| `panels/ai_workbench_panel.py` | AI 助手面板、阶段状态、候选选择、草案标签与人工审阅 | 保持“AI 助手”可见名称；复用现有 `_AiWorker`，但生成前后调用后台 TamengAgent 校验。 |
| `tests/test_tameng_agent.py`（新增） | 纯函数与安全回归 | 覆盖候选匹配、歧义拒绝、过期快照拒绝、未知字段拦截、方言与索引元数据。 |

#### 必测场景

| 场景 | 输入与前置 | 预期 |
|---|---|---|
| 创建日期排序 | 快照存在 `PRPCMAIN.CREATED_DATE`，注释为“创建日期” | 生成包含 `ORDER BY CREATED_DATE DESC` 的草案，并显示字段证据。 |
| 同义字段歧义 | 同表同时有 `CREATE_DATE`、`CREATED_DATE`，用户只说“创建日期” | 不生成 SQL；显示两个候选并要求勾选。 |
| 字段不存在 | 用户要求 `createddate`，快照无该字段 | 拦截并列出接近候选；不把模型猜测写入草案。 |
| 快照过期 | 连接指纹变化或快照状态 stale | 禁止生成，提供“重新扫描结构”。 |
| 索引建议 | 快照 V2 有 `IDX_PRPCMAIN_CREATED_DATE` | 解释中可引用真实索引名与字段；旧快照只能提示索引信息不完整。 |
| 多表无 Join 证据 | 两张表均已确认但没有 FK/注释/用户条件 | 生成被拦截或 `risk_level=unknown`，明确要求人工补充 Join。 |
| 模型越界输出 | 模型返回未知字段、多语句、写入 SQL | 草案被拦截，保留模型输出摘要但不进入可执行标签。 |

## 9.15 模型对话

- 模型下拉无可用模型时显示“未启用内网模型”；状态说明“前往设置 > 内网模型新增并启用后可对话”，提供“配置模型”次操作；
- 头部保持常驻“本机明文历史”状态与“数据与隐私”入口；不能仅依赖可关闭一次性提示；
- 操作命名：新建会话、重命名会话、删除会话、发送消息、停止生成、重新生成上一条回复、测试模型连接；
- 删除确认展示会话标题并说明本机明文记录将被移除。

## 9.16 环境签提交弹窗

- 采用流程弹窗：选择签配置 → 选择环境/时段 → 勾选需求 → 预览目标路径 → 生成并提交；
- 主操作“生成并提交环境签文档”；
- 签库地址配置为次级入口；
- 空态：“还没有配置任何签。先配置签库地址。”

# 10. 控件与文案规范

## 10.1 按钮

| 类型 | 文案结构 | 示例 |
|---|---|---|
| 本地处理 | 动词 + 对象 | 格式化 XML、复制解密明文 |
| 草稿/预览 | 动词 + 产物 + 草稿/预览 | 生成 SQL 草稿、生成 cURL 草稿 |
| 远端动作 | 动词 + 对象 + 目标 | 向测试环境发送请求、执行到当前终端 |
| 删除/清空 | 动词 + 范围/对象 | 清空本次会话、删除模型配置 |
| 本地文件输出 | 动词 + 对象 | 导出 SQL 交付包、打开导出目录 |

禁止在脱离邻近上下文或进入更多菜单后只保留“发送”“执行”“清空”“删除”“更新”“选择”“打开”等泛化文本。

## 10.2 下拉框

1. 筛选下拉有“全部 X”复位项；
2. 枚举下拉首项是实际默认值或“请选择 X”；
3. 依赖下拉显示“请先选择 X”；
4. 无可选数据时显示“暂无 X，请先新增/配置”；
5. 高风险环境下拉不得只用颜色或缩写区分，执行前再次展示完整名称。

## 10.3 Tab

- 使用名词或工作对象；
- 同层不混用动作、对象和状态；
- 不使用空白、重复、内部缩写或“其他”；
- 可关闭 Tab 的关闭按钮 Tooltip 为“关闭当前 SQL 标签页”等对象明确短语；
- 小窗口激活页标题必须完整可见。

## 10.4 图标、Tooltip 与无障碍

- 业务纯图标按钮必须有 Tooltip、accessibleName、键盘焦点和可见焦点样式；
- 数字步进组件必须可读为“增加数量/减少数量”等字段相关语义；
- Tooltip 是辅助而非唯一说明：高风险主操作、关键状态与空态不能只靠悬停理解；
- 状态不得只以颜色区分，至少同时使用文字、图标或形状。

# 11. 确认弹窗与风险交互

## 11.1 通用规则

危险或外部影响动作必须展示：

1. 操作对象；
2. 影响范围/数量；
3. 是否影响外部环境；
4. 是否可恢复及恢复方式；
5. 确认后的下一步。

取消在左、确认在右，危险确认默认焦点为取消。确认按钮使用真实动作，例如“删除连接和快照”“安装并信任证书”“向测试环境发送请求”。

## 11.2 风险模板

| 场景 | 必备确认内容 |
|---|---|
| HTTP 请求 | 方法、URL、环境、Host、认证状态、生产风险、可取消性 |
| SSH 执行 | 当前主机/会话、命令、只读或状态改变、影响、授权与回滚 |
| SQL 执行 | 连接、方言、语句类型、SQL 摘要、事务/提交语义 |
| 证书信任 | 当前 Windows 用户、证书用途、HTTPS 解密影响、移除路径 |
| 删除连接 | 名称、本地配置、凭据引用、快照、不会删除数据库对象 |
| 清空会话 | 会话条数、仅内存/本机范围、不影响浏览器或远端 |
| SVN 操作 | 本地工作副本路径、选中对象、是否丢弃修改/是否提交远端 |

# 12. 数据、安全与技术考量

## 12.1 数据边界

| 数据类型 | 默认策略 | UI 告知 |
|---|---|---|
| 网关密钥、明文、Cookie、Token、抓包内容 | 仅内存，用户主动清空或退出后移除 | 显示敏感内容、复制、清空时说明范围 |
| 接口会话 | 当前应用会话内；停止监听不等于清空 | “清空本次会话”作为明确动作 |
| SQL 连接/快照 | 本机配置与本地快照 | 删除连接必须说明同时删除快照 |
| SSH 密码 | 本机 Windows DPAPI 加密存储 | 设置页明确说明本机存储方式 |
| 模型聊天记录 | 本机 `data/` 明文 JSON，明确例外 | 常驻“本机明文历史”和数据与隐私入口 |
| 调查摘要（V2） | 仅用户确认后保存脱敏摘要 | 禁止默认收集原始敏感正文 |

## 12.2 技术约束

- 平台：Windows、PyQt6、离线优先；
- 不引入云同步、遥测、浏览器内核、外部 CDN；
- 继续使用统一的 `page_chrome`、`confirm_dialog`、`responsive`、主题与图标系统；
- 业务页面不自行复制确认、空态、Tooltip 或响应式实现；
- 所有新增交互在中英文状态下均需有对应文案；
- 页面可用性最低验证尺寸为 960×640，DPI 125%/150%。

## 12.3 数据模型建议（仅规格，不要求本期实现）

- `ui_preferences`：主题、密度、导航折叠、最近工具、固定工具；不得存敏感正文；
- `ui_context`：当前模块、当前非敏感对象 ID、最近页面、筛选条件；
- `risk_confirmation`：仅记录用户界面状态，不记录 Token/密钥/请求正文；
- `investigation_summary`（V2 停车场）：问题标题、关联对象 ID、脱敏结论、下一步、创建时间。

# 13. 设计考量

## 13.1 年轻化科技视觉语言：克制的本地工程工作台

科技感来自“主工作区更大、状态更精确、反馈更迅速”，而不是赛博装饰、监控大屏或持续发光。

### 表面、色彩与层级

- 层级固定为 `APP_BG → SIDEBAR_BG → SURFACE → ELEVATED_SURFACE`；最后一层仅供 Dialog、Menu、Drawer、Toast、Loading 等临时浮层使用。
- 每个主题仅通过 ThemeManager Token 改变颜色和表面，不改变布局、数据、交互路径或安全边界；所有新增颜色必须覆盖 calm/clear/warm/black 四主题。
- `PRIMARY` 只表示唯一主动作、激活导航和焦点/选中，不兼任成功或风险色；`SUCCESS/WARNING/DANGER` 只表示状态，必须同时配短文本或图标。
- 可使用低面积 `CYAN` 作为工程点缀（运行点、诊断标签、细边线），但不得形成第二主色、霓虹或大面积渐变。
- 常规控件使用 1px `BORDER`、8px 圆角；标准卡片 12px 圆角。仅独立语义分区才使用卡片，禁止卡片墙和重复标题占用 L4。
- 当前工作分区使用 2–3px 主色短边或 1–2px 微弱顶部线，必须同时有分区名和状态；Focus 使用即时可见的 2px `FOCUS_RING` 或高对比边界。
- 阴影只用于 Dialog/Menu/Drawer/Loading；普通卡片不常驻投影。只允许对激活输入或当前停靠区使用一次性、低透明内边界增强，禁止外发光、呼吸光、彩虹光效或闪烁。

### 图标与终端

- 使用本地 SVG 线性图标：模块 `20–24px`、按钮 `16–18px`、状态点 `6–8px`；图标是冗余识别，文字才是主语义。
- 宽屏中执行、发送、提交、删除、回滚、解锁、导出等动作必须保留文字；纯图标只用于刷新、展开/折叠、打开目录等低风险熟悉动作，并提供 Tooltip、accessibleName 和可见焦点。
- “更多”必须按上下文命名为“更多连接操作 / 更多会话操作 / 更多文件操作”等，不能统一写成模糊“更多”。
- SSH 终端保持 `TERM_*` 独立深色岛，禁止绑定/回退到 `CODE_BG`；连接状态以“主机名 + 会话状态 + 图标/颜色”表达。终端焦点可加强静态 `TERM_BORDER`，不得使用扫描线、逐行入场、闪烁、渐变或假实时效果。

## 13.2 高频信息预算、提示语与冗余清理

### 首屏信息预算

每个页面首屏按如下顺序分配空间，前一层级不得被后一层级挤压：

`主输入 / 主列表或证据 / 主输出或终端 → 当前对象与状态 → 唯一主操作 → 高频次操作 → 可选配置 → 教程与背景说明`。

除“当前对象、下一步动作、运行/成功/失败/风险”外，固定文字默认视为待删除项。说明应在首次空态、帮助、Tooltip、可展开详情或用户主动打开时出现。

### 四通道反馈规则

| 信息或动作 | 默认载体 | 不得使用 |
|---|---|---|
| 删除、覆盖、清空、SVN 提交/回滚、远端/生产请求、代理/证书、SSH 执行 | 风险确认 Dialog，写清对象、范围、影响、恢复/取消 | Toast、状态栏、仅 Tooltip |
| 环境、URL 规则、浏览器/端口、证书管理、服务器管理、系统配置、导出高级参数 | Drawer 或“更多”后的原子弹窗 | 常驻首屏大卡 |
| 必填缺失、格式错误、当前条件不满足 | 字段内联提示，焦点回到字段 | 只弹全局错误框、只变红色 |
| 已连接、抓包中、导出中、已选数量、仅内存 | 靠近任务点的一条短状态 | 多处重复胶囊、长横幅 |
| 复制、保存、刷新、加载成功 | 3–5 秒 Toast 或状态栏 | 阻断弹窗 |
| 连接/导出/生成等长任务失败 | 内联错误 + 可展开的详细原因 + 下一步 | 默认展示技术堆栈、常驻长异常 |
| 真正无对象或无结果 | 内容区空态：原因 + 下一步 | “暂无数据”、大面积教程 |
| 自动刷新、保存偏好、默认推荐 | 静默；必要时短状态 | Loading 浮层、成功弹窗 |

### 大白话文案规则

所有任务提示按“**发生了什么 → 对哪个对象 → 下一步做什么**”组织：

- 主按钮：4–10 个汉字，动词 + 对象，例如“生成本次升级资料”“发送到当前终端”。
- Tooltip：一整句、约 20–36 字，说明对象与后果，例如“清空当前终端显示，不删除远端日志。”
- 字段内联提示：约 16–28 字，例如“请输入完整 URL，例如 http://host:port/path。”
- Toast/状态栏：一句、≤30 字，例如“已导出 6 个日志文件。”
- 空态：标题 8–14 字，说明 1–2 句且 ≤40 字；必须给原因和下一步。
- 弹窗摘要：先说影响，再列对象、范围、后果、恢复/取消路径；首屏不超过四项。

固定说明只说数据边界，不重复讲功能。例如接口页头保留“本机监听 · 会话仅内存”；请求验证区单独说明“当前环境：集成测试 · 将发送请求”。模型输入区保留“本地明文会话 · 请勿粘贴密码或客户数据”，完整说明进入“数据与隐私”。

### 必须删除/按需显示的冗余

- 页面标题、Tab 标题、卡片标题重复同一模块名时，只保留页面标题和必要分区名。
- 同屏重复离线/本地/仅内存、当前系统、已选数量、已连接等状态时，只在最接近决策的位置常驻。
- “连接主机→选择服务→关键字截取”等常驻教程转为空态、首次帮助或 `?`；连接成功后用对象短状态替代。
- 生成前的大块空结果区、长期空日志区、重复 CTA、长路径常驻、低频操作平铺、成功弹窗、技术实现术语堆叠一律清理或按需展示。
- 不允许孤立“暂无数据”；必须改为“为什么为空 + 下一步”。

## 13.3 轻量功能型动效

### 全局边界

- 标准时长 `120–180ms`；hover/focus `120–160ms`；Drawer/折叠 `160–180ms`，使用 ease-out / ease-in-out。
- 焦点、风险确认、选中、错误定位、连接状态第一帧必须立即可见；每屏同一时刻最多一个非 Loading 的结构/装饰动效。
- 必须提供“减弱动效”设置：开启后 Dialog/Menu/Drawer/折叠直接切换；安全状态、焦点和键盘导航不受影响。
- 窗口 resize、断点切换可用约 `120ms` 防抖，但必须即时重排，禁止位移动画。

### 允许的动效

| 场景 | 表现 | 边界 |
|---|---|---|
| Hover / Press | 变色、边框、极轻阴影、即时压暗 | 不改尺寸、位置或文字排版；表格行不滑动 |
| Focus | 静态 Focus Ring，可短色彩过渡 | 首帧即时可见 |
| Dialog / Menu / Toast | 透明度淡入 | `120–160ms`；风险 Dialog 首帧按钮可交互 |
| Drawer | 透明度 + 最多 12px 位移 | `160–180ms`；仅用户显式打开；窄屏全幅覆盖，不挤压主编辑区 |
| 折叠区 | 高级参数、低频帮助、长错误详情、辅助日志 | `160–180ms`；用户触发，展开完再加载重内容 |
| Loading | 现有 AuroraProgress 进度流动 | 仅长任务、每页一个、不进 layout、不推移按钮 |
| 复制/保存成功 | 局部状态/Toast 轻淡入，3–5 秒消失 | 不遮挡主操作，不替代确认或错误详情 |
| 首页低频工具卡 | 轻微边界增强或 1–2px 浮起感 | 仅入口卡；技术页不使用 |

### 严禁的动效

- 页面、模块、Tab 滑动转场；侧栏收放弹跳；窗口缩放动画；表格行、日志、终端文本逐项/逐行入场。
- 粒子、扫描线、噪点、3D、玻璃拟态、全屏渐变、AI 紫粉、霓虹、呼吸灯、常驻闪烁、彩虹 Loading、数字翻牌、图表生长、假实时监控大屏。
- Skeleton shimmer、连续 spinner 泛滥、成功庆祝动画、每张卡片都动。
- 在大表格、编辑器文本、终端、Splitter resize、整页 layout 上创建动画；QSS hover 与 QPropertyAnimation 不得竞争同一属性。

### PyQt6 性能约束

- 仅可动画透明度、浮层/Drawer 的一次 geometry 和局部边界反馈；动画结束释放引用。页面不可见、最小化、切换/销毁时停止动画。
- AuroraProgress 是唯一允许长期运行的视觉节奏；搜索、筛选、排序、树展开、Tab、终端输入、日志追加均不播放 Loading/动画。
- 后台线程只更新结果与进度，不驱动逐帧业务 UI 重绘。

## 13.4 显隐与模块变体

- Dialog 仅用于风险确认、原子配置/选择、必须立即完成或取消的决策；Drawer 用于筛选、列设置、历史、会话信息、长路径和二级配置；折叠区用于高级项、低频参数、长错误详情、辅助日志和帮助；更多菜单只放低频低风险非主链路动作。
- 环境、SSH 主机/会话、HTTP 目标、TLS/证书校验、敏感显示状态、运行任务、主要错误摘要、取消/确认永远常显，不能被隐藏、折叠、动画遮掩或只靠颜色表达。
- 技术模块 L4 至少约 65% 面积分给编辑器、列表、结果、终端或原始报文；采用 Splitter/Tab，不做卡片化。流程模块聚焦当前对象、下一步和可回溯结果；轻工具让输入/输出双栏或上下布局优先于按钮和说明。
- 首页可以使用低频入口卡的轻量 hover；技术模块不得使用入口卡动画。SQL、接口、SSH/日志、加解密/格式、模型审阅均以内容阅读和结果验证优先。

## 13.5 无障碍要求

- 关键文本对比度达到可读标准；关键状态不只依赖颜色。
- 键盘可完成主动作、取消确认、Tab 切换、菜单/Drawer 打开、纯图标操作；隐藏或收纳控件不得残留在焦点链。
- 焦点不可只依赖颜色；字段报错后焦点回到首个错误字段，Dialog 关闭/取消后回到触发控件。
- 表格/树长内容可通过 Tooltip、横向滚动或详情区访问完整值；长文本不通过缩小字号解决。
- 不用幽默文案替代关闭、风险或数据处理信息；关闭应用时优先说明“隐藏到托盘/退出软件”的实际差异。

4. **变更控制**：任何业务逻辑、安全边界、数据留存、远端执行/发送、SQL 事务或网络访问语义变化，均不属于本设计基线，必须单独形成需求和风险评审；不得借 UI 改造改变现有安全事实。
5. **缺陷判定**：主输入/输出/终端被压缩到第 8.3 节下限以下、关键对象或风险被收纳、文案与真实副作用不一致、动画妨碍阅读/输入，均视为阻断验收缺陷。

### 范围变更规则

- V2 的调查摘要、个性化和效率统计不得阻断 P0 高风险页面收口；
- 每阶段结束均回查本文件第 1 章问题陈述，确认没有仅做视觉翻新。

# 15. 验收标准

## 15.1 V1.2 增量冻结条款

- 品牌统一为 `PenngTools`，作者 `Lihp` 仅在关于/版本信息和受控品牌区出现；不得在日常工作区重复署名。
- Loading 分四级：`<150ms` 静默、`150–399ms` 控件忙碌、`400–799ms` 局部 Loading、`≥2s` 可观察任务态；不得用全局遮罩遮挡输入、结果、风险状态或分隔条。
- 接口“请求验证”采用最多两行紧凑上下文：环境/Base/认证/HTTPS 与方法/最终 URL/发送动作必须可见；主按钮不得使用裸“发送”。
- 连续任务按钮优先横排；不足时先缩短次级文案，再收入“更多操作”；主操作、取消和风险说明不得截断或隐藏。
- 主题扩展为 Calm、Clear、Warm、Black 四套；轻玻璃只用于页签和浮层，SQL、日志、终端、表格、敏感输入和风险区保持不透明高对比表面。
- TamengAgent 仅允许从用户明确选择的真实、有效、可追溯快照读取表、字段、索引、注释和方言，先校验字段证据再生成 SQL 草案；不得猜测、联网拉取、自动执行或自动修复。例如“查询 prpcmain 中创建日期倒序”必须依据快照识别 `created_date`，无法证明时应拒绝生成并说明原因。
- 展示区继续遵循 V1.1 的 QSplitter/QHeaderView 规则：只拖分隔条或表头边界，最小尺寸保护，双击复位，本机按页面/Tab/模式/窗口档位保存；拖动不触发 Loading、刷新、执行或业务保存。

## 15.2 V1.2 实施闸门

1. P0-0：冻结品牌、主题 Token、Loading 状态机、请求验证安全文案和 Agent 只读边界。
2. P0-1：接入局部 Loading、失败/取消/重试和可观察任务态。
3. P0-2：完成请求验证字段重排、横排按钮和真实发送确认。
4. P0-3：完成日志/SSH 技术工作区的目标可见性、终端执行分层和 Loading 收口。
5. P0-4：完成 TamengAgent 的真实快照证据链；生成与执行严格隔离。
6. P1-1：再实施四主题、轻玻璃和 PenngTools 品牌视觉。
7. P1-2：最后实施悬浮 Tab、拖拽视觉和响应式收口。

未通过对应闸门，不得进入下一批；任何 UI 改动不得改变安全、敏感数据留存、网络访问或 SQL 执行边界。

## 15.3 通用验收

### 15.3.1 全局

- Given 用户以 960×640、125% DPI 打开任一页面  
  When 页面进入 Compact 或 Narrow 布局  
  Then 当前标题、主操作、当前对象、环境/连接状态、错误提示和确认按钮均完整可见，次操作以完整文案进入更多菜单。

- Given 某业务按钮在窄屏被收纳  
  When 用户打开更多菜单  
  Then 菜单项保留对象明确的完整动作文本，且危险动作不能仅展示图标。

- Given 用户看到纯图标业务按钮  
  When 使用鼠标悬停或键盘聚焦  
  Then 系统展示完整 Tooltip/accessibleName，说明动作与对象。

### 15.3.2 可拖拽展示区

- Given 当前页面的两个或以上展示模块在同一容器内可见  
  When 用户拖动 QSplitter handle  
  Then 仅相邻展示模块在安全 min/max 范围内同步改变宽度或高度，列表可见行数、正文可视区域或结果阅读面积随之变化；正文选择、编辑、终端输入、表格单元格操作和业务状态不受劫持。

- Given 用户持续向一侧拖动 splitter  
  When 任一展示模块将低于第 8.3 节的最小宽/高，或将遮蔽顶部环境、风险、主操作、运行/失败状态与错误恢复  
  Then handle 停止在安全边界，且 `setChildrenCollapsible(False)` 阻止任何子区缩为 `0px`、不可见或不可读。

- Given 用户双击当前 QSplitter handle  
  When 当前页面及当前 Tab/模式存在本机保存的展示比例  
  Then 仅重置该页面/Tab/模式为默认安全比例；不改变业务数据、选择、筛选、会话、草稿、请求或运行任务。

- Given 用户拖动表格列边界或双击列边界  
  When 使用 QHeaderView 当前列的边界  
  Then 仅当前列宽被拖动或按内容适配，并保持名称/时间/长文/状态列至少 `160/140/220/56px`；列顺序、行选择、筛选和单元格编辑行为不改变。

- Given 用户在同一本机调整当前页面的展示比例或列宽后释放 handle  
  When `250ms` 防抖结束且重新打开同一页面/Tab/模式/窗口档位  
  Then 恢复经 DPI、有效画布和 min/max 尺寸夹取后的本机布局；若比例不合法则回退默认安全布局，且不保存任何 SQL、报文、日志、凭据或正文内容。

- Given 窗口处于 `960–1099×640–719` 显式紧凑模式  
  When 并列展示模块不能同时满足第 8.3 节下限  
  Then 次展示模块转换为 Tab、Drawer 或底部抽屉；用户可调整已打开纵向区/抽屉的安全高度，不出现硬压的不可读三栏。

- Given 键盘用户聚焦到展示区分隔条  
  When 使用键盘增量、Home 或 End 调整尺寸  
  Then 焦点、调整方向与区域用途通过 accessibleName 和可见 focus 反馈可辨识；Home/End 分别到达最小/最大安全值，不依赖鼠标、颜色或动画。

## 15.4 空态

- Given 没有 SQL 连接、服务器、日志、模型、发版月份或可用模型  
  When 用户进入对应页面  
  Then 下拉不显示空白，而是呈现“暂无/请先选择/请先配置”的原因和可达下一步。

- Given 下拉依赖上级选择  
  When 上级未满足  
  Then 下级控件禁用或显示“请先选择 X”，不会默选无关数据。

## 15.5 高风险操作

- Given 用户尝试发送 HTTP 请求  
  When 点击发送请求  
  Then 首屏或确认框展示方法、URL、环境、Host 与认证状态，并允许取消。

- Given 用户尝试将命令发往 SSH 终端  
  When 点击“执行到当前终端”  
  Then 页面显示当前会话/主机；不连接时动作不可执行并给出原因。

- Given 用户删除数据库连接  
  When 确认删除  
  Then 弹窗明确列出连接名称、当地结构快照和不影响数据库对象的边界。

- Given 用户安装抓包证书  
  When 打开确认弹窗  
  Then 弹窗说明当前 Windows 用户信任本机 CA、可解密 HTTPS、移除入口和授权使用边界。

## 15.6 文案、状态与可拖拽展示检查清单

- [ ] 所有业务 Tab 具有非空、对象明确的标题。
- [ ] 所有可见业务按钮具有可见文字或 Tooltip；纯图标另有 accessibleName。
- [ ] 所有“发送/执行/清空/删除/更新/选择/打开”在跨模块或高风险上下文中带对象。
- [ ] 所有危险确认含对象、范围、影响、恢复方式和真实确认动词。
- [ ] 模型对话页持续显示本机明文历史边界。
- [ ] 停止接口监听不被描述为已清空会话。
- [ ] 主操作不被挤压、截断或隐藏。
- [ ] 覆盖矩阵中的同屏展示模块仅通过 QSplitter handle 或 QHeaderView 列边界调整；正文、编辑器、终端和单元格原有操作不被劫持。
- [ ] 所有 QSplitter 均设置 `setChildrenCollapsible(False)`，handle 命中 `6–8px`、视觉线 `1–2px`，并有 hover/focus、resize 光标、accessibleName 与键盘调整路径。
- [ ] 侧列表/树、主详情、编辑、结果、上下分割区和核心表格列均达到第 8.3 节下限；拖拽不会将任何关键展示区压为 0、裁切或遮蔽状态。
- [ ] 双击 handle 只重置当前页面/Tab/模式默认比例；双击表头边界只适配当前列；“恢复默认布局”不删除业务内容。
- [ ] 本机布局按页面 + Tab/模式 + 窗口档位以 release 后 250ms 防抖保存；恢复经过 DPI 和 min/max 夹取，且不持久化敏感/业务正文。
- [ ] 运行证据覆盖 Wide、Standard、Compact、Narrow 四档以及 100%/125%/150% DPI；至少包含拖拽、抵达下限、双击重置、列适配、恢复、紧凑回退和键盘焦点场景。

# 16. 开放问题

1. 是否冻结导航分组中的“交付管理 / 接口与诊断 / 运维工作台 / 数据与测试 / 智能与偏好”命名，还是由产品负责人给出内部术语偏好？
2. 是否将模型聊天本机明文历史提示设计为不可关闭的状态标签，还是允许关闭横幅但保留页头状态与隐私入口？
3. 请求验证在不同环境是否需要额外的生产环境权限/白名单判断？该规则属于业务安全策略，不能由 UI 自行假设。
4. 日志/SSH 页面中哪些命令属于“只读可直接执行”，哪些必须始终确认？需要由运维责任方提供白名单。
5. SQL 控制台的事务/自动提交语义应如何按数据库类型展示？需要由数据库维护方确认。
6. 响应式与信息密度规格已在第 8 章冻结；后续仅可通过第 14.1 节的变更控制进行调整，并需保留截图/走查证据。
7. 本机展示比例/列宽偏好是否统一写入既有 UI 偏好存储，还是采用独立布局偏好文件？无论实现位置如何，必须满足第 7.4 节的数据最小化、250ms 防抖和页面 + Tab/模式 + 窗口档位键规则。
8. 960–1099×640–719 的显式紧凑模式是否作为正式支持窗口档位保留，还是仅将 1100×720 以上作为可实施承诺？该决定影响窗口最小值与回归截图矩阵，但不得降低第 7.4 / 8.3 节的可读性下限。

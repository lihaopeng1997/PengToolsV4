待升级事项：固定任务行、编号展示与完成闪退修复

分析范围：工作台 panels/dashboard_panel.py 的待升级任务行与“已完成”操作；不改变现有月份筛选、任务入选规则或需求业务数据。

根因确认

闪退“已完成”按钮的回调会立刻执行 refresh()，它在当前鼠标点击事件尚未结束时清空并延迟销毁整列任务行。当前按钮、所属任务行和布局同时被重建，存在 Qt 原生事件派发与控件销毁重叠的高风险路径。

自适应任务行没有固定高度；标题虽关闭换行，但未定义可用宽度、最大行宽或省略规则，因此会随内容和相邻按钮挤压而产生不稳定尺寸。

字段现状

需求台账已有 code 与 record_kind 字段，现有数据可分别承载需求号和 BUG 号。待升级列表目前只渲染标题，未显示编号。

编号将优先展示 code；缺失编号时回退为“需求”或“BUG”，不伪造编号。

拟议修复

固定任务行
待升级任务行统一固定为 64px 高；左右内边距 10px，上下内边距 7px，列表间距 4px。滚动区承担任务数量增长，不再由单项高度扩张。
标题处理
标题保持单行；给文本区设置可收缩宽度与 ElideRight，过长时显示“…”；完整标题放在 Tooltip 中，鼠标悬停可查看。
编号展示
标题左侧增加紧凑编号胶囊：例如 REQ-20260801 或 BUG-101。标题与编号同一行，第二行保留“系统 · 计划日期”。
完成操作
保存完成态后不在按钮点击栈中立刻销毁当前行；改为将刷新安排到 Qt 下一轮事件循环执行，并在刷新前保留当前月份。这样按钮事件完整返回后才重建列表。
点击分流
任务行点击仍打开需求详情；点击“已完成/撤销完成”仅执行完成状态更新，不再向上触发任务行点击，避免完成后误跳转或重叠事件。

回归验证

  • 构造超长标题任务：行高固定为 64px，标题实际文本省略且 Tooltip 保留全文。
  • 分别验证需求与 BUG：展示各自的 code。
  • 模拟真实按钮点击：完成态保存成功、列表安全刷新、任务仍存在且显示“已完成”。
  • 模拟撤销：状态回退，不修改需求的 status、上线日期或 SQL 数据。

影响范围

panels/dashboard_panel.py：任务行组件、待升级行渲染、完成后的安全刷新。

resources/style.qss：编号胶囊与固定行视觉规则。

tests/test_dashboard_release_monthly.py：补充点击、尺寸、省略与编号回归。

不修改需求台账结构、月份筛选规则、发版 Excel、SQL 流程和历史完成态格式。

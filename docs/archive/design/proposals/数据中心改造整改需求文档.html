二、改造项 ②：Redis 扫描展示修复

2.1 现状与根因（为什么扫不到 / 显示不对）

扫描函数 tools/schema_snapshot.py::_scan_redis 本身能扫到 key，问题在展示层：

  • 根因 A — 树分组错位：panels/ai_workbench_panel.py:1112 的 _rebuild_tree 用 owner = obj.get('owner') or obj.get('object_type') 分组。Redis 对象 owner=''、object_type 是 key 的数据类型（string/hash/list/set/zset），导致所有 key 被按「string / hash / list…」错误地当成 schema 分组，层级完全错乱。
  • 根因 B — 假字段：_scan_redis（571-576 行）给每个 key 塞了一个无意义字段 {'name': kind, 'data_type': kind}，点开 key 详情只显示「string / string」这种一行废话，看起来就像「没有数据」。
  • 根因 C — DB 序号隐患：db_connect.open_connection 里 Redis 用 db=db_index（默认 0）。如果数据在非 0 号库、或用户没填 DB 序号，就真的扫不到。属连接参数问题，需在扫描时给出提示。

2.2 正确目标形态

Redis 的「对象」是 key，不是表。展示应表达：key 名 + key 类型 + 该 key 的摘要信息。

key 类型树节点显示详情（字段）应展示
stringkey名 [string]value 预览（截断）
hashkey名 [hash]field 列表（HKEYS，只读）
listkey名 [list]长度（LLEN）
setkey名 [set]成员数（SCARD）
zsetkey名 [zset]成员数（ZCARD）
none/其他key名 [unknown]（空，或提示「已过期/无类型」）
安全边界：只允许使用只读命令（TYPE / HKEYS / HLEN / LLEN / SCARD / ZCARD / STRLEN / TTL / GET）。禁止执行任何写命令（DEL / SET / HSET / EXPIRE / FLUSHDB 等）。扫描取数据必须走 scan_iter（现有 REDIS_KEY_CAP=5000 上限保持不变）。

2.3 具体改法（精确到函数）

改法 1：_rebuild_tree 对 NoSQL 方言不做 owner 分组

文件 panels/ai_workbench_panel.py，函数 _rebuild_tree（约 1101-1129 行）。当前用 owner 分组生成「schema → 对象」两层；对 redis/mongodb，改为单层平铺：根节点下直接挂 key/collection 节点，不套 schema 层。

# 伪代码示意（Grok 落地时保持现有控件用法一致）

        node = QTreeWidgetItem([format_object_label(obj)])
        node.setData(0, UserRole, {'kind': 'table', 'object': obj})
        root.addChild(node)
else:
    # 原有 owner 分组逻辑保持不变（oracle/mysql/dameng/oceanbase）
    ...

改法 2：_scan_redis 产出真实摘要字段，替换假字段

文件 tools/schema_snapshot.py，函数 _scan_redis（560-582 行）。为每个 key 生成有意义的 columns（只读命令取摘要），而不是 [{'name': kind, 'data_type': kind}]。

# 每个 key 的 columns 按类型生成（只读、异常吞掉降级为空）
# string → [{'name':'value', 'data_type':'string', 'comment': value[:200]}]
# hash   → 遍历 HKEYS（截断前 N 个）作为字段
# list   → [{'name':'length', 'data_type':'int', 'comment': llen}]
# set/zset → [{'name':'cardinality', 'data_type':'int', 'comment': card}]
实现约束：_scan_redis 的返回值仍必须是 (objects, truncated) 二元组，objects 仍是 dict 列表，字段结构须满足 _clean_object 的清洗规则（name/data_type/nullable/position/comment/primary_key/indexed）。不要改 _clean_object 本身。

改法 3：扫描提示 DB 序号

在扫描完成回显（_on_db_ok 里 kind=='scan' 分支）或 _refresh_header 中，当方言为 redis 时，把当前 DB 序号体现在提示里，例如连接元信息追加 DB=0。避免用户误以为「扫不到」其实是连错了库。此条为可选增强，不阻塞主改动。

三、改造项 ③：MongoDB 扫描展示修复

3.1 现状与根因

  • 根因 A — 树分组错位（同 Redis）：_scan_mongo 产出 object_type='COLLECTION'、owner=''，被 _rebuild_tree 的 owner or object_type 塞进一个叫 COLLECTION 的 schema 分组，层级错乱。
  • 根因 B — 字段推断太弱：_scan_mongo（531-557 行）只用 find_one() 取第一条文档的顶层 key，嵌套字段、数组元素、其他文档独有的字段全部漏掉；空集合 columns=[]。

3.2 正确目标形态

MongoDB 的「对象」是 collection。字段应通过采样多条文档 + 递归合并推断，并明确标记为「推断字段」（inferred=True）。

  • 每个 collection 采样 N 条文档（建议 N=20，可配），递归合并所有 key（含嵌套字段，用点号路径如 a.b.c，数组元素用 a[] 或 a.0 表示）。
  • 空集合至少保留 _id 作为占位字段，不要返回空 columns（否则看起来像「没数据」）。
  • 每个字段 data_type 用 type(value).__name__（复用现有 _type_name），comment 留空或写「推断」。
# _scan_mongo 采样合并伪代码
def _collect_keys(doc, prefix='', out=None):
    # 递归：dict 下钻、list 加 [] 标记、标量记录类型
    ...

for name in names:
    docs = list(conn[name].find().limit(SAMPLE_N))
    keys = {}
    for d in docs:
        _collect_keys(d, out=keys)
    columns = [{'name': k, 'data_type': t, ...} for k, t in keys.items()] or [_ID_PLACEHOLDER]
安全边界：采样必须用 find().limit(N)，禁止 aggregate 或 mapReduce；不读取 system.* 内部集合的敏感内容（采样仅取字段名，不落盘、不回显完整文档内容，字段值只用于推断类型）。

3.3 具体改法

文件 tools/schema_snapshot.py，函数 _scan_mongo（531-557 行）：

  1. 将「单条 find_one」改为「采样 find().limit(20) + 递归合并 key」。
  2. 空集合 columns 兜底为 [{'name': '_id', 'data_type': 'object', ...}]。
  3. 保持返回 (objects, truncated) 结构、object_type='COLLECTION'、inferred=True 不变。

树分组修复复用「二、2.3 改法 1」（_rebuild_tree 对 mongodb 也做单层平铺），两处共享同一处改动，不要重复实现。

三·五、改造项 ④：Redis 键值管理（按方言差异化功能区）

4.1 设计原则（本次范围的总基调）

用户明确要求：「不一定要完整的面板，跟当前面板规则保持一致就行，只是每个数据库连接对应的功能不一样」。即——不新起独立面板、不另立导航，而是在现有「数据中心」面板内，按当前连接的 dialect 差异化展示中栏功能区：

dialect中栏功能区说明
oracle / mysql / oceanbase / dameng / 等关系型现有 SQL 多标签编辑器（sql_tabs）保持原样，一字不改
redisRedis 键值管理（DB 切换 + 键列表 + 模糊搜索 + 值查看/格式切换/删除/刷新/TTL）本次新增，复用现有控件与骨架
mongodb集合查询（沿用现有 SQL 编辑 + find 语法）本次不新增交互，仅靠改造项③修正展示
挂载点（已核对源码）：中栏当前结构为 middle → editor_row(格式化/清空/风险chip) + sql_tabs(多标签编辑)。
Redis 键值管理区替换 sql_tabs 所在位置（ai_workbench_panel.py:408-413），仅在 dialect=='redis' 时用 QStackedWidget 或按需 setVisible 切换；关系型方言时仍显示 sql_tabs。
「选中 key 后下方展示 value」复用下栏结果区 result 表格（ai_workbench_panel.py:554，现有 _fill_result 已能接收 {columns, rows}），不新造结果控件。

4.4 写操作安全边界（已拍板：复用现有确认门禁）

  • 新增 Key / 删除 / 设置 TTL 三种写操作，全部复用现有 tools/sql_guard.py 的 classify_statement → REDIS_WRITE 分类 → needs_confirm=True 门禁（ai_workbench_panel.py:1109-1120 的 confirm_action(danger=True)）。
  • 写操作点击后，弹「需确认写操作」对话框，内容含 连接名 + 类型 + 命令类别 + 具体命令，默认焦点在「取消」。
  • 禁止绕过门禁直接执行；禁止新增 FLUSHDB / FLUSHALL / CONFIG / SHUTDOWN 入口（这些即使底层支持也不提供按钮）。
  • 删除 key 前必须二次确认，确认文案明确写出 key 名。

4.5 骨架规范遵守（避免违反现有 UI 规范）

  • Redis 功能区不是独立页面，必须复用现有 ds-card/ds-zone 容器、apply_button/apply_table/size_line 等公共控件，风格与关系型方言一致。
  • 主操作（如「新增 Key」或「运行」）保持 ≤1 个 primary，其余用 ghost/secondary，不新增超过 8 个工具栏按钮。
  • 写按钮（删除 / 设置 TTL / 新增）统一放功能区，不塞进 L3 筛选条（筛选条只放搜索/DB 切换这类不写数据的控件）。
  • 空状态（无 key / 未扫描）复用 make_empty_state。

SQL 控制台 · 数据库对象导航优化设计图

从“混合层级树”改为“对象目录 + 字段详情”的可辨识结构

表与字段分离对象类型显式标识字段元数据表格化兼容六类数据库

问题与改造结论

原设计的问题

  • 连接、Schema、表、字段全部塞在一个无限树层级里。
  • 表名和字段名视觉权重接近，无法一眼识别“当前看到的是表还是列”。
  • 字段类型、可空、注释等决策信息缺失。
  • 大库展开后层级过深，检索效率低。

新设计：对象目录 + 字段详情

  • 左侧仅展示连接、Schema、对象，字段不进入树。
  • 对象有固定类型图标和标签：表、视图、集合、键模式。
  • 选中对象后，右侧独立展示字段表：名称、类型、可空、键、注释。
  • 字段可勾选为 AI 上下文，并可插入 SQL 编辑器。
一句话原则：左侧回答“有什么对象”，右侧回答“这个对象有哪些字段”，编辑器回答“我要写什么 SQL”。不再让用户在一棵树里猜层级。

操作路径设计

1. 选择连接 → 选择 Schema（默认当前账号 Schema） 2. 在“对象目录”按类型筛选或搜索对象名/注释 3. 单击对象 → 右侧加载对象详情和字段元数据 4. 勾选字段 → 底部显示“已选 N 个字段” 5. 选择动作： - 双击字段 / 点击“插入选中字段” → 插入当前 SQL Tab - 点击“生成 SELECT” → 新建 SQL Tab 并生成基础 SELECT - 点击“发送给 AI” → 右侧 AI 助手收到“表 + 已选字段”上下文 6. AI 生成 SQL 草案 → 写入“AI 生成”新 Tab，绝不自动执行

边界条件

  • 未扫描快照：对象目录显示空状态，只提供“扫描/更新结构”，不显示伪造树。
  • 对象名相同但 Schema 不同：列表显示 OWNER.OBJECT_NAME，搜索结果同时显示 Schema 徽标，不可只显示裸名称。
  • 字段超过 100：字段详情表按当前对象分页或虚拟列表，默认带字段搜索；不一次性卡死 UI。
  • 字段勾选只属于 AI 上下文和“插入字段”动作，不会限制用户在手工 SQL 编辑器中自由写任何字段。
  • 选择视图：详情字段可查看和发送 AI；“生成 SELECT”默认只读。

给 Grok 的覆盖规则

本文档覆盖 AI_SQL控制台与模型对话模块设计图.html 中 SQL 控制台左侧“混合树结构”的展示方案。Grok 实施时必须以本设计图为对象导航视觉与交互基准：字段不进入对象树；左侧只列对象；右侧表格化展示字段元数据。

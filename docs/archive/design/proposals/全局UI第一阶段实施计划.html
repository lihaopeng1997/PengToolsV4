PengToolsHub · 开发计划 01

全局 UI 基础设施实施计划

先统一主题、密度、侧栏偏好与公共页面骨架，再进入接口排查、SSH、日志等核心模块的具体界面改造。当前仅为实施计划，尚未修改业务代码。

第一阶段目标

主题 token

确保四套主题 token 完整且 QSS 无未替换占位符。

密度偏好

新增紧凑/舒适与侧栏折叠的兼容设置。

公共骨架

提供标题、上下文与主操作容器，不耦合业务。

安全回归

导航映射、代理行为、会话隔离和敏感边界不变。

改造范围

文件计划改动不做什么
ui/theme_manager.py补齐 token 校验与 QSS 占位符检测。不改图标注入、主题监听器和现有 token 含义。
config.py兼容 ui_density、sidebar_collapsed。不变更数据根、凭据或安全设置。
ui/design_system.py新建密度尺寸映射纯函数。不导入 panel、不读写文件。
ui/page_chrome.py新建页面标题/上下文/操作槽容器。不承载业务、不发请求。
style.qss主题、状态、焦点、紧凑/舒适视觉规则。不修改终端 TERM 色 token。
settings_panel.py增加密度和启动时侧栏折叠控件。不建立第二套保存流程。
main_window.py消费视觉偏好并刷新 QSS 属性。不改 nav → Stack 映射和面板副作用。

不可触碰的行为

导航与安全边界：Stack 顺序固定；nav 8/9 同指向 PersonalPanel，10/11/12/13 分别指向需求、格式、接口排查、日志排查。离开接口排查自动暂停代理、per-tab SSH 连接、日志流式导出、网关内存态解密与现有敏感数据禁止落盘规则全部保持原样。

按测试驱动执行

任务 1–2：token 与设置

先写 token 完整性、QSS 无占位符、旧配置回退和密度尺寸映射的失败测试，再补最小实现。

任务 3–4：公共组件与 QSS

新增无业务耦合的 PageChrome，并加入按钮、状态、焦点、密度样式选择器。

任务 5–6：设置与主窗口

设置页沿用现有保存信号；主窗口仅应用视觉属性并回归验证导航映射。

任务 7：交付验证

运行定向测试、敏感扫描和离线安装包构建；通过后才提交并推送。

验证标准：四个主题可渲染、旧设置兼容、密度可持久化、无 QSS token 残留、导航和代理行为无回退、敏感数据未新增持久化、离线包构建成功。

后续节奏

第一阶段通过后，依次落地接口排查 → SSH/终端 → 日志排查三条核心排障链路，再覆盖首页、发布、工具与辅助模块。每轮均需要定向测试、敏感扫描和离线打包。

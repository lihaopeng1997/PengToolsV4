表头与按钮紧凑化设计方案

文件库列表列伸缩修复 · 全局按钮尺寸收紧 · 列表行高优化

日期：2026-08-04 设计：UI Designer 影响范围：全局 QSS + 3 个面板 风险：低 · 纯视觉调整

一、问题诊断

1文件库表头列不填满

现象：窗口放大后，文件库列表右侧留大片空白，5 列内容没有撑满可用宽度。

根因：所有 5 列均设为 Interactive 模式 + 固定列宽，没有任何一列 Stretch，多出的空间无人认领。

文件：panels/requirement_panel.py:1418-1419
for col in range(5):
  file_header.setSectionResizeMode(col, Interactive)
列宽：280 + 96 + 140 + 80 + 320 = 916px（固定）

2日志排查远端列表同样不填满

现象：远端文件树 4 列在窗口放大后右侧也有空白。

根因：与文件库完全一致——4 列全部 Interactive，无 Stretch 列。

文件：panels/ops_log_panel.py:1789-1790
for col in range(4):
  hdr.setSectionResizeMode(col, Interactive)
列宽：160 + 72 + 64 + 120 = 416px（固定）

3文件库按钮没填满工具条

现象：文件库 9 个操作按钮（打开目录 / 刷新 / 更新 / 添加文件 / 新建文本 / 锁定 / 解锁 / 回滚 / 提交）在容器宽度足够时仍只占左侧一小条，右侧空白。

根因：按钮容器 action_row 末尾有 addStretch(1)，按钮设了 setMinimumHeight(24) 但未设 expanding 策略，且 compactAction QSS padding 偏大（7px 12px），按钮内距吃掉了可用空间。

QSS：resources/style.qss:265
QPushButton[compactAction="true"] { padding: 7px 12px; min-height: 18px; }

4日志排查按钮尺寸过大

现象：「上级 / 打开 / 刷新 / 选用」「看尾部 / 终端截取 / 导出日志 / 预览」这些行内操作按钮高度 36px，在窄栏里显得臃肿，挤占了列表空间。

根因：虽然调用了 apply_button(..., compact=True)，但 compactAction 的 QSS padding 仍为 7px 12px，加上 FIELD_H=36 的 setFixedHeight，实际渲染高度仍约 36px，没有真正紧凑。

按钮高度来源：ui/field_metrics.py:8
FIELD_H = 36
compact 仍走：size_field_height(button, 36)

二、设计方案

2.1 列伸缩策略：名称列 Stretch + 其余 Interactive

核心原则：名称列是变长内容列，设为 Stretch 自动填满剩余空间；类型 / 大小 / 修改时间 / 路径等短值列保持 Interactive（用户可拖拽调整），保证放大时填满、缩小时可横向滚动。

名称Stretch · 自动撑满
类型Interactive 96px
修改时间Interactive 140px
大小Interactive 80px
路径Interactive 200px

路径列从 320px → 200px（路径列在文件库里只是辅助参考，不需要那么宽，让名称列拿到更多空间）。

日志排查 · 远端文件树（4 列）

名称Stretch · 自动撑满

2.2 按钮紧凑化：全局 compactAction 尺寸收紧

将 compactAction 的 QSS padding 和 min-height 统一收紧，使所有标记了 compactAction=true 的按钮真正变成紧凑态（约 28px 高），而非现在的"假紧凑"（仍 36px）。

属性 当前值（旧） 目标值（新） 说明
padding 7px 12px 4px 10px 上下从 7→4、左右从 12→10，减少内距
min-height 18px 16px 降低最小高度门槛
font-size 13px（继承） 12px 紧凑按钮文字小一号
实际渲染高度 ~36px ~28px padding + min-height + 文字 = 约 28px
旧（36px）： 上级 打开 刷新 选用 看尾部
新（28px）： 上级 打开 刷新 选用 看尾部

同时调整 size_compact_button() 的 Python 侧高度，让 setFixedHeight 与 QSS 配合而非冲突：

# ui/field_metrics.py — size_compact_button() def size_compact_button(button) -> None: button.setProperty('compactAction', True) button.setMinimumWidth(BTN_COMPACT_MIN_W) # 保持 72px 最小宽 button.setFixedHeight(28) # 旧：FIELD_H=36 → 新：28 button.setProperty('compactAction', True)

2.3 非紧凑按钮也适当收紧

全局 QPushButton 默认 padding 从 8px 14px → 6px 12px，primary-btn 从 9px 16px → 7px 14px，让所有按钮视觉上更紧凑但不影响可点击性。

选择器 旧 padding 新 padding
QPushButton（全局默认） 8px 14px 6px 12px
QPushButton#primary-btn 9px 16px 7px 14px
QPushButton[compactAction="true"] 7px 12px 4px 10px

2.4 列表行高微调

文件库和远端列表的行高从 min-height: 27px → 30px，让列表内容"放大"——行间距更舒展，可读性更好。这不是缩小，而是让列表展示区域在按钮缩小后获得更多垂直空间，整体"列表放大、按钮缩小"。

QSS 选择器 旧 min-height 新 min-height 说明
#requirement-file-tree::item 27px 30px 文件库行高 +3px
#ops-remote-tree::item 27px 30px 远端列表行高 +3px
#requirement-file-tree::item padding 4px 7px 5px 8px 上下/左右各 +1px

六、风险评估

风险项 等级 缓解措施
compactAction 按钮高度从 36→28，部分页面按钮内文字可能换行 低 所有 compactAction 按钮文字均为 2-4 字短词（上级/打开/刷新/选用/看尾部等），28px 高 + 12px 字号足够
名称列 Stretch 后用户拖拽列宽行为变化 低 Stretch 仅作用于名称列，其余列仍 Interactive 可拖拽；名称列 Stretch 时拖拽其余列会自动调整名称列宽度
全局 QPushButton padding 收紧影响非 compactAction 按钮 低 padding 6px 12px 仍满足 44px 最小触控靶（padding + min-height + 文字），且桌面工具台非触屏场景
行高 +3px 后可见行数减少 极低 27→30px 仅减少约 10% 可见行数，但按钮缩小释放的垂直空间远大于此

总结

本次改造通过三个维度的协同调整解决"列表不填满 + 按钮过大"问题：

  1. 列伸缩修复：名称列从 Interactive → Stretch，窗口放大时自动填满剩余宽度——覆盖文件库（5列）、远端列表（4列）、批量导出树（3列）共 3 棵树。
  2. 按钮真正紧凑：compactAction 的 QSS padding 从 7px 12px → 4px 10px，Python 侧 setFixedHeight 从 36→28，让"标记为 compact 的按钮"真正变成 28px 紧凑态，而非假紧凑。
  3. 列表行高放大：行高 27→30px、padding 4px 7px → 5px 8px，让列表内容更舒展——"按钮缩小让出的空间还给列表"。

改动范围：6 个文件，纯视觉层面，无业务逻辑变更，无数据结构变更。

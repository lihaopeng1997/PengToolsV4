自然语言输入区 · 表与字段右键选择交互设计图

AI SQL 助手的主选择入口：右键添加表 / 添加字段 → 搜索当前库对象 → 选择字段 → 结构化回填自然语言

输入区右键菜单表 → 字段两步弹窗当前库快照搜索结构化 Token 回填

交互设计结论

主入口调整：表/字段选择不再依赖左侧对象目录。用户直接在 AI 自然语言输入框内右键，选择“添加表”或“添加字段”，通过弹窗搜索当前库中的对象；先选表，再选字段，最后把带类型的结构化 Token 插回当前光标位置。对象目录仍保留，但只作为浏览和手工 SQL 编辑辅助。
1右键输入区

在自然语言任意光标位置右键，选择“添加表”或“添加字段”。

2搜索并选择

弹窗仅加载当前连接且快照有效的对象。选字段时强制先选表，再多选字段。

3结构化回填

选中对象以可辨识 Token 回填，用户继续输入自然语言条件，AI 将 Token 对应对象作为强上下文。

弹窗规则

  • “添加表”模式：只显示左列对象，确认后只插入表 Token；字段列不展示。
  • “添加字段”模式：必须先选表，才启用右列字段；支持多选字段。
  • 搜索优先匹配当前表库快照的对象名、字段名、表/字段注释；不在 SQL 中模糊猜测对象。
  • 同名对象不同 Schema 时显示 OWNER.OBJECT_NAME；Token 保存 qualified_name，展示时可简洁显示。
  • 集合/键模式选择时右侧提示其非关系型语义，不提供关系型字段强约束；Mongo 显示“样本字段”，Redis 显示“键类型/模式”。
  • 快照不存在或已过期：弹窗不显示旧对象，改为“请先扫描/更新当前库结构”的空状态，并提供扫描入口。

Token 回填与 AI 上下文规则

自然语言文本（用户可自由编辑） + 表 Token（model_context.selected_objects） + 字段 Token（model_context.selected_fields） → AI Prompt：方言 + 已选对象/字段完整元数据 + 用户自然语言 → AI 生成说明：objects_used / selected_fields / condition_interpretation / join_assumptions → SQL 草案写入新 AI Tab，绝不自动执行
规则要求
Token 与显示Token 以 QPlainTextEdit/富文本或等效受控组件实现，必须可视觉区分、可退格删除、可点击查看元数据；不得把不可见 JSON 标记混入用户文本。
编辑后行为用户手工编辑普通文本不清除 Token；用户删除 Token 时同步移除对应对象上下文；用户点击“清除已添加对象”只删 Token。
强约束AI Prompt 明确提供 Token 对应 qualified_name 与字段，且要求优先使用；如果用户添加字段，生成 SQL 不得引用未选中的业务字段（允许 COUNT(*)）。
多表用户添加多表但未在自然语言说明关联条件时，AI 生成说明必须输出 Join 假设/警告，SQL 仅为草案，不得成为“可安全执行”状态。
插入位置点击确认后，Token 插入右键触发时保存的光标位置；若输入框已失焦或内容变化，回填到当前光标末尾并提示，不得覆盖用户输入。

给 Grok 的覆盖规则

本文档覆盖此前两份设计图中“左侧对象目录/字段 checkbox 是 AI 表字段选择主入口”的描述。最终规则：AI 自然语言输入框的右键“添加表 / 添加字段”弹窗，是选择表字段的主入口；对象目录仅用于浏览和手工 SQL 辅助。

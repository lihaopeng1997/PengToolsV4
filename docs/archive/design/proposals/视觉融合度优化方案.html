一句话诊断

项目已有完整的设计系统（layout_metrics / design_system / page_chrome），但执行率不均 + 零阴影零动画 + 硬编码颜色泛滥，导致三大视觉问题：嵌入式割裂、风格死板、整体不协调。

1 嵌入式割裂感

根因诊断

核心问题：零阴影 + 嵌套硬边框 = "盒子套盒子"

整个代码库中 QGraphicsDropShadowEffect 使用次数为 0。PyQt6 QSS 不支持 box-shadow，必须用 Python 侧的 GraphicsEffect。没有阴影意味着边框是唯一的深度线索，而项目大量使用 border: 1px solid __BORDER__，导致内容区与主界面之间产生硬切——视觉上就像"外挂嵌入"而非自然融合。

具体表现

网关解密面板 APP背景 → QGroupBox#gateway-config-group(border) → QFrame#gateway-work-zone(border) → QFrame#gateway-action-zone(border) 3 层嵌套硬边框，每层都是 1px solid，无阴影过渡
需求管理面板 APP背景 → req-toolbar-card(border) → req-tree-card(border) + req-file-card(border) + req-sql-card(border) 工具栏、树、文件、SQL 四个卡片各有边框，并排时形成"格子"观感

7个面板无标准骨架 credit / settings / sql / vin / ops / docx / personal 自行创建标题样式，与使用 make_page_header() 的6个面板视觉断层

优化方案

方案 A：引入轻量阴影体系（核心）

在 ui/design_system.py 中新增 apply_shadow(widget, level='sm') 工具函数，封装 QGraphicsDropShadowEffect：

# ui/design_system.py 新增 def apply_shadow(widget, level='sm'): """为控件添加柔和阴影，替代纯边框做深度区分。""" from PyQt6.QtWidgets import QGraphicsDropShadowEffect effect = QGraphicsDropShadowEffect(widget) presets = { 'sm': {'blur': 8, 'y': 1, 'alpha': 0.04}, # 卡片默认 'md': {'blur': 16, 'y': 4, 'alpha': 0.06}, # 悬浮/弹层 'lg': {'blur': 24, 'y': 8, 'alpha': 0.08}, # 对话框 } p = presets.get(level, presets['sm']) effect.setBlurRadius(p['blur']) effect.setOffset(0, p['y']) effect.setColor(QColor(0, 0, 0, int(p['alpha'] * 255))) widget.setGraphicsEffect(effect) return effect

在 page_chrome.make_zone_card() 中默认应用 apply_shadow(frame, 'sm')，让所有使用设计系统的卡片自动获得阴影。

方案 B：减少嵌套边框层级

将 3 层嵌套硬边框收敛为"外层有边框+阴影，内层无边框仅用背景色区分"：

2 风格死板

根因诊断

核心问题：零动画 + 瞬变 hover = 交互无"呼吸感"

整个代码库中 QPropertyAnimation 使用次数为 0。虽然 QSS 定义了大量 :hover 伪状态（约 35 处），但所有状态切换都是瞬间跳变——背景色、边框色直接跳到新值，没有任何过渡效果。这导致界面虽然"能交互"，但感觉"僵硬"——像在操作表格而非现代软件。

具体表现

交互场景 当前行为 期望行为
按钮 hover 背景/边框色瞬间跳变（QSS :hover） 150ms 渐变过渡（需 QPropertyAnimation 或 QGraphicsOpacityEffect）
卡片 hover 仅 #tool-card:hover 变边框色 轻微上浮（translateY -2px）+ 阴影加深
面板切换 StackedWidget 瞬间切 可选：100ms 淡入效果（QPropertyAnimation windowOpacity）
列表项选中 背景色瞬间变 __PRIMARY__ 保持瞬变（选中态需即时反馈，不适合动画）
Loading 浮层 直接 show/hide 150ms 淡入淡出

优化方案

方案 A：按钮 hover 渐变（低风险，高频感知）

在 ui/design_system.py 的 apply_button() 中，为按钮安装 EventFilter 实现 hover 渐变：

class HoverFadeFilter(QObject): """按钮 hover 时用 QPropertyAnimation 渐变背景色。""" def eventFilter(self, obj, event): if event.type() == QEvent.Type.Enter: self._animate_color(obj, 'background', target=PRIMARY_SOFT, ms=150) elif event.type() == QEvent.Type.Leave: self._animate_color(obj, 'background', target=SURFACE, ms=150) return False

注意：QSS :hover 伪状态和 QPropertyAnimation 不能同时控制同一属性。方案是 QSS 去掉 :hover 的 background 声明，改由 Python 动画驱动。或退一步——仅对 #tool-card 等少量核心卡片做动画，按钮保持 QSS 瞬变（低风险策略）。

方案 B：卡片 hover 上浮（中风险，高感知）

对工作台首页的 #tool-card 和需求管理的分区卡片，hover 时用动画微抬：

def _animate_lift(widget, up=True): anim = QPropertyAnimation(widget, b'pos') cur = widget.pos() target_y = cur.y() - 2 if up else cur.y() + 2 anim.setDuration(200) anim.setStartValue(cur) anim.setEndValue(QPoint(cur.x(), target_y)) anim.setEasingCurve(QEasingCurve.Type.OutCubic) anim.start(widget) widget._lift_anim = anim # 防止 GC

方案 C：Loading 浮层淡入淡出（低风险）

当前 Loading 浮层直接 show/hide，视觉突兀。用 QGraphicsOpacityEffect + QPropertyAnimation 做 150ms 淡入淡出。改动仅涉及 ui/loading_overlay.py，不影响业务逻辑。

4 实施路线（风险递增）

  • 1
    硬编码颜色 → Token 替换
    低风险 纯 QSS 值替换，30 处硬编码 hex → token，使所有颜色响应主题切换。改动：仅 style.qss，零 Python 代码。
  • 2
    卡片样式统一 + 重复定义清理
    低风险 将 gateway-* / xml-* / req-* / release-* 的卡片样式收敛到 ds-card / ds-zone / ds-muted。删除 #ops-title 重复定义，运维助手面板改用 make_page_header()。改动：style.qss + 少量 Python objectName 替换。
  • 3
    引入阴影体系
    中风险 新增 apply_shadow() 工具函数，在 make_zone_card() 中默认应用。关键卡片（tool-card / req-*-card / dashboard-task-card）手动添加阴影。同时将部分卡片边框从 1px solid 改为 1px solid transparent（阴影做深度，边框做仅色调微调）。改动：design_system.py + page_chrome.py + 各面板调用点。
  • 4
    交互动画 + 页面骨架迁移
    较高风险 Loading 浮层淡入淡出（低风险子项）。卡片 hover 上浮动画（中风险子项）。7 个面板迁移到 make_page_header()（较高风险，涉及布局重构）。建议分步验收。

推荐执行顺序

先做阶段 1-2（低风险，纯样式收敛）→ 验收视觉效果 → 再做阶段 3（阴影）→ 最后做阶段 4（动画+骨架迁移）。

阶段 1-2 预计 ~60 处 QSS 值替换 + ~10 处 objectName 替换，零逻辑改动，可快速打包验证。阶段 3 引入阴影是"割裂感"的核心解决方案，但需要 Python 侧改动，建议单独验收。阶段 4 的动画效果是"死板感"的核心解决方案，但 hover 动画与 QSS :hover 有冲突风险，需逐个控件验证。

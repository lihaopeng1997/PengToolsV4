Harness 技能（Skill）配置化设计方案

面向 Grok 开发 · 边界卡死 · 禁止扩大改动 · v1.0 · 2026-08-27
内置 skill 3 → 5 个 配置清单驱动（去硬编码） 用户可自定义多个 skill 升级不丢：落 local_data_dir()

〇现状与目标（一句话看清要改什么）

现状：Harness 底层已经有一套 skill 机制，但「任务清单」是硬编码的，用户够不到、加不了。

层现状路径
任务白名单TASKS 字典硬编码 3 个任务tools/ptools_harness.py:18-22
skill 文件每个任务对应一个 .mdresources/ai_skills/*.md
项目级覆盖同名文件放项目包 skills/ 覆盖resources/harness/projects/prpcar/skills/
用户自定义install_skill() 已能落盘，但无 UI 入口data/harness/skills/
加载优先级用户 → 项目 → 内置 → 兜底字符串harness_project.py:96-115
目标：把「写死 3 个」改成「配置清单驱动 + 可扩展 + 有 UI」。核心不是从零建 skill 机制，而是解耦任务注册 + 补 UI 入口 + 扩内置 skill 覆盖 NoSQL。

一三层 skill 结构（定稿）

层级作用路径优先级升级行为
内置 skill随 EXE 发布，通用能力resources/ai_skills/最低随打包覆盖
项目级 skill随项目包，业务方言定制resources/harness/projects/<id>/skills/中随项目包走
用户级 skill用户自建，跨项目通用/个人偏好data/harness/skills/最高升级不丢

三层加载优先级已由 harness_project.load_skill_text() 实现（用户 → 项目 → 内置 → 兜底），本次不改这套优先级，只补「任务注册清单」与「UI」。

二改造项①：任务注册从硬编码改为「配置清单驱动」

根因

ptools_harness.py 里 TASKS 字典把「任务名 → skill 文件名」写死，run_task() 遇到未注册任务直接抛「未知任务」。用户新增一个 .md 也不会被识别，必须改代码。

改法

  1. 新增清单文件 data/harness/skills.json（用户级，落 local_data_dir()，升级不丢）。结构： 
    {
  "tasks": [
    {"task": "sql.draft",    "file": "sql.md",         "title": "生成 SQL 草案",   "desc": "自然语言转 SQL"},
    {"task": "sql.optimize", "file": "sql_optimize.md","title": "优化 SQL",        "desc": "优化已有 SQL"},
    {"task": "linux.query",  "file": "log_query.md",   "title": "Linux 只读查询",  "desc": "自然语言转只读命令"},
    {"task": "mongo.query",  "file": "mongo_query.md", "title": "Mongo 查询",      "desc": "自然语言查 Mongo"},
    {"task": "redis.query",  "file": "redis_query.md", "title": "Redis 查询",      "desc": "自然语言查 Redis"}
  ]
}
  2. 新增读取函数（建议放 tools/harness_project.py，与现有 skill 加载同域）：
    • list_tasks()：合并「内置默认清单（代码常量）+ skills.json 用户覆盖」，同名 task 用户覆盖内置；返回 task 列表。
    • resolve_task_file(task)：返回该 task 对应的 skill 文件名。
  3. 改 ptools_harness.py 的 run_task()：用 resolve_task_file() 替代硬编码 TASKS 查表；未知任务仍抛「未知任务」，但来源变为清单而非代码常量。
安全边界（关键）：skills.json 只负责「任务名 ↔ skill 文件」的注册映射，不负责放开执行权限。真正的安全门禁仍在：
  • SQL 草案：ai_sql_draft.generate_sql_draft（evidence 空则 fail_closed 不调模型）
  • 写命令：sql_guard.classify_statement 的 REDIS_WRITE / SQL 写分类
  • Linux：linux_guard.inspect_commands 白名单
新增 skill 不得绕过这三层门禁。

三改造项②：内置 skill 扩到 SQL + Linux + NoSQL（3 → 5）

保留现有 3 个，新增 2 个 NoSQL skill，配合第三轮「数据中心」的 Redis/Mongo 改造。

task文件类型动作
sql.draftsql.md已有保留
sql.optimizesql_optimize.md已有保留
linux.querylog_query.md已有保留
mongo.querymongo_query.md新增自然语言 → Mongo 查询（只读，find 采样）
redis.queryredis_query.md新增自然语言 → Redis 只读命令（GET/HGETALL/SCAN 等）
新 skill 内容约束：mongo_query.md / redis_query.md 只需写「把自然语言转成对应只读查询/命令草案」的 system 提示词，不直接执行。执行仍走第三轮已定的 _run_mongo / _run_redis 只读分支 + 写命令门禁。

四改造项③：用户自定义 skill 的 UI 入口（放模型对话面板）

挂载点

模型对话面板 panels/model_chat_panel.py，现有结构：页头 → 工具栏（model_combo + ping_btn）→ 左栏会话列表 / 右栏对话区。

建议：在工具栏加一个「skill 管理」ghost 按钮，点击弹出 skill 管理对话框（不新起面板/导航）。

skill 管理对话框功能清单

功能说明底层
列表展示所有已注册 task（内置 + 用户），含 title/desc/来源（内置/用户）list_tasks()
新增选本地 .md，填 task 名 + title + desc，注册进清单install_skill() + 写 skills.json
删除删除用户级 skill（内置不可删，仅可停用）删 skills.json 条目 + 可选删 md
启用/停用切换 task 是否参与调度写 skills.json 的 enabled 字段
编辑改 title/desc（skill 内容本身用文本编辑 md）写 skills.json
升级不丢：所有用户级 skill 与清单都落 data/harness/（即 config.local_data_dir()），升级只替换 EXE，data/ 原地保留，用户自定义 skill 升级后依然在。

五开发边界总则（Grok 必读，违反即返工）

只允许改以下三处，其余一律不动：
  • ① 任务注册：tools/ptools_harness.py（去硬编码）+ tools/harness_project.py（新增 list_tasks / resolve_task_file）
  • ② 内置 skill：resources/ai_skills/ 新增 2 个 md
  • ③ UI：panels/model_chat_panel.py 加「skill 管理」入口 + 对话框

禁止改动：

  • harness_project.load_skill_text() 的三层加载优先级（保持用户→项目→内置→兜底）
  • 安全门禁：ai_sql_draft / sql_guard / linux_guard / tameng_agent
  • 连接建立与查询执行：db_connect.open_connection / _run_redis / _run_mongo / run_read_query
  • 凭据加密 secure_store、打包 requirements.txt / build_release.ps1
  • 不新起导航/面板/Stack 页（skill 管理用对话框，非独立页面）
  • 不把 skill 内容打进 resources/ 之外，用户 skill 只进 data/harness/

六验收标准（Grok 完成后自测）

#验收项预期
1内置 5 个 skill 全在清单，run_task 能识别sql.draft/sql.optimize/linux.query/mongo.query/redis.query 均可用
2用户新增一个 md → 注册后 run_task 可执行无需改代码
3删除用户 skill 后内置仍正常内置 task 不受影响
4停用某 skill 后调度跳过它enabled=false 不参与
5三层加载优先级未变用户 > 项目 > 内置 > 兜底
6安全门禁未被绕过sql_guard / linux_guard / ai_sql_draft 仍生效
7打包可过，用户 skill 不打包resources/ 不含用户 skill
8升级后用户 skill 保留data/harness/ 不被安装包覆盖

七非目标（本次不做）

  • 不做 skill 市场 / 在线下载 / 云端同步（产品无账号、无插件市场）。
  • 不做 skill 版本的依赖管理、自动更新。
  • 不做「任意函数调用」式 skill（skill 仍是提示词文本，不是可执行代码，安全门禁不变）。
  • 不做 frontmatter 解析（用 skills.json 清单注册，不解析 md 头部）。

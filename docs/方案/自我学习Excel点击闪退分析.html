自我学习：搜索后点击 Excel 列表闪退

排查时间：2026-07-28 · 影响模块：panels/personal_panel.py

问题描述

在“自我学习”中搜索内容后，点击列表里的 Excel 工作表条目，程序会闪退。

根因

Qt 对象生命周期冲突。Excel 详情重建时，_show_workbook() 调用 table_view.clear() 删除旧的 QTableWidgetItem；但搜索高亮缓存 _highlighted_cells 仍保存这些旧对象。随后 _filter_workbook_rows() 尝试恢复旧单元格背景色，访问已被 Qt 删除的底层 C++ 对象，导致进程崩溃。

关键调用链：列表 currentItemChanged → _show_entry → _show_workbook → table_view.clear → _filter_workbook_rows → 访问旧 _highlighted_cells。

复现步骤

  1. 打开“自我学习”，选择已导入的 Excel 工作表。
  2. 输入能命中表格行的关键字，使单元格进入高亮缓存。
  3. 点击列表中其他条目后，再点击该 Excel 条目，或在搜索结果中直接点击该 Excel 条目。
  4. 表格重建时旧单元格被清理，但缓存回写仍被执行，触发闪退。

拟实施的最小修复

  • 在清空/重建 Excel 表格前，先清空 _highlighted_cells，不再保留已失效的 Qt 单元格引用。
  • 补充回归测试：搜索命中 Excel → 切换列表项 → 再次进入 Excel，确认无异常且新表格高亮正常。
  • 运行自我学习相关定向测试并重新打包离线安装包。

该修复仅处理失效对象缓存，不改变搜索结果、Excel 展示或筛选逻辑。

自检与验证现状

  • 根因已由独立代码复核确认。
  • 现有全量 UI 测试存在 7 个历史/基线断言失败；其中 Excel 搜索测试也因当前搜索刷新时序与旧断言不一致失败，但未出现进程崩溃。
  • 本轮修复将增加覆盖实际闪退序列的专用回归测试，以崩溃场景为验收标准。

加解密布局与字段排序分析

目标：压缩解密参数区，扩大输入报文与解密结果阅读空间；格式化后的 JSON 字段统一按 A–Z 排序。

现状与关键发现

参数区固定 QFormLayout，当前上下边距 16/12、行距 10；Key 输入框高度为 72–110px。
报文工作区输入报文与解密结果使用横向分隔条，初始尺寸为 480 : 560。
字段顺序格式化文本和树形节点均沿用原始 JSON 输入顺序，尚未排序。

建议改动

1. 压缩参数区，不隐藏任何参数

  • 保留“解密参数始终可见”的既有安全与可用性约束，不做折叠或删除。
  • 将表单边距、行间距收紧；将 Key 输入框调整为约 56–80px，并压缩提示区间距。
  • 释放出的垂直高度由工作区的 stretch 吸收，因此输入报文与解密结果编辑器会同步增高。

2. 放大报文与解密结果

  • 把横向初始比例由 480 : 560 调整为更均衡的 1 : 1，两侧均获得更多默认宽度。
  • 仍保留拖动分隔条；窄屏沿用现有上下排列逻辑，单个编辑区最小高度不低于既有响应式下限。

3. 按 A–Z 排序格式化字段

  • 仅排序 JSON 对象（object）的字段名；数组（array）元素顺序严格保持原样。
  • 递归应用到所有嵌套对象，确保“格式化文本”“树形节点”“复制全部”“搜索路径”一致。
  • 排序遵循 JSON 字段名的 Unicode / A–Z 升序；数字、大小写或中文键将使用确定性字典序，而非业务自定义排序。

影响提示：格式化后的展示及复制文本会改变对象字段顺序，但 JSON 语义不变；数组顺序不变。若某些签名场景依赖原始报文字节序，仍应使用原始输入报文，不应对格式化文本重新签名。

首页“待升级事项”异常分析与修复方案

覆盖：从需求添加后不展示、移除导致闪退、卡片占满任务区。分析仅定位问题，尚未修改生产代码。

已确认的根因

展示缺陷

“从需求添加”没有真正加入看板

当前动作只会从 hidden_requirement_ids 移除 ID；页面刷新时仍要求需求“计划上线日期属于当前自然月”。未排期、下月排期或仅有上线月份的已选需求都会再次被过滤掉。

崩溃缺陷

移除按钮的 Qt 信号参数覆盖对象

行内回调写法为 lambda current=item: ...。按钮 clicked 会传入 checked: bool，覆盖 current；后续 item.get(...) 对布尔值调用，触发未处理异常。

布局缺陷

滚动区和父卡均允许扩张

待升级卡在任务行的交叉轴被拉伸，同时滚动区以 stretch=1 吃掉剩余高度，因此少量事项也会撑成整块大区域。

问题链路

从需求添加仅取消“隐藏 ID”
→
刷新看板按“本月 + 有日期”二次筛选
→
视觉结果已添加需求仍不展示

修复设计

问题修复方式数据/交互影响
添加后不展示在看板数据中新增 included_requirement_ids。从需求添加时写入该集合；看板渲染时，已选需求可跨越“本月/有计划日期”筛选，但仍排除已上线、已关闭、已取消、暂停等终态。已选即展示；需求台账和发版候选规则不变；老数据默认空集合兼容。
移除闪退所有行内 QAction / QPushButton 回调改为 lambda _checked=False, current=item: ...，显式吸收 Qt 的布尔参数，避免覆盖业务对象。仅修复回调参数绑定；移除仍只在首页隐藏，不删除需求。
卡片占满待升级卡设为固定工作区高度 276px；列表滚动区固定为 184px，显示约 4 条紧凑事项，超过部分滚动。父布局中取消它的纵向扩张能力。固定、可预期；事项再多也不推挤首页其他模块。
移除后的反向操作移除时从 included_requirement_ids 删除并写入 hidden_requirement_ids；再次“从需求添加”则移出隐藏、重新加入已选集合。状态闭环清晰，避免“加了看不见 / 移除又自动回来”。

固定尺寸效果预览

待升级事项　　发版联动　 从需求添加　 手工添加
需求标题 A　·　计划日期 / 未排期　　移除
需求标题 B　·　计划日期　　移除
手工事项 C　·　备注　　编辑 / 删除

固定 276px 卡片高度；列表超过约 4 条时仅在列表内滚动，不再拉长首页任务区。

定向验收

选择无计划上线日期的需求后，立即显示在待升级事项中。
选择下月计划需求后，仍作为“已选事项”显示。
点击“移除”后不抛异常、不退出程序、列表立即刷新。
再次从需求添加同一需求后，能恢复展示且不重复。
终态需求不因“已选”而重新出现。
少量事项时卡片高度固定；多项时仅列表内部滚动。

计划修改范围：tools/dashboard_release_items.py、panels/dashboard_panel.py、tests/test_interface_debug.py，以及首页卡片的局部布局/样式。不会改动需求台账、升级准备发版逻辑或已有用户数据字段。

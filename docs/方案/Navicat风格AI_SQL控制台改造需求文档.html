1. 背景、问题与目标

1.1 问题陈述

当前应用已具备多数据库连接、简化表字段查询和单一内网模型配置的基础，但并非面向日常 SQL 工作的专业控制台：对象层级混合展示时难以分辨表与字段；模型上下文选择不够直观；模型配置与通用对话能力也无法独立验证。用户需要在离线桌面应用中，以接近 Navicat 的工作流连接数据库、浏览结构、编辑并手动执行 SQL，同时利用内网大模型把自然语言可靠地转换为可审计 SQL 草案。

1.2 目标

  • 提供一套 SQL 控制台：连接、对象浏览、多 Tab 编辑、结果展示、危险操作确认均在同一桌面工作区完成。
  • 让用户能在 AI 输入区通过右键搜索当前库对象，先选表再选字段，以可见引用 Token 精确限定模型上下文。
  • 模型输出 SQL 草案和结构化生成说明，不展示或请求隐藏原始思维链，不自动执行。
  • 设置页可维护多个完整内网模型配置；新增独立“模型对话”页用于连续聊天与真实最小 ping 验证。
  • 对当前账号可见结构做全量元数据快照，减少每次请求扫描，并确保不把业务行数据、密码、Token 等敏感信息发给模型或写入日志。

1.3 非目标（本期不做）

  • 不引入浏览器内核、Monaco、WebSocket、外网模型、云同步、账号体系或插件市场。
  • 不实现 AI 自动执行、自动修复线上数据、自动提交事务或生产写入绕过。
  • 不把完整数据库、业务源码、结果集、抓包内容、密码、Token 或完整连接串上传到模型 Prompt。
  • 不把对象目录改造成字段混合树；字段不作为树子节点展示。
  • 不新增固定 AND/OR 规则控件；多字段条件含义由模型依据用户自然语言推断，并在生成说明中披露。

3. 信息架构与页面布局

SQL 控制台采用“对象目录 + 编辑与结果主区 + 右侧工作面板”的三栏布局。右侧工作面板采用 Tabs：AI 助手为默认页；选择对象时可切到对象详情查看字段元数据。这样既避免字段混入对象树，也不挤占 AI 生成工作流。
区域功能要求边界与交互
L1 页头标题“SQL 控制台”、当前连接别名、数据库类型、快照状态/时间；“新建 SQL Tab”为唯一主操作。不得显示 host、端口、用户名、密码或 Token。
L2 连接工具栏新建/编辑/删除连接、测试连接、扫描/更新结构、查看快照、删除快照、模型配置快捷入口。删除连接/快照必须走 confirm_action；未连接或无快照时禁用依赖动作并说明原因。
左侧对象目录仅展示：连接 → schema/数据库 → 表、视图、集合、Redis 键模式等对象。提供对象名/注释搜索及对象类型固定图标、标签。字段绝不进入树。对象目录仅用于浏览和手工 SQL 辅助；不作为 AI 表/字段选择主入口。对象同名时必须显示 OWNER.OBJECT_NAME。
中部编辑主区多标签 SQL/命令编辑器：新建、关闭、未保存标识、执行当前/选中语句、格式化、清空、保存本地草稿；下方结果区显示结果表、执行消息、受影响行数、耗时、分页与会话内历史。使用 PyQt 原生实现，不引入浏览器/Monaco。结果与执行历史默认仅内存，禁止将业务数据写入模型上下文或日志。
右侧 AI 助手支持自然语言输入、输入框右键添加对象、可见 Token、生成 SQL、结构化说明、查看已添加对象；成功后仅新建 AI 生成 Tab。AI 只生成；不得存在调用 _run_sql() 或任何数据库执行函数的自动路径。
右侧对象详情选择左侧对象后显示字段元数据表：字段名、类型、可空、主键/索引、注释；支持字段搜索、分页/虚拟列表和插入当前手工 SQL Tab。字段详情的“发送给 AI”（如保留）必须复用第 4.4 节同一套 Token 与上下文模型，不得另建 checkbox 上下文或绕过右键交互规则。

4. 核心功能需求

4.1 多数据库连接与全量结构快照（P0）

编号需求验收要点
DB-01复用 tools/db_connect.py 的 Oracle/MySQL/OceanBase/达梦/Redis/MongoDB 配置 CRUD 和 DPAPI/enc 凭据处理；所有新增数据经 config.local_data_dir() 保存。不新增 b64 明文密码；不得写入 resources/、_MEIPASS 或用户主目录。
DB-02为关系型数据库全量扫描当前账号可见的 schema、表、视图、字段、字段类型、可空、主键/索引、注释等元数据；支持进度、取消、完成/失败状态。无快照时显示真实空状态与“扫描/更新结构”入口，绝不伪造树；对象/字段量大时后台执行，不冻结 UI。
DB-03Redis 只保存数据库编号、键模式/类型/TTL 等安全元数据，严禁使用 KEYS *；Mongo 只保存 collection 与受控采样得到的字段形状/类型统计，禁止持久化 document value。快照不含行数据、键值、文档内容、密码、Token。
DB-04快照包含连接指纹、数据库方言、扫描时间、版本、状态和失效标记；连接关键字段修改后使对应快照过期。提供删除与重新扫描。连接指纹不得包含明文密码；无法证明属于当前连接的快照不得用于对象选择或 Prompt。

4.2 Oracle Thin/Thick 兼容（P0）

  • 新增 tools/oracle_runtime.py 或等价无界面模块，管理 auto / thin / thick、Instant Client 目录、目录诊断及进程级单次初始化。
  • Windows Thick 使用 oracledb.init_oracle_client(lib_dir=...)；不下载 Client、不修改系统 PATH、不重复初始化。模式/路径变化后明确提示重启应用再生效。
  • 对于 DPY-3010，以脱敏诊断说明 Oracle 11.2 或更早版本可能需 Thick 模式和可用 Instant Client；不得记录连接 ID、账号或连接串。

4.3 SQL 控制台执行与危险确认（P0）

  • 手工编辑器允许自由输入 SQL/命令；执行前根据方言和语句分类显示危险确认。确认框须明确连接别名、方言、操作类型、风险说明和取消默认焦点。
  • 增强 tools/sql_guard.py：识别多语句、WITH ... INSERT/UPDATE/DELETE、DDL/DCL/PLSQL、Redis 写命令、Mongo 写操作。手工执行与 AI 草案校验必须分开实现。
  • 静态分析无法可靠判断安全范围的复杂 AI SQL，必须 fail closed：可生成、可查看，但标为“仅草案 / 不可安全执行”，不得通过任何快捷路径直接执行。
  • 会话连接必须 per-tab，禁止全局 disconnect；执行、断开、取消等操作只能影响当前 Tab 所属连接。

4.4 AI 自然语言对象选择：右键主入口（P0）

最终规则：AI 自然语言输入框右键菜单是选择表/字段上下文的唯一主入口。对象目录只用于浏览和手工 SQL 辅助；若对象详情保留“发送给 AI”，也只能打开/调用同一右键选择模型，最终写入同一种 Token 和同一个 model_context。
编号需求详细交互与边界
AI-OBJ-01输入组件与右键菜单将现有 QLineEdit 替换为 QTextEdit、受控富文本组件或等效自定义输入组件。右键菜单至少有“添加表… / 添加字段… / 查看已添加对象 / 清除本次已添加对象”。保留普通输入、复制、粘贴、撤销等合理编辑能力。
AI-OBJ-02添加表弹窗基于当前连接且状态有效的本地快照，支持搜索并选择表、视图、集合或适配 Redis 的键模式；列表展示对象类型、schema/数据库、限定名和注释。确认后在右键触发时的光标位置插入“表 Token”。允许同一次添加多个对象，但重复选择同一限定对象只保留一个 Token。
AI-OBJ-03添加字段两步弹窗第一步必须先搜索并选择一个当前快照中的对象；第二步才加载该对象字段列表并支持字段名/注释搜索、类型展示与多选。确认后插入属于该对象的“字段 Token”。未选择表时“下一步/确认字段”不可用；不得让用户从所有库字段的混合列表中直接检索。
AI-OBJ-04Token 显示、删除与回填Token 必须肉眼可区分普通文本，显示如“表：PRPCMAIN”“字段：PRPCMAIN.SUM_PREMIUM”，支持悬浮/点击查看限定名、类型、快照时间等元信息，支持选中后退格或删除按钮移除。不得把不可见 JSON、HTML 注释或伪 SQL 标识隐藏进用户文本。用户编辑普通文本时不得丢失 Token；删除 Token 时同步从上下文移除。
AI-OBJ-05上下文数据模型每个输入会话维护独立 model_context，至少含 snapshot_id、connection_fingerprint、selected_objects、selected_fields、token_id、限定名、对象/字段类型。Token 视觉状态与上下文模型一一对应，不通过从普通文本反向猜测对象。
AI-OBJ-06失效与异常状态未选择连接、未扫描快照、连接指纹不匹配、快照已过期、对象已不存在、字段加载失败时，禁用“添加表/添加字段”并展示原因与“扫描/更新结构”入口。不得使用上一次连接、其他库或过期快照中的对象回填。
AI-OBJ-07光标位置保护确认后优先插入右键触发时记录的光标位置；若弹窗期间输入框失焦、文本已变化或位置不可恢复，则插入当前光标末尾并给出轻提示。任何情况下不得覆盖用户已输入的自然语言。
AI-OBJ-08方言边界关系型库的字段来自真实字段快照。Mongo 字段仅在受控 schema 快照可用时允许选择，标记为“推断字段”；Redis 以键模式/命令上下文为主，不伪造表字段，字段动作应禁用并解释原因。
用户在 AI 输入框编写普通自然语言 └─ 右键添加表 / 添加字段 ├─ 校验当前连接 + 有效快照 ├─ 添加表：搜索对象 → 插入对象 Token └─ 添加字段：搜索对象 → 选择字段（多选）→ 插入字段 Token ↓ 受控 model_context（仅本次输入会话） ↓ 方言 + 已选对象/字段元数据 + 普通自然语言 ↓ 结构化生成说明 + SQL 草案 ↓ 新建“AI 生成”Tab（绝不执行）

4.5 AI Prompt、结构化输出与草案写入（P0）

  • Prompt 仅发送：方言、经裁剪的当前有效快照元数据、Token 对应的限定对象/字段、用户显式自然语言。禁止上传密码、Token、host、端口、用户名、完整连接串、业务行数据、结果集、抓包内容。
  • 如果用户添加了字段，生成 SQL 不得引用未选择的业务字段（允许 COUNT(*)）；如因主键、关联键或方言要求必须使用额外字段，必须在 warnings 说明，且标为需用户复核。
  • 用户添加多个表/集合但未提供关联条件时，必须输出 join_assumptions 与警告；SQL 仅为草案，不得成为“可安全执行”状态。
  • 修改 resources/ai_skills/sql.md 与 tools/ptools_harness.py：SQL 任务必须要求单条草案或受控结构化 JSON，禁止旧规则“多语句用分号分隔”。对模型输出做严格 JSON 校验、字段默认值补齐和 SQL fence 清理。
结构化输出契约（仅展示可审计摘要，不是隐藏思维链）： { "summary": "", "intent": "", "objects_used": ["SCHEMA.TABLE"], "selected_fields": ["SCHEMA.TABLE.COLUMN"], "condition_interpretation": "", "join_assumptions": [""], "risk_level": "read|write|ddl|unknown", "warnings": [""], "sql": "" }

5.1 设置页多完整模型配置（P0）

编号需求交互与边界

MC-SET-03内网安全每次模型请求前用 socket.getaddrinfo 解析主机名，所有解析 IP 必须是 loopback、RFC1918 或允许的 link-local；拒绝已知公网模型域名；使用 ProxyHandler({}) 绕过系统代理。Token 继续 DPAPI/enc 存储。

5.2 新增 nav 15「模型对话」（P0）

编号需求交互与边界
CHAT-01会话管理左侧会话按更新时间倒序；支持新建、重命名、删除、关键词搜索。首条消息成功后可用前 20 个字符生成默认标题；手工名称不得被覆盖。
CHAT-02连续聊天中部气泡流展示用户与助手消息；助手消息显示“配置名称 · 模型名 · 完成时间”。可复制消息、重新生成最近一条、停止当前生成。上下文最多 30 条或 12,000 字符，超限仅裁剪发送上下文，不删除本地完整记录。
CHAT-03模型切换与测试顶部只显示启用配置；切换仅影响后续消息。测试当前模型应发送真实最小 ping、显示成功/失败和耗时，但绝不创建会话消息。配置删除/停用后，历史会话可查看但不能继续发送，直到选择有效配置。
CHAT-04本地明文持久化会话 JSON 保存在 data 目录，原子写入；首次进入与页面常驻提示“聊天记录明文保存在本机，请勿输入密码、Token、客户隐私、生产敏感数据或抓包报文”。记录只含会话元信息、用户/助手文本、配置 ID 与模型名。

7. 非功能与安全要求

  • 依赖方向：严格保持 run → main_window → panels → tools|ui|config；tools 不 import panels，ui 不 import panels/tools。
  • 数据根：所有新增文件均在 config.local_data_dir()；升级不得覆盖安装目录 data；安装包不得包含用户 data。
  • 隐私：连接密码和模型 Token 继续用 DPAPI/enc；聊天明文保存是用户明确决策，但聊天页必须提示风险。接口排查、网关解密、数据库结果、模型 Prompt 均不得落入普通日志。
  • 性能：全量扫描和大字段列表必须后台化；字段超过 100 使用搜索 + 分页/虚拟列表；取消、异常、成功三条路径都结束 Loading。
  • 兼容：保留旧 ai_local.json、已有连接配置和既有 AI 工作台未提交功能的兼容迁移；读取 JSON 使用默认值兼容旧字段，写入保留已知旧字段。
  • UI：遵循现有 resources/style.qss、PageChrome、四层页面骨架与主题 Token；禁止临时硬编码破坏现有主题。

8. 验收标准与定向测试

8.1 功能验收清单

  • 导航显示 nav 14“SQL 控制台”、nav 15“模型对话”；Stack、侧栏、状态栏、中英文、快捷入口和懒加载映射正确。
  • SQL 控制台对象目录仅显示对象，不显示字段子节点；对象详情展示字段元数据；无快照时显示空状态。
  • AI 输入区右键显示“添加表 / 添加字段 / 查看已添加对象 / 清除本次已添加对象”。
  • 添加表只能搜索当前连接、当前有效快照中的对象；不同 schema 同名对象可区分；重复对象不会重复插入。
  • 添加字段必须经历“先选表、后多选字段”两步；未选表不得确认字段；Redis 禁止伪字段选择。
  • Token 可见、可查看元信息、可删除；删除后上下文同步移除；编辑普通文本不破坏 Token；弹窗回填不覆盖用户文本。
  • 快照过期、连接切换、对象不存在或字段加载失败时，禁用对象选择并提供明确提示和扫描入口。
  • AI Prompt 只使用当前有效 Token 对应对象/字段及裁剪快照；选字段后不引用未选业务字段；多表无关联条件时输出 Join 假设与警告。
  • AI 输出创建新的“AI 生成”Tab，任何生成路径均不自动执行；复杂或无法静态判断的草案 fail closed。
  • 手工 DML/DDL/DCL/PLSQL/Redis/Mongo 写操作均有危险确认；连接按 Tab 隔离。
  • 多模型配置可新增、复制、编辑、删除、设默认、真实 ping；旧单条配置自动迁移且原 token 可继续使用。
  • Oracle DPY-3010 有 Thick 模式、Instant Client 目录诊断与重启提示；不改变系统 PATH。
  • 模型对话支持新建/重命名/删除/搜索/连续消息/模型切换/真实 ping；明文 JSON 提示和数据边界符合本需求。

9. 实施风险与处理原则

风险处理原则
富文本 Token 破坏普通文本编辑采用受控输入组件和独立 model_context 映射；Token 不通过隐藏文本序列化表达；增加删除、撤销、回填和焦点丢失测试。
旧对象树和新设计冲突字段不进入树为强制规则；对象详情承载字段浏览；AI 选择一律以右键 Token 流为准。
快照/连接串联错误以 connection fingerprint + snapshot_id 双重校验；失效或不匹配时 fail closed，禁止回填和生成。
模型返回非结构化内容严格解析和默认字段补齐；无法验证时显示“生成失败/仅原始草案待复核”，不自动执行。
复杂 SQL 静态分析误判AI 草案只生成；无法证明安全时不提供安全执行状态。手工执行仍由用户危险确认承担明确操作意图。
现有未提交代码冲突先查看 diff，采取兼容重构，保留现有表/字段选择能力中可复用部分；不得粗暴覆盖文件。

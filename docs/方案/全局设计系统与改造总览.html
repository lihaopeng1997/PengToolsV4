全局设计系统与全模块改造总览

面向运维与技术人员的离线工作台设计基线。以缩短排障路径、降低误操作、保持敏感数据边界为目标，统一所有模块的导航、主题、密度、组件、状态反馈与桌面响应策略。

设计原则与全局框架

整体定位为“问题处理驾驶舱”：用户进入任意模块后，都能持续知道自己在哪个环境、面对什么对象、下一步可做什么，以及哪些操作会有风险。

任务优先

首页、工具中心与全局搜索引导用户从目标任务进入，而不是记忆导航层级。

结果优先

日志、响应、终端和格式化结果默认获得最大阅读空间，配置按需收纳。

风险显式

生产、删除、清理、覆盖、代理恢复和 SVN 操作均显示对象、范围与确认。

边界稳定

保持离线产品范围与现有敏感数据约束，不因 UI 统一引入网络、遥测或落盘风险。

稳定导航

左侧导航按工作任务排序：工作台、接口排查、日志排查、SSH/运维、发布准备、工具中心、需求管理、日报/学习、设置。只有“自我学习”保留原有彩蛋隐藏机制；日报、需求、格式工具和接口排查保持常显。

统一工作面

定位型页面采用“左侧范围/筛选 + 右侧详情/结果”；编辑型页面采用“顶部上下文与主操作 + 中部编辑 + 下部或右侧结果”；多标签终端和接口排查保留可拖拽分栏，并优先保障结果阅读。

视觉 Token 与主题策略

默认浅色，支持跟随系统与手动深色覆盖；主题切换不仅变背景，还必须同步表面层级、边框、正文、代码/日志和状态色。

组件与交互规范

按钮层级

每个工作面仅一个主操作，例如“发送测试”“开始抓包”“生成发布材料”。次要操作用中性描边；删除与清理用危险色描边。按钮文字禁止换行、缩写或截断。

搜索、筛选与列表

搜索靠近结果列表；筛选条件即时生效，复杂条件收进弹窗/抽屉。列表行显示核心判断信息，并支持双击打开、右键处理低频动作。

详情与编辑

详情用可收起分区；编辑前保留当前对象上下文；长 Headers、Params、Body、响应、日志与终端输出支持可拖拽区域和复制/格式化。

状态反馈

统一使用“处理中、通过、需确认、阻断/失败”四级状态；颜色、图标和文字共同表达。无命中属于成功结果，不标为错误。

加载与异常

加载采用不占布局的浮层；成功、失败、取消和异常均必须结束加载。失败保留输入与选择，并提供可定位的错误说明和重试入口。

危险操作

删除、清空、回滚、恢复代理、覆盖输出等操作展示影响对象与范围，二次确认，默认焦点落在“取消”。不可用状态要说明原因，不只置灰。

布局、密度与响应式

信息密度

  • 紧凑（默认）表格/列表行 32px，工具条控件 32px，适合高频排障。
  • 舒适列表行 40px，控件 36px，增加阅读留白。
  • 用户偏好写入设置；当前页面可临时覆盖。终端字号与日志行距独立保存，避免全局密度影响排查阅读。

桌面断点

  • ≥1280px：完整左栏 + 主区 + 可选右侧上下文栏；三栏工具页保持可拖拽。
  • 1024–1279px：左栏压缩至图标/约 280px，右侧辅助栏改为抽屉或收起。
  • <1024px：不压缩日志/响应/终端正文；优先隐藏或抽屉化导航、资源栏和辅助栏。
可记忆性：可拖拽分隔条、当前密度、主题、展开分区和近期非敏感工作项可按既有本地数据策略保存；敏感正文、令牌、明文和密钥不可作为 UI 偏好或历史存储。

全模块功能调整总览

模块最终界面方向必须保持的业务边界
工作台首页继续处理、异常/任务汇总、四个快捷排障入口、真实环境状态。真实数据来源未就绪时不展示虚构状态；保留现有需求与升级跳转。
接口排查抓包与会话定位左栏、诊断/请求/响应/测试右栏；测试编辑与响应可上下拖拽。会话敏感数据只留内存；代理仅 loopback；停止保留会话；清空/退出才清会话。
SSH 与终端服务器/服务定位、最多 4 个独立标签、终端为主工作面、命令库与操作记录辅助。连接 per-tab；密码加密；断开只影响当前标签；PTY 与退格兼容、流式导出规则保持。
日志排查按服务器—服务—文件—关键词的连续定位；结果优先、异常摘要和终端联动。关键词 AND 规则、具体 .log resolve、无远端临时文件、导出限制与命名规则保持。
发布与环境需求范围—分系统 SQL—预检—生成材料；系统配置列表化。日期格式、有效系统、无 SQL 确认、SQL 归属和 23 列 Excel 表头规则保持；不新增远程发布。
工具与辅助任务型工具中心，统一列表/详情/编辑/确认，跨模块采用“发送至”。格式工具不执行 SQL；网关解密内存态；敏感信息不进搜索/收藏/历史；需求 SVN 能力保留。

安全、数据与可访问性底线

敏感数据限制：网关密钥、密文/明文、抓包 Authorization/Cookie/Token、真实证件号、工作簿密码、SSH 明文密码和含凭据的知识内容不得写入日志、搜索索引、收藏、最近记录或 UI 偏好。密码存储继续遵从既有 DPAPI/加密规则，禁止新增 b64 明文方案。
键盘与焦点

全部关键操作可键盘完成；焦点可见且顺序符合阅读逻辑；弹窗打开后焦点进入弹窗，关闭后返回触发控件。

文本与触控

正文最小 13px，终端/日志可独立调字号；交互目标至少 44px；不只依赖颜色表达成功、警告和失败。

动效与性能

只对状态变化使用 150–250ms 过渡；尊重减少动效偏好；加载不阻塞页面布局，避免大面积重绘和复杂视觉效果。

实施顺序与验收

第一阶段

建立 QSS token、主题、密度、全局导航、通用按钮/表单/状态/弹窗组件。

第二阶段

实现接口排查、SSH 与日志三条核心排障工作流，逐模块定向测试。

第三阶段

落地工作台首页、发布准备、工具中心与辅助模块的统一布局和跳转。

第四阶段

整体验收、敏感数据回归、打包离线安装包、核对构建信息与用户验收。

代码改造前提：本轮完成的是全量 UI 设计与功能调整说明，尚未修改业务代码。进入开发时应按阶段提交：先说明修改文件、影响范围、预期效果与验证方式，得到明确确认后再实施；每次可验收迭代后按项目规则执行定向测试和离线打包。

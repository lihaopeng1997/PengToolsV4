2. 发现的问题与整改项

优先级问题与证据潜在影响具体整改事项
P1

紧凑操作按钮会被全局密度规则反向放大

style.qss:2136-2155 对所有 QPushButton 强制 32/36px；而紧凑按钮本应由 size_compact_button() 固定为 28px。真实 Qt 验证：加入主窗并设置 compact 后由 28px 变为 42px，comfortable 后变为 46px。		“整体软化”叠加密度设置后，列表工具栏、日志排查行内操作重新变大，直接抵消近期紧凑化体验，且会挤占信息展示空间。在密度选择器中排除 [compactAction="true"]，或在密度规则之后声明同等特异性的 28px 覆盖。补“主窗口 + compact/comfortable + compactAction”集成测试，不能只测孤立按钮。
P1

柔和主题的关键文本/主按钮未满足 WCAG AA 普通文本对比度

实测：calm 主色/白字 3.76:1、warm 3.81:1；calm/clear/warm 的弱提示文字分别为 3.86/3.91/4.10:1，均低于 4.5:1。位置：theme_manager.py:79-228。		低亮度显示器、投屏、长时间办公或视觉敏感用户下，主按钮文字、辅助说明和状态信息可读性不足；“软化”容易变成“发灰”。保留柔和背景，但把 calm/warm 主色加深，或为主按钮使用更深的 ON_PRIMARY；将 TEXT_MUTED 调深并区分“说明”和“禁用”。新增所有主题的 WCAG 对比度测试：正文、辅助文本、主按钮、语义状态四组。
P1

主题切换不是原子事务，失败被静默吞掉

settings_panel.py:405-418 先执行 ThemeManager.apply(None,...) 并吞掉异常，随后 _save() 写入设置；main_window.py:700-709 再次应用失败时只拼接旧 QSS。config.py:226-231 也非原子写入。		QSS/资源异常时，用户可能看到“当前卡片已切换”、配置已保存，但实际界面仍是旧主题或仅字体变化；重启后状态再次变化，难定位且没有错误反馈。将切换收敛为主窗口唯一命令：先渲染和应用成功，再原子写入临时文件后替换；失败时回滚主题/卡片选中态并给出可读提示。移除设置页的预先 apply(None)，防止一次点击双重应用/双重通知。
P2

局部手工着色内容不会随主题即时重绘

只有日志终端注册了监听：ops_log_panel.py:1043,3851。需求树、Excel 预览、接口会话会在填充时调用 setForeground/setBackground，但没有统一主题刷新；例如 personal_panel.py:607-649、requirement_panel.py:1736-1803、interface_debug_panel.py:2252-2280。		切到夜间或暖色主题后，已展示的搜索高亮、月份行、状态字体可能保留上一个主题的颜色，产生“页面已换肤、局部仍旧色”的割裂。建立 theme_changed 统一刷新协议：可重新填充的数据视图调用现有 render/fill；不能重建的数据用 Token 重设 brush。禁止新代码直接使用颜色字面量，局部绘制都从 ThemeManager 取 Token。
P2

图标主题刷新覆盖不完整，部分图标使用导入时的默认色

ui/icons.py:165-180 的 qicon() 默认参数在模块导入时绑定 calm 色；format_panel.py:525-528 创建 Tab 图标后无主题监听。禁用图标仍固定 #A8B1C2。		主题切换后导航类图标可刷新，但格式工具 Tab、部分编辑器/弹窗图标可能继续保持静谧办公色，夜间主题尤为明显。把 qicon 的 normal/active 改为运行时解析 None；为 Tab/常驻图标容器注册刷新方法；禁用色纳入 DISABLED_ICON Token。
P2

颜色来源仍有两套：ThemeManager 与 layout_metrics 常量

layout_metrics.py:60-80 保留 calm 固定色，design_system.py:15-31、page_chrome.py:50-63、icons.py:15 仍导入它们。		新增组件若沿用这些常量，将在非 calm 主题回退为绿灰色；长期会重新积累“局部不软化/不换肤”的设计债。将 layout_metrics 限制为几何常量，颜色只保留兼容别名或移除；创建 theme_token() 统一入口。增加静态检查：生产 UI 代码新增 HEX 必须有白名单说明。
P2

主题回调异常被无声忽略，性能与视觉失败不可观测

theme_manager.py:458-462 对 listener 捕获所有异常后忽略。每次切换还会渲染约 58.8KB QSS、清空图标缓存、全局 setStyleSheet；设置页一次点击可触发两轮 apply。		监听者失效后没有诊断入口；未来主题监听增多时会造成切换卡顿或局部未刷新但难以复现。保留“单个监听不阻断全局”的策略，但记录开发日志/状态摘要；去掉重复 apply 后测试 20 次连续切换的耗时、内存与监听数量稳定性。
P3

DPI、字体与超大字号的跨设备验证不足

run.py:41-42 仍设置旧环境变量；多处固定 px/pt 与 Windows 字体依赖（如 ssh_terminal.py:169-174）。设置允许 10-18px，但主题测试未覆盖 125%/150% 缩放、字体缺失、18px 与窄屏组合。		高 DPI/多屏、精简 Windows 字体环境下可能产生控件裁切、按钮溢出或行高不一致。以 Qt6 原生高 DPI 行为为主，验证 100/125/150% 三档；覆盖默认字体缺失、18px、窄屏与 comfortable 密度的截图/布局断言。
P3

完整主题测试模块同进程执行异常退出

单项及核心组均通过，但一次性执行 tests.test_theme_responsive tests.test_theme_format_tools 在第一个按钮测试处以退出码 127 结束、无 Python traceback。		当前无法依赖完整主题回归作为发布门禁；可能隐藏 Qt 生命周期、全局单例或进程环境交叉污染问题。作为测试基础设施缺陷单独复现：启用 faulthandler，二分缩小到具体测试组合，确保每个 QWidget 关闭/清理并重置 ThemeManager 单例。修复前将已通过的核心组与失败命令同时记录，禁止误报“全量通过”。

3. 推荐整改顺序

第一批：保护当前体验

  1. 修正密度规则对 28px 紧凑按钮的覆盖。
  2. 调整 calm/warm/clear 对比度并加自动测试。
  3. 主题切换改为“应用成功后再保存”的单一事务。

第二批：消除视觉割裂

  1. 统一主题刷新通知，覆盖手工 brush、Tab 与常驻图标。
  2. 清理 layout_metrics 色彩常量与硬编码回退。
  3. 增加连续切换性能、DPI、字体和测试进程隔离验证。

4. 已验证的正向能力与残余风险

已验证：所有四套主题的 QSS 渲染无未替换 Token；实际连续切换成功；夜间主题表面层级、非纯白约束、预览可见性、徽章图标差异等 13 项核心回归均通过。
仍需人工验收：真实 Windows 桌面 100%/125%/150% 缩放下的四主题切换；已打开 SSH 终端、Excel 预览、需求树、接口会话后再切换主题；紧凑/舒适密度下的工具栏高度与长中文文案。

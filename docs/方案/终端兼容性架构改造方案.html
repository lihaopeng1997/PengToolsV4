日志排查终端兼容性架构改造方案

目标：保留“每标签独立服务器会话”，同时恢复命令输入、退格、Delete、Tab、方向键等完整交互。

参考结论

FinalShell / MobaXterm 不能直接拷贝源码

已核验 FinalShell 的公开 GitHub 仓库是 Flatpak 分发配置，未包含终端核心源码；其元数据还标注为专有软件。MobaXterm 同样不是可直接复用的开源终端代码。可以参考的是它们共同采用的设计原则：一个标签对应一个独立 SSH 连接与 PTY 通道，UI 状态只在通道真正就绪后开放交互。

已确认的现状

按键映射本身可用

  • 现有实现已将输入、Backspace、Delete、回车、Tab、方向键映射为标准 xterm 控制序列。
  • 本地模拟通道已验证这些按键会进入 PTY 的发送方法。
  • 多服务器会话选择逻辑已按当前标签隔离，不能回退为“总连接第一台服务器”。
根因

连接成功与终端就绪被混为一谈

SSH 目录连接成功后，界面会先将标签标为已连接并启用终端；但 invoke_shell() 若失败或通道随后关闭，界面仍可能可编辑，造成“看起来能输入、实际没有存活 PTY”的假连接状态。

拟采用的会话模型

按成熟终端工具的通道状态机收口

SSH 已连接
可浏览远端目录
→
PTY 启动中
终端禁用、显示状态
→
终端就绪
允许键盘输入
→
已关闭 / 失败
释放本标签资源并提示

目录浏览与 PTY 交互分层：SSH 可用但 PTY 失败时，目录功能仍能按实际连接状态使用；终端区域明确显示“终端未就绪”，绝不吞键或伪装可输入。

最小改动

实施范围

文件调整效果
tools/ops_ssh_shell.py让 PTY 启动、存活和关闭状态可明确返回，发送失败可被上层识别。避免把未启动/已关闭的通道当作可交互终端。
ui/ssh_terminal.py只在 PTY 创建成功后进入可输入状态；通道关闭时立即禁用交互并保留错误说明。输入、退格、Delete 等按键始终只发送到当前标签的活跃通道。
panels/ops_log_panel.py连接流程先完成当前标签的 PTY 就绪校验，再启用终端相关控制；失败时只释放当前标签。保持多服务器、多标签隔离，不影响其他标签的会话。
tests/test_ops_ssh.py补 PTY 启动失败、关闭后禁用输入、键盘序列与多标签资源隔离回归测试。防止“连对服务器但终端假连接”再次出现。
验收标准
  • ✓ 每个标签只操作自己的 SSH Client 与 PTY。
  • ✓ 输入、Backspace、Delete、Tab、回车、方向键发送到当前活跃 PTY。
  • ✓ PTY 启动失败或关闭后，终端立即不可输入且给出明确提示；不会影响目录浏览或其他标签。
  • ✓ 定向测试、敏感信息扫描、离线安装包构建均通过。

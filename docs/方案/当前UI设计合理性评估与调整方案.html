四、需要调整的问题清单

P0 一致性（最关键）

#问题表现影响面
1 页面骨架不一致 「升级准备」页直接 Tab 起，缺 PageChrome 标题区 用户切换页面时缺少"定位锚点"
2 主操作按钮位置分裂 需求管理=右上"新建需求"、接口排查=右上"本地"状态点、日志排查=右上"连接本会话"、升级准备=内右"升级上下文"、证件/VIN=内右"生成"、模型工作台=内左"填入问句"、接口文档=内右"一键更新" 同类操作在不同页面要重新找
3 顶部工具栏概念混乱 需求管理"扫描/检出/更新/登记/导入/配置"6 按钮 vs 模型工作台"新建/删除/测试/同步"4 按钮 vs 升级准备"刷新/全选/取消/已截"4 按钮 + 升级上下文，控件条/工具栏/筛选条三种形态并存 用户无法建立心智模型
4 筛选条控件种类不一 需求管理=搜索+3 下拉；接口排查=搜索+列设置；命令库=搜索+分类下拉+新建按钮；模型工作台=连接下拉+4 操作按钮；升级准备=日期+操作组 同一类功能（筛选/搜索）视觉差异大

P1 视觉细节

#问题表现
5 图标按钮过多无文字 需求管理文件库工具栏 8 个图标按钮（打开/刷新/更新/添加/新建/锁定/解锁/回滚）
6 折叠操作分散 需求管理："一键搞定/全部展开/全部折叠"在左侧树工具栏，但"全部展开/全部折叠"又在搜索条右侧重复
7 空状态视觉友好度 证件类型 12 列空表 / 需求管理文件库空表 / 接口排查列表空 / 命令库右侧空，缺少引导文案或插画
8 模型工作台「只生成」按钮 右上角孤立放置，与左侧主操作"填入问句"同色调但语义不同；建议改为次要色 ghost 按钮
9 升级准备「升级上下文」按钮 右上角与下方面板位置割裂，应改为右侧主操作位或顶部 PageChrome 槽位
10 日志排查按钮分组 终端顶部"生成查询/历史/发送" + 右上"智能终端/清屏/新终端"两组按钮视觉重叠，应分层

方向 B：主操作收口到 PageChrome 右上

现状（操作散落 6 个位置）

  • 右上：需求管理 = 新建需求
  • 内右：证件 = 生成 / VIN = 生成 / 升级准备 = 升级上下文
  • 内左：模型工作台 = 填入问句
  • 内右：接口文档 = 一键更新文档
  • 右下：日报 = 保存日报

建议（统一到 PageChrome 主操作位）

  • PageChrome.primary_actions：本页面唯一的主操作（如「生成」「新建」「保存」「连接本会话」「执行查询」）
  • PageChrome.secondary_actions：次要操作（如「导出 CSV」「复制安全 URL」「导入资料」）
  • 内嵌工具栏：仅承载批量操作（多选 + 批量执行），不再放主操作

方向 C：三层控件分层（页面骨架 → 工具栏 → 筛选条）

层职责允许的控件
L1 页面骨架（PageChrome） 标题 / 副标题 / 主操作 / 次要操作 1 个主按钮 + ≤2 个次要按钮 + 可选状态点
L2 工具栏（page-toolbar） 本页面的批量操作 / Tab 切换 / 视图模式 操作按钮组（按语义分组，组间加间距）+ Tab 控件
L3 筛选条（page-filter-bar） 搜索 / 筛选 / 排序 / 计数反馈 搜索框 + 下拉 + 计数；不再混入操作按钮

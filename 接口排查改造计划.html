确认结论

整体设计方向已确认：保留现有核心能力，仅重构信息架构、控件层级和操作路径；后续代码改动将在取得明确授权后执行。

最终工作流

开始抓包→搜索与筛选定位→概览/请求/响应诊断→请求测试复现→导出或保存接口

功能布局与调整说明

左侧：采集与定位抓包状态、URL 搜索、XHR/失败/慢请求筛选、导出、清空及高密度会话列表。开始/停止合并成一个状态按钮，保留测试连接与恢复系统代理。
右侧：诊断与复测固定请求摘要 + 概览、请求、响应、请求测试四标签。请求与响应内容占据主要阅读面积，不压缩长 JSON。
请求测试：空间优先Headers、Params、Body 与响应 Body 改用上下可拖动分隔条；默认响应区域更大，便于排查返回内容。
配置：主界面减负环境增删改收拢至“环境配置”弹窗；URL 前缀改用“过滤配置”弹窗，以多规则列表维护。
接口库与历史：列表更干净移除“加载所选”“复制并重发”常驻按钮。接口库双击回填；历史 URL 右键可填充、复制、生成 cURL、保存接口库、删除单条。
历史清理：避免误删以“历史清理配置”入口处理全部、7 天前或当前搜索结果；先展示影响条数，再确认删除，默认焦点为取消。

实施边界

保持不变调整方式验收重点
抓包、代理恢复、CDP/IE 代理逻辑仅调整界面入口和状态呈现停止抓包不清会话；退出才清内存会话
请求测试 Base 重写与 HTTPS 默认校验保留原有安全逻辑路径/query 不丢失，默认开启证书校验
敏感会话数据不写入任何 UI 偏好或配置配置文件不出现 Authorization、Cookie、Token、正文
既有字段与工具能力全部保留，仅重排位置/入口Headers、Params、Body、导入导出、复制格式化均可用

实施顺序

  1. 配置与分隔条偏好兼容测试。
  2. 顶层双栏工作台和单一抓包状态按钮。
  3. 概览、请求、响应详情的阅读层级。
  4. 请求测试编辑/响应纵向可拖拽布局。
  5. 环境配置与过滤配置弹窗。
  6. 接口库/历史右键操作与历史清理配置。
  7. 桌面自适应、明暗主题、无障碍与离线打包验收。

每一阶段均配套定向测试；最终执行离线构建并核对安装产物。

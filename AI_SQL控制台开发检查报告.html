3. Critical：必须修复后才能验收

C-01 旧 Token 可被新连接/新快照重绑，未 fail closed

位置panels/ai_token_edit.py:51-54；panels/ai_workbench_panel.py:1148、1233；tools/ai_object_context.py:38-55
问题bind_snapshot() 直接覆盖现有 model_context.snapshot_id 与 connection_fingerprint，但不清空或重新验证已存在 Token。之后 context_matches_snapshot() 只对比已被覆盖的标识，会误判为一致。
复现在连接 A 添加表/字段 Token → 切换到连接 B 或重扫快照 → 调用 bind_snapshot(B) → 旧 Token 继续参与 B 的 Prompt。
违反需求违反 AI-OBJ-05、AI-OBJ-06 和第 9 节“connection fingerprint + snapshot_id 双重校验、失效 fail closed”。
最小修复禁止 bind_snapshot() 覆写已有 Token 的身份。连接指纹/快照 ID 变化时清除可见 Token 与 selected_objects/selected_fields，新建上下文并提示“连接/快照已变化，请重新添加对象”；生成前逐一验证 Token 的限定对象、字段和类型仍精确存在于当前快照。

C-02 单独选字段会丢失父表限定关系，同名字段的其他对象被发给模型

位置tools/ai_object_context.py:80-123；tools/schema_snapshot.py:401-434；tools/ai_sql_draft.py:92-108
问题字段 Token 内虽记录 object_qualified_name，但 Prompt 构建仅使用裸字段名和裸表名。只选字段时，父对象 Token 不可见，会被 keep_tokens() 清掉；随后 selected_fields=['ID']、selected_tables=[]，裁剪逻辑会将所有包含 ID 的对象都加入 Prompt。
独立复现结果选择 S1.ORDERS.ID 后，使用含 S2.ORDERS.ID、S3.AUDIT.ID 的快照构造 Prompt，实际输出同时包含 S2.ORDERS(ID) 和 S3.AUDIT(ID)。
违反需求违反 AI-OBJ-03、AI-OBJ-05、4.5 节“Prompt 只能发送 Token 对应对象/字段”。
最小修复内部与 Prompt 全程使用完整限定名：对象 OWNER.TABLE、字段 OWNER.TABLE.COLUMN。clip_snapshot_for_prompt() 先精确匹配对象，再精确过滤该对象字段；不得使用裸字段名做全库筛选。父对象关系应留在结构化上下文中，不能依赖看得见的父表 Token 是否存在。

C-03 无 Token 或快照无效时，失效 Snapshot 仍会发送给模型

位置panels/ai_workbench_panel.py:1069-1088；tools/ai_sql_draft.py:99-108
问题_run_ai() 只在“已选 Token”时拦截失效快照。无 Token 时继续发起请求，build_safe_context() 虽附加“快照已过期”文字，仍调用 clip_snapshot_for_prompt() 并发送旧元数据。
违反需求违反 DB-04、AI-OBJ-06 与第 9 节：不能以“提示已过期”代替 fail closed。
最小修复生成前统一做快照准入：无连接、无快照、扫描失败、已过期、连接指纹不匹配时，禁止带数据库结构的生成请求。若要支持通用 SQL 草案，必须显式进入“无数据库上下文”模式，传入 snapshot=None 且 UI 明示未使用任何库结构。

C-04 对象详情“发送给 AI”绕过右键流程，Redis 可生成伪字段 Token

位置panels/ai_workbench_panel.py:1227-1241；tools/schema_snapshot.py:376-392
问题右键路径会禁用 Redis 字段选择，但对象详情的“发送给 AI”直接调用 add_field()，不做快照有效性、方言或两步选择校验。Redis 快照还把键类型伪造为 columns，因此可经对象详情产生字段 Token。
违反需求违反 AI-OBJ-04/05/08：对象详情若保留发送 AI，必须复用 Token 主流程；Redis 不伪造关系型字段。
最小修复对象详情“发送给 AI”必须打开同一受控对象/字段选择服务，或将其收敛为“发送对象”而非直接字段注入；Redis Snapshot 改展示键模式、类型、TTL 等元数据，不创建 columns 伪字段。

4. Important：应在复测前一并修复

编号问题与位置建议
I-01tools/sql_guard.py:194-252：classify_statement() 未在手工执行入口先拒绝/分类多语句；如选区为 SELECT 1; DELETE ...，可按首 SELECT 判定为无需确认。入口先调用 split_sql_statements()；多语句最稳妥做法是拒绝并要求逐条执行，至少必须标记高风险确认。补充字符串/注释含分号测试。

I-04panels/ai_token_edit.py:219-295：字段选择弹窗没有字段名/注释搜索，也没有分页/虚拟化；快照无效时右键动作仍可点，只在之后弹警告。改为明确两步 UI：对象搜索 → 字段搜索 + 多选 + 100 条分页/虚拟列表；菜单层直接禁用添加项并显示快照原因。
I-05tools/schema_snapshot.py：扫描取消仅在启动前判断，长循环中缺少 cancel 检查和进度回报。把 cancel/progress 回调传入各方言扫描循环，在对象/字段/Redis SCAN/Mongo collection 循环中周期检查；取消后不落盘、不更新 UI。

# 完成开发分支

## 概述

通过呈现清晰选项并处理选定工作流来指导开发工作的完成。

**核心原则：** 验证测试 → 呈现选项 → 执行选择 → 清理。

**开头声明：**"我正在使用完成开发分支技能来结束此工作。"

## 注意：适应 SVN 工作流

本项目使用 SVN 而非 Git。以下是适应调整：

| Git 概念 | SVN 等价 |
|---------|---------|
| `git merge` | `svn merge` + `svn commit` |
| `git branch` | SVN 分支目录（`/branches/`）|
| `git worktree` | 不适用（SVN 无此机制）|
| `git push -u` | `svn commit`（已绑定工作副本）|

## 流程

### 步骤 1: 验证测试

**在呈现选项之前，验证测试通过：**

```bash
# 运行项目测试套件
D:\development\tools\Python312\python.exe -m pytest tests/ -v
```

**如果测试失败：**
```
测试失败（N 个失败）。必须修复后才能完成：

[显示失败]

在测试通过之前不能继续。
```

停止。不要进入步骤 2。

**如果测试通过：** 继续步骤 2。

### 步骤 2: 确定基准分支

```bash
# 查看当前分支信息
svn info
```

询问："工作分支从哪个分支分出？"

### 步骤 3: 呈现选项

呈现恰好这 4 个选项：

```
实施完成。你想做什么？

1. 合并回基准分支（本地 merge + commit）
2. 直接 commit 到分支
3. 保留当前状态（稍后处理）
4. 放弃此工作

选择哪个？
```

**不要添加解释**——保持选项简洁。

### 步骤 4: 执行选择

#### 选项 1: 合并回基准分支

```bash
# 切换到基准分支
svn switch ^/trunk  # 或具体分支路径

# 合并功能分支
svn merge ^/branches/your-feature-branch

# 验证合并结果
D:\development\tools\Python312\python.exe -m pytest tests/ -v

# 提交合并
svn commit -m "Merge feature: <description>"
```

#### 选项 2: Commit 到分支

```bash
# 添加所有更改
svn status

# 提交
svn commit -m "feat: <description>

- <change 1>
- <change 2>"
```

#### 选项 3: 保留当前状态

报告："工作保存在分支 `^/branches/your-feature-branch`。"
**不要做任何清理。**

#### 选项 4: 放弃

**首先确认：**
```
这将永久删除：
- 分支上的所有提交
- 工作副本中的未提交更改

输入 'discard' 确认。
```

等待确切确认。

如果确认：
```bash
# 切回基准分支
svn switch ^/trunk

# 删除分支（如果有独立分支）
svn delete ^/branches/your-feature-branch -m "Abandon feature"
```

### 步骤 5: 清理

**对于选项 1、2、4：**

确认工作副本状态干净：
```bash
svn status
```

如果工作副本有未提交更改且不打算保留：
```bash
svn revert -R .
```

**对于选项 3：** 保留工作副本。

## 快速参考

| 选项 | Commit | Merge | 保留工作副本 | 清理 |
|--------|--------|-------|---------------|------|
| 1. 合并 | ✓ | ✓ | - | ✓ |
| 2. 直接 Commit | ✓ | - | ✓ | - |
| 3. 保留 | - | - | ✓ | - |
| 4. 放弃 | - | - | - | ✓ |

## 常见错误

**跳过测试验证**
- **问题：** 合并坏代码
- **修复：** 始终在呈现选项之前验证测试

**开放式问题**
- **问题：** "接下来做什么？" → 模糊
- **修复：** 呈现恰好 4 个结构化选项

**自动清理**
- **问题：** 删除了可能需要的工作副本（选项 2、3）
- **修复：** 只对选项 1 和 4 清理

**放弃前无确认**
- **问题：** 意外删除工作
- **修复：** 要求输入 "discard" 确认

## 红牌

**绝不：**
- 用失败测试继续
- 不验证结果就合并
- 不确认就删除工作
- 强制 commit

**始终：**
- 验证测试后再呈现选项
- 呈现恰好 4 个选项
- 对选项 4 要求输入确认
- 只对选项 1 和 4 清理

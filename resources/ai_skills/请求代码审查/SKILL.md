# 请求代码审查

## 概述

在问题级联之前，派遣代码审查子 Agent 来发现问题。

**核心原则：** 早审查，勤审查。

## 何时请求审查

**强制：**
- 子 Agent 驱动开发中每个任务之后
- 完成重大功能之后
- 合并到主分支之前

**可选但有价值：**
- 卡住时（新鲜视角）
- 重构之前（基线检查）
- 复杂 Bug 修复之后

## 如何请求

**1. 获取版本范围：**
```bash
# SVN：获取工作副本当前版本号
svnversion .
```

**2. 派遣代码审查子 Agent：**

使用 Task 工具和 `code-reviewer` 类型，填写以下占位符：

- `{WHAT_WAS_IMPLEMENTED}` - 你刚构建的内容
- `{PLAN_OR_REQUIREMENTS}` - 应该做什么
- `{BASE_REV}` - 起始提交（SVN 版本号）
- `{HEAD_REV}` - 结束提交（SVN 版本号）
- `{DESCRIPTION}` - 简要说明

**3. 处理反馈：**
- 立即修复关键问题
- 在继续之前修复重要问题
- 记录次要问题供稍后处理
- 如果审查者错了，推回去（带推理）

## 示例

```
[刚完成任务 2：添加验证函数]

你：让我在继续之前请求代码审查。

BASE_REV=$(svn info --show-item revision)  # SVN 当前版本号
HEAD_REV=$(svn info --show-item revision)  # 或记录起始/结束版本号

[派遣 code-reviewer 子 Agent]
  WHAT_WAS_IMPLEMENTED: 会话索引的验证和修复函数
  PLAN_OR_REQUIREMENTS: docs/plans/deployment-plan.md 的任务 2
  BASE_REV: r100
  HEAD_REV: r101
  DESCRIPTION: 添加了 verifyIndex() 和 repairIndex()，4 种问题类型

[子 Agent 返回]：
  优势：架构清晰，有真实测试
  问题：
    重要：缺少进度指示器
    次要：魔法数字 (100) 用于报告间隔
  评估：可以继续

你：[修复进度指示器]
[继续任务 3]
```

## 与工作流集成

**子 Agent 驱动开发：**
- 每个任务后审查
- 在问题累积之前捕获
- 修复后再继续

**执行计划：**
- 每批次（3 个任务）后审查
- 获取反馈，应用，继续

**临时开发：**
- 合并前审查
- 卡住时审查

## 红牌

**绝不：**
- 因为"很简单"跳过审查
- 忽略关键问题
- 用未修复的重要问题继续
- 对有效的技术反馈争辩

**如果审查者错了：**
- 用技术推理推回去
- 展示证明其有效的代码/测试
- 请求澄清

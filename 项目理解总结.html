一、产品定位与一句话画像

PengToolsHub 是一款 Windows 离线桌面效率工具台（单 EXE，PyInstaller 打包），服务内网开发 / 运维 / 交付日常，覆盖「需求台账 → SQL 升级 → 发版 Excel → 日报」的完整交付链路，并内置接口抓包、SSH 日志排查、国密加解密、自然语言查库等 Private 能力。作者署名 Lihp。

三、架构分层与依赖方向

run.py（入口：AUMID/单实例/闪屏/主题/代理安全清理） └─ MainWindow（导航 + QStackedWidget + 信号总线 + 面板懒加载 _ensure_*） ├─ panels/*（15 个 UI 面板：交互、Loading、只调 tools 不写算法） │ └─ tools/*（40+ 无界面业务逻辑，扁平命名，可单测） └─ ui/*（30+ 公共 UI：theme_manager / design_system / page_chrome / responsive…） 依赖铁律：run → main_window → panels → tools|ui|config ui 不 import panels/tools；tools 不 import panels
  • 懒加载启动：主窗口先建壳 + 工作台立即可见，其余面板按导航进入时构造（_ensure_panel_for_nav），后台预热分步走 _startup_tick；offscreen 测试走同步 boot。
  • 异步模式：耗时操作用 QThread Worker（completed/failed 双信号），Loading 用 AuroraProgress 浮层，成功/失败/异常三条路径都必须结束。
  • 跨模块联动全部经 main_window 信号（如 _receive_requirement_sql、_open_gateway_from_iface），面板间不深层引用对方控件。

七、硬边界与安全红线（违反即事故）

级别规则
P0离线原则：无账号/云同步/插件市场/在线更新/遥测/在线 CDN；业务代码不引入远程 HTTP/WebSocket/浏览器内核
P0HTTP 例外仅两项：① 接口排查本机 loopback（127.0.0.1 MITM + 可选 CDP），禁止暴露局域网；② 内网模型（默认关闭，用户启用后仅 data/ai_local.json 的一个 Base URL，仅 loopback + RFC1918，拒绝公网模型域名）
P0敏感数据只存内存：抓包请求/响应/Cookie/Token/Key/明文禁止写日志、JSON、搜索历史；停止抓包保留会话，仅「清空」与退出调用 clear_session()
P0凭据安全：密码不上库、不进 Git；仅 DPAPI/enc 存储，禁止新增 b64；Token 不进提示词；网关明文/SSH 密码不进提示词
P0数据根唯一：只能写 config.local_data_dir()；禁止 _MEIPASS/用户主目录；真实账密禁止进 resources/（会打进 EXE）
P0升级不删数据：只替换 EXE/程序文件；安装包不得包含用户 data
P1IE 代理：启动前备份 WinINet，停止/失败/退出必须恢复；证书仅删配置记录的指纹；应用启动时 ensure_system_proxy_safe() 清残留
P1只读底线：运维助手不自动执行破坏性命令；Harness 自然语言→SQL / Linux 仅只读（禁 rm/reboot/kill）；查询需用户点「执行查询」才发 SSH
P1日志导出：目录 resolve 到具体 .log（resolve_remote_log_file）；命名「关键字文件夹 / IP-服务.log」；远端走 stdout 流，禁止远端临时文件
P1SSH per-tab：会话按 Tab 独立，禁止全局 disconnect；终端规范化保留 \x08
P2提交前扫描：scripts/scan_release_secrets.py 必须 PASS（build 已集成）；发布产物三件套核对 + build_info.json 时间戳

八、代码规范与 UI 约定

  • 文件头：# -*- coding: utf-8 -*-；中文注释/docstring；tools 扁平命名保持 import 稳定（from tools.xxx import …）。
  • 样式：统一 resources/style.qss + ui/theme_manager.py Token 注入；新增颜色必须走 Token 且四主题全覆盖；render() 有未解析占位符即抛错（勿移除）；终端色用独立 TERM_*，禁止绑回 CODE_BG。
  • 公共组件：apply_button（primary 图标用 ON_PRIMARY）/ apply_table / apply_tree / make_page_header（PageChrome）；confirm_action / show_info / show_error 统一弹窗。
  • 删除类交互：取消在左、确认在右、默认焦点取消。
  • JSON 兼容：读用 setdefault/默认值；写保留未知旧字段；settings 原子写入（临时文件 + replace）。
  • 布尔解析：禁止裸 bool("false")，必须规范化字符串解析。
  • 响应式：Wide≥1440 / Standard 1280–1439 / Compact 1080–1279 / Narrow 960–1079；Compact/Narrow 双栏可垂直但不重排 splitter 顺序。
  • 中英文：所有可见文案走 set_language，zh/en 双份。
  • Git：commit 格式 type(scope): 中文说明；禁止 add data/、zip、截图、日志、build/dist；分支名避免斜杠（Windows 下用 feat-xxx）。

九、开发与交付流程（每轮强制）

接到需求 → 对照 AGENTS.md 判断边界 → （CodeGraph 定位调用链/影响面） → 小步改：tools 先行可单测 → panels UI → 文案/QSS → 定向测试（QT_QPA_PLATFORM=offscreen + python -m unittest tests.test_xxx） → python scripts/scan_release_secrets.py（必须 PASS） → powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_release.ps1 → 核对三产物 + resources/build_info.json 时间戳 → git add（精确路径）→ commit → push origin main
  • 测试策略：只跑本次改动覆盖的定向测试（45+ 个测试文件按模块匹配）；业务规则必须函数级断言；show_* 弹窗需 mock。
  • 打包注意：EXE 被占用报 PermissionError → 先结束 PengToolsHub 进程；打包前确认新依赖已进 requirements.txt 和 spec hidden-import。
  • 内网能力（SVN、真实抓包、内网 DB）：本环境不可验证，交付说明写「待用户内网验证」。

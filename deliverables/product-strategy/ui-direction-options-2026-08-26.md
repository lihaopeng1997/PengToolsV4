**类型**：产品头脑风暴 / UI 方向选择  
**参与成员**：方向明（产品舵手）、析客（需求分析师）、瑞思（用户研究员）、竞析（竞品分析师）、数析（数据分析师）、路径（路线图规划师）

## 📌 TL;DR（执行摘要）
- 本稿只用于确认 PengToolsHub V4 Private 的**整体 UI 组织方向**；不修改代码、不冻结单页细节，也不替代确认后产出的完整 UI 需求文档。
- 推荐选择 **C「统一壳层 + 专业模块变体」**：用一致导航、安全状态、控件与响应式规则作为底座；按场景吸收 A 的任务推进和 B 的异常调查能力。
- A「任务流驾驶舱」最适合需求→升级准备→SQL/发版材料→日报；B「案件式调查工作区」最适合接口、日志、SSH 的跨工具排障；二者都不宜强制覆盖全产品。
- 方向确认后，先以接口异常→解密/格式化→请求验证验证技术工作区，再以升级→SQL/发版材料→日报验证流程工作区；全程保持离线、安全边界和敏感数据规则。

## 1. 方向选择的共同前提

### 1.1 产品与安全硬边界

- Windows 离线 PyQt6 桌面工具；禁止引入云同步、遥测、浏览器内核和在线 CDN。
- 敏感会话、Cookie、Token、网关密钥与明文继续保持既有不落盘/最小暴露边界；模型对话的本机 `data/` 明文历史是用户已确认的唯一例外，必须持续可见说明。
- 高风险动作必须由人确认：真实请求验证、SSH 终端执行、SQL 执行、证书信任、删除/清空/回滚/SVN 提交等均不得被 UI 包装成无副作用行为。
- 维持现有四层页面骨架：**L1 页头 → L2 工具栏 → L3 筛选条 → L4 内容区**；每页仅一个主操作，操作与筛选分离。

### 1.2 必须优先保障的任务链

| 优先级 | 任务链 | UI 的关键要求 |
|---|---|---|
| P0 | 需求 → 升级准备 → SQL/发版材料 → 日报 | 不丢需求上下文；步骤、产物、阻塞和下一步清晰；不完整资料不阻断可完成部分 |
| P0 | 接口异常 → 会话筛选/阅读 → 解密/格式化 → 请求验证 | 证据、请求/响应、派生结果与验证参数连续可见；始终知道是否会真实发送 |
| P0 | 日志/SSH 排障 | 主机、服务、日志、会话、命令与风险状态持续可见；“填入/生成/执行”严格分层 |
| P1 | 轻工具输入 → 处理 → 复制/导出 | 单任务聚焦，不用卡片堆叠或复杂多窗格压低效率 |

### 1.3 文案、空态与小窗口基线

已完成独立审计，详见：`ui-control-copy-audit-2026-08-26.md`。后续任一方向均须继承以下硬门槛：

- 7 个无配置下拉框必须显示可理解的空态与下一步：工作台月份、设置 AI 模型、日志服务器/服务/日志文件、SQL 连接、模型对话模型。
- 960×640、125%/150% DPI 下不得截断关键按钮和当前 Tab；空间不足时进入上下文明确的“更多”菜单。
- 远端与高风险动词按对象区分：HTTP 为“发送请求”、SSH 为“执行命令”、模型为“发送消息”；生成草稿、复制、载入、导出、清空、删除均须表明对象与范围。
- 接口敏感内容、抓包证书、会话清理、请求验证、删除连接及结构快照等安全提示，必须与真实行为一致。

## 2. 方向 A：任务流驾驶舱

### 2.1 一句话定位
把专业模块重新组织为“我现在要完成什么”，围绕准备→执行→校验→结果推进标准化交付任务。

### 2.2 信息架构与视觉语言

| 维度 | 设计定义 |
|---|---|
| 一级结构 | 工作台、业务任务流、工具库、结果与历史、设置 |
| 任务流分类 | 升级与变更、接口保障、车辆与安全、运维排障、协作与管理、辅助工具 |
| 工作台 | 今日待办、进行中任务、最近结果、常用任务模板、失败/超时任务；唯一主操作依上下文为“继续任务”或“开始任务” |
| 页内形态 | 顶部任务目标和当前阶段；中区步骤清单 + 主工作区；右侧/底部为可收起的任务摘要、风险、运行日志、校验结果 |
| 视觉语言 | 克制企业工作台；步骤编号、进度、状态与留白表达层级；避免用卡片瀑布流替代任务重点 |
| 核心交互 | 主操作始终推进当前阶段；保存草稿、导出、重置进入次级区或更多菜单；结束后生成脱敏的结果摘要 |

### 2.3 最适合与不适合的任务

| 适合 | 不适合 |
|---|---|
| 升级准备、SQL/发版材料、日报、接口文档更新等步骤相对稳定的任务 | 临场、非线性、频繁回退的接口/SSH/日志排障 |
| 需要检查点、产物、责任与恢复路径的交付任务 | 单次格式化、临时查询、一次性解密等轻工具 |

### 2.4 优点、风险与待验证假设

**优点**
- 直接解决“需求、SQL、升级、日报被不同模块拆散”的问题。
- 对漏项、阻塞、未完成资料和交接更友好。
- 工作台可从“模块入口集合”转为“继续未完成工作”。

**风险**
- 将探索式排障强行线性化，可能增加点击和维护成本。
- 任务模板若与真实流程不一致，用户会绕开驾驶舱回到旧模块。
- 若首页堆积卡片，反而挤压专业工具入口。

**待验证假设**
1. 高频升级工作具有可复用的准备、执行、校验步骤。
2. 用户愿意选择任务模板，以换取上下文恢复与检查点。
3. “继续最近任务”比按模块找入口更符合进入首页后的首要预期。

### 2.5 推荐验证与落地路径

| 阶段 | 范围 | 验证点 |
|---|---|---|
| A0 | 任务上下文、全局状态、空态/安全/小窗口规则 | 任务入口、风险状态与关键控件在 960×640 下均可理解 |
| A1 | **升级准备 → SQL/发版材料 → 日报**任务模板 | 用户不凭记忆在多个模块找入口；关键产物、阻塞与回跳路径可见 |
| A2 | 需求拆解、发版核验、日报汇总等第二类流程 | 至少两个流程复用任务骨架但不造成字段膨胀 |
| A3 | 对非线性工具提供“转入专业工作区” | 不要求用户为日志/SSH/接口排障伪造线性步骤 |

## 3. 方向 B：案件式调查工作区

### 3.1 一句话定位
围绕一次异常、变更或排障“案件”聚合线索、工具操作、验证结果与交接结论，避免跨工具调查丢失上下文。

### 3.2 信息架构与视觉语言

| 维度 | 设计定义 |
|---|---|
| 一级结构 | 工作台、案件、工具目录、资产与输出、设置 |
| 案件状态 | 待处理、调查中、待交接、已关闭 |
| 案件视图 | 概览、线索时间线、操作与结果、关联对象、结论/交接 |
| 主布局 | 三栏调查桌面：左侧案件范围/关联对象，中间专业工具/证据，右侧线索、风险、行动与结论；窄屏右栏退为抽屉 |
| 核心交互 | 工具操作生成脱敏行动摘要，可追加到案件时间线；关闭前展示影响对象、已做操作、未解决事项 |
| 安全边界 | 原始 Token、Cookie、明文和密钥默认不进入案件时间线；仅在用户确认后记录脱敏摘要 |

### 3.3 最适合与不适合的任务

| 适合 | 不适合 |
|---|---|
| 接口异常、日志排查、SSH 诊断、VIN/网关关联问题等跨工具、跨时间、需要交接的调查 | 单次格式转换、一次性查询、短时脚本执行、简单数据生成 |
| 需要复盘、交接、证据链或持续数小时/数天的问题 | 不愿维护任何记录的极短任务 |

### 3.4 优点、风险与待验证假设

**优点**
- 让接口、日志、SSH、解密、格式化的证据和判断保持在同一个工作语境。
- 适合高压排障中的状态、范围、风险与交接。
- 有助于最小化记录敏感原文，仅沉淀脱敏结论。

**风险**
- “案件”建立与记录可能成为额外负担。
- 若案件默认持久化，可能扩大敏感数据留存面。
- 多窗格在 960×640 下易拥挤，必须有聚焦和抽屉降级。

**待验证假设**
1. 高价值故障通常会跨多个专业工具、跨时间推进。
2. 用户确实需要交接/复盘，且可接受只保留脱敏摘要。
3. 少量案件模板可覆盖主要排障类型。

### 3.5 推荐验证与落地路径

| 阶段 | 范围 | 验证点 |
|---|---|---|
| B0 | 案件上下文、证据/操作/结论骨架 | 可从接口、日志、SSH 进入同一异常上下文；无隐式云同步 |
| B1 | **接口异常 → 筛选/阅读 → 解密/格式化 → 请求验证** | 原始证据、派生结果和验证判断连续可见，用户无需手工拼接 |
| B2 | 日志、SSH、证书/快照检查接入 | “查看”与“可能改变环境”有显著视觉和文案区分 |
| B3 | 本地案件归档、重开、交接摘要转日报/任务 | 不扩大敏感原始数据留存，结论仍可复用 |

## 4. 方向 C：专业工具箱中枢

### 4.1 一句话定位
建立统一应用壳层、导航、安全反馈和设计系统，同时让每个专业模块采用最适合自身任务的工作区形态，支持渐进式改造。

### 4.2 信息架构与视觉语言

| 维度 | 设计定义 |
|---|---|
| 一级结构 | 工作台、收藏与最近、工具分类、管理与协作、设置 |
| 工具分类 | 数据与升级、接口与诊断、车辆与安全、运维、协作、生产力 |
| 应用壳 | 可收缩侧栏、统一页头/工具栏/筛选条/内容区、全局运行与安全状态、统一确认与反馈 |
| 技术模块工作区 | IDE 式多窗格或“参数—预览—结果”模板；适用于接口、SQL、SSH、日志、加解密、格式化 |
| 流程模块工作区 | 任务步骤、产物与检查点；适用于需求、升级准备、SQL/发版材料、日报 |
| 轻工具工作区 | 输入—处理—结果—复制/导出，渐进披露高级选项；适用于 VIN、证件、格式等 |
| 核心交互 | 收藏、最近、固定快捷操作、命令搜索、带确认的跨模块上下文打开；不默认保存敏感正文 |

### 4.3 最适合与不适合的任务

| 适合 | 不适合 |
|---|---|
| 存量模块成熟但体验不一致，需保留专业效率并分批换新 | 把系统天然变成完整案件管理或强制流程编排 |
| 多角色、多密度、多任务类型同时存在的离线桌面工具 | 未经验证的全局自动编排、云端协同、实时监控大屏 |

### 4.4 优点、风险与待验证假设

**优点**
- 统一性与专业效率兼顾：壳层统一，内容区按专业任务变化。
- 与当前 PyQt6 存量模块和四层页面骨架兼容，能逐模块迁移、每轮独立验收。
- 优先解决“快速找到工具、动作/状态可预测、敏感边界可见”，不需要先赌全局任务或案件模型。

**风险**
- 若壳层只换视觉不改变状态、空态、风险反馈，会沦为“只换皮”。
- 规范若过强，可能压缩 SSH、日志、SQL 的高密度能力。
- 新旧模式并存期可能增加用户迷失；需定义旧新入口切换条件。

**待验证假设**
1. 多数用户首先要快速找到正确工具，而不必先进入任务或案件模型。
2. 统一导航、页头、主操作、状态与反馈已足以显著降低学习成本。
3. 技术、流程、轻工具三种工作区变体能共用壳层而不牺牲效率。

### 4.5 推荐验证与落地路径

| 阶段 | 范围 | 验证点 |
|---|---|---|
| C0 | **统一壳层**：导航、模块入口、全局状态、确认、空态、下拉、窗口规格、控件/文案 Token | 接入模块时不改变离线与安全行为；所有关键入口、无配置态、长文本和 960×640 达标 |
| C1 | **接口异常调查型技术模块**：会话筛选/阅读、解密/格式化、请求验证 | 验证多窗格、参数—预览—结果、可能真实发送时的完整状态和确认；旧核心行为无回归 |
| C2 | 三类模块分型迁移：日志/SSH 专业变体；升级/SQL/日报流程变体；轻工具单任务变体 | 三种变体共用壳层，仍保留专业操作密度与清晰的风险边界 |
| C3 | 收口：清理重复导航/异构状态，建立常用/最近、本地上下文交接与统一帮助 | P0 链路端到端一致；新旧入口不并存造成迷失 |

## 5. 三套方向对比与选择建议

| 维度 | A 任务流驾驶舱 | B 案件式调查工作区 | C 专业工具箱中枢（推荐） |
|---|---|---|---|
| 首要组织单位 | 一项标准任务 | 一次异常/变更案件 | 一个专业工具，统一壳层承接 |
| 最优场景 | 升级、发版、日报等稳定流程 | 接口、日志、SSH 等跨工具排障 | 复杂技术工具 + 流程模块 + 轻工具共存 |
| 首个验证模块 | 升级→SQL/发版材料→日报 | 接口异常调查 | 接口异常技术工作区 |
| 对现有模块的适配 | 中：需抽取稳定步骤 | 中：需建立案件与证据模型 | 高：可保留模块业务边界、渐进改造 |
| 用户学习成本 | 中：理解任务模板 | 中高：理解案件/证据组织 | 低中：先熟悉统一壳层，模块能力仍可直达 |
| 实施风险 | 中高：流程模板维护和非线性任务冲突 | 高：敏感持久化、记录负担、多窗格小屏问题 | 中：需防止“只换皮”和新旧入口并存 |
| 对离线与安全边界 | 可适配，但任务历史需谨慎留存 | 风险最高，案件持久化必须最小化 | 最稳：逐模块保持既有边界，并统一可见安全提示 |
| 是否建议作为唯一全局范式 | 否 | 否 | 是，但模块内容区允许 A/B 能力按场景激活 |

### 推荐决策

选择 **方向 C：专业工具箱中枢** 作为产品的唯一全局底座，并吸收：

- **A 的能力**：仅用于需求→升级准备→SQL/发版材料→日报等高频、稳定的流程型模块；以轻量步骤、检查点、产物与恢复路径组织，不强行流程化技术排障。
- **B 的能力**：仅用于接口、日志、SSH 等异常调查场景；以案件摘要、证据线索、脱敏交接结论辅助排障，不把“案件”作为所有工具的前置条件。

这是一条“**全局统一，模块专业；壳层稳定，内容适配任务**”的路线。

## 6. 推荐方向的分阶段优先级与验证闸门

### 6.1 优先级路线

| 阶段 | 优先级 | 关键交付 | 核心模块 / 任务 | 不做什么 |
|---|---|---|---|---|
| P0-1 | P0 | C0 统一壳层与基础规范 | 全局导航、四层骨架、空态/下拉、确认、状态、960×640 响应 | 不重写业务逻辑，不做首页大屏化 |
| P0-2 | P0 | C1 接口异常技术工作区 | 异常→筛选/阅读→解密/格式化→请求验证 | 不把请求验证伪装成仅草稿；不扩大敏感会话留存 |
| P0-3 | P0 | 日志/SSH 专业工作区 | 主机→服务/日志→读取/截取→终端/导出 | 不做自动远端执行；不破坏 per-tab 会话边界 |
| P1-1 | P1 | A 型流程工作区 | 需求→升级准备→SQL/发版材料→日报 | 不让固定流程取代专业 SQL/接口页面 |
| P1-2 | P1 | B 型调查摘要 | 接口/日志/SSH 异常的脱敏交接、转日报/任务 | 不前置复杂案件管理或保存原始敏感内容 |

## 2. 这次要实现什么

### 2.1 全局 UI 目标

- 将软件统一为 C「专业工具箱中枢」：统一导航、页头、工具栏、筛选条、内容区、状态、空态、确认弹窗与响应式规则。
- 高密度技术工具保持专业工作区：输入、输出、列表、终端、结果和编辑器优先占据工作面积。
- 全部存在并列/上下独立展示区的页面，使用真实 `QSplitter` 与表头列宽调整；不劫持正文、终端、编辑器或列表行的拖拽。
- 统一 Loading：短操作不闪烁；长任务可观察、可取消/可恢复；不遮挡关键风险信息和已加载结果。
- 主题实现四套：Calm、Clear、Warm、Black。四主题只改变颜色与表面温度，不改变布局、控件位置、安全语义或终端边界。
- 使用克制的轻玻璃层级、悬浮 Tab、分隔条抓手与 120–180ms 微动效；不得做霓虹、扫描线、呼吸灯、大屏监控感、全局毛玻璃或高频动画。

### 2.2 UI 不改变业务行为

UI 重构仅允许调整：布局、间距、QSS Token、容器层级、控件尺寸、显示密度、状态展示、Tooltip、无障碍、响应式收纳、Splitter 比例、表格列宽与 Loading 表现。

不得借 UI 重构改变：网络发送、SSH 执行、SQL 执行、SVN 操作、删除语义、密码/密钥/Token 存储、接口会话生命周期、模型聊天历史、数据路径、导出规则或权限规则。

## 3. 不可变更功能（硬约束）

### 3.1 需求管理

- 需求目录继续**按月展示**。
- 必须保留月份展开/折叠、选择需求、删除所选需求、搜索与筛选。
- 原有顶部按钮、需求目录业务能力、文件与 SVN、关联 SQL、上线与联动、测试点均不得删除或改写业务语义。
- 允许增加：目录/详情/右侧信息的可拖拽展示比例、统一样式、删除确认的对象/月份/影响说明。
- 不将需求目录改为平铺卡片流；不改变月份归属、排序、选择和删除数据逻辑。

### 3.2 文件库与 SVN

以下按钮必须原样保留：**文字、顺序、功能、启用/禁用条件、图标、快捷操作、确认流程均不得调整**：

`打开目录` → `刷新` → `更新` → `添加文件` → `新建文本` → `锁定` → `解锁` → `回滚` → `提交`

- 只允许统一外观、间距、容器样式，以及窄宽度下的横向滚动。
- 不隐藏、合并、换名、移入“更多操作”、改为纯图标或重排这些按钮。
- 文件树、文件表、详情区可以支持 Splitter 和列宽调整，但不得改变 SVN 行为。

### 3.3 SQL 控制台与 TamengAgent

- SQL 控制台用户可见右侧名称继续为**“AI 助手”**，不得改名为 TamengAgent。
- `TamengAgent` 是后台 Schema 证据编排器代码/架构名称：它先校验有效 Schema 快照、解析候选表/字段/索引、构建证据、调用内网模型、再本地复核模型 SQL。
- 用户可见草案页签名称使用 **“SQL 草案 · 未执行”**；不得显示 TamengAgent 名称。
- 用户输入“查询 prpcmain 中创建日期倒序”时，只有快照能证明 `PRPCMAIN.CREATED_DATE` 时才能生成 `ORDER BY CREATED_DATE DESC`；字段歧义必须让用户选择，禁止猜测 `createddate`。
- “生成 SQL 草案”与现有“执行当前 SQL”必须是独立按钮、独立调用路径、独立状态；绝不自动执行。
- TamengAgent 的详细开发规则、快照 V2、索引元数据、候选消歧和回归用例以 `TamengAgent_SQL_Schema_开发规格_V1.0.md` 为准。

## 4. 全局 UI 实施规则

### 4.1 页面骨架

每个页面遵循四层：

1. **L1 页头**：图标、标题、副标题、当前状态、最多一个主操作。
2. **L2 工具栏**：当前对象高频操作；不混入搜索和筛选。
3. **L3 筛选条**：搜索、筛选、排序、环境/日期等上下文；不放会改变业务数据的动作。
4. **L4 内容区**：列表、树、输入、编辑器、结果、终端、表格和主要工作内容。

核心工作内容优先于说明、帮助、历史和低频配置。不要用冗余标题、固定说明卡、重复状态和按钮堆挤占 L4。

### 4.2 按钮

- 连续任务优先横排；同一组最多保留 1 个主操作 + 2 个高频次操作 + 1 个“更多操作”。
- 空间不足时顺序为：删除冗余装饰 → 缩短次要按钮文案 → 将低频动作放入“更多操作” → 调整字段布局；不得截断主按钮/取消按钮、缩小字体或堆成难看的瀑布式竖排。
- 高风险操作保留对象、范围、影响和取消路径，不能只显示图标或模糊词。
- 文件库按钮是第 3.2 节例外，按原顺序常显并允许横向滚动。

### 4.3 Loading

- `<150ms`：无 Loading，仅按压/选中反馈。
- `150–399ms`：仅触发控件忙碌，防重复点击。
- `400–799ms`：受影响容器局部 Loading，保留旧结果。
- `≥2s`：显示阶段、耗时、取消/重试或后台继续入口。
- 搜索、筛选、选中、Tab 切换、主题切换、列宽、Splitter、复制等禁止全局/页面级 Loading。
- Loading 不占布局，不清空已有内容，不遮挡环境、主操作、错误、风险提示和分隔条。

### 4.4 拖拽与响应式

- 仅 `QSplitter` handle 和 `QHeaderView` 列边界可拖拽；正文、编辑器、终端、表格单元格、树节点、滚动区不劫持为调整尺寸。
- Splitter：实际命中带 6–8px、可见轨道 1–2px、hover/focus resize 光标、可键盘等价操作、双击恢复当前页/Tab/模式默认比例。
- 设置 `setChildrenCollapsible(False)` 与明确的最小尺寸；关键区不得被拖至 0 或不可读。
- Wide `≥1440`、Standard `1280–1439`、Compact `1100–1279`、Narrow `960–1099`；小于 `960×640` 不继续压缩关键区。
- 窄窗口优先切上下布局、Tab、Drawer 或明确“显示目录/显示会话列表”入口，不得挤出多条窄缝。
- 布局偏好仅保存非敏感的分隔比例、列宽和可见性；按页面 + Tab/模式 + 窗口档位本机保存，释放后约 250ms 防抖写入。

### 4.5 四主题、轻玻璃、悬浮 Tab

- 主题：Calm（默认办公）、Clear（排障/数据）、Warm（阅读/记录）、Black（低眩光工程）。
- 所有颜色从统一 Token 获取；正文/代码/表格/按钮文字对比度目标 `≥4.5:1`，边界/焦点/Tab/分隔条目标 `≥3:1`。
- 终端始终使用独立 `TERM_*` Token，不绑定回 `CODE_BG`。
- 轻玻璃只用于 Tab、Menu、Drawer、Dialog、Toast、Loading 和低频首页入口。SQL 编辑器、日志、终端、报文、表格、密钥输入、错误和风险确认必须使用实底高对比表面。
- 激活 Tab 可用表面抬升、细边框和 2px 主色短线形成轻悬浮感；不得位移动画、厚阴影或遮挡相邻 Tab。

## 6. 实施顺序与闸门

### P0-0：全局设计系统与保护规则

- 建立主题 Token、四层页面骨架、按钮角色、空态、风险确认、Loading、Splitter 与响应式基础组件。
- 先加/更新定向 UI 测试门禁：页面骨架、按钮文字/Tooltip、Tab 标题、空下拉、关键风险确认、可拖拽最小尺寸。

**通过条件**：全局壳和公共组件可复用；不改变任何业务行为；四主题和主状态可读。

### P0-1：高风险技术页面

依次重构：接口排查 → 日志/SSH → SQL 控制台（含 AI 助手 UI）。

**通过条件**：真实发送/执行目标和风险持续可见；Loading 可恢复；编辑器、响应、终端和结果不被压缩；SQL 的 AI 助手仍不执行 SQL。

### P0-2：需求交付链路

依次重构：需求管理 → 文件与 SVN → 升级准备 → 接口文档更新 → 日报。

**通过条件**：按月需求目录和文件库九按钮完整保留；所有既有业务动作可达且行为不变；关键列表/详情可拖拽。

### P0-3：TamengAgent 后台能力

按 `TamengAgent_SQL_Schema_开发规格_V1.0.md` 的 P0-4A 至 P0-4D 实施快照 V2、证据编排、AI 助手集成与安全回归。

**通过条件**：TamengAgent 不作为可见 UI 名称；无有效快照不调用模型；字段歧义不猜测；生成和执行隔离。

### P1：其余页面与体验收口

格式工具、加解密、证件/VIN、命令库、模型对话、设置；完善四主题、轻玻璃、悬浮 Tab、所有 Splitter/列宽持久化与高 DPI 回归。

### P2：非阻断增强

低频页面细节、局部动效与辅助信息优化；不得进入新的业务能力、云同步、遥测、浏览器内核或自动化执行范围。

## 7. 每批开发与验收要求

每个批次都必须：

1. 先阅读本批对应页面源码、现有定向测试和 V1.2 设计稿。
2. 只修改本批覆盖的公共组件和页面；发现需要改变业务语义时停止并单独说明。
3. 先补/调整本批定向测试，再实现页面。
4. 验证 `1440×900`、`1280×800`、`1100×720`、`960×640` 以及 `100% / 125% / 150%` DPI 下的主要状态。
5. 必测：默认态、空态、Loading、失败/取消、风险确认、拖拽极限、双击重置、Tab/主题切换和窄窗回退。
6. 执行敏感信息扫描、`scripts/build_release.ps1`、构建信息与发布产物核验。
7. 不提交 `data/`、Token、密钥、日志、报文、临时截图、构建临时文件或用户本地配置。
8. 每批提交前汇报：修改文件、保留功能核对、定向测试、构建/扫描结果、截图、未完成项和待内网验证项。

## 8. 明确禁止项

- 不把 TamengAgent 显示为“AI 助手”的新名称、按钮名、Tab 名或草案名。
- 不改需求目录的按月逻辑、展开/折叠、选择、删除或原有按钮业务行为。
- 不改文件库九个按钮的文字、顺序、功能、图标、快捷操作、启用规则和确认流程。
- 不以 UI 重构为由改变 HTTP 请求、SSH 执行、SQL 执行、SVN、导出、密钥、会话、历史或权限语义。
- 不将请求验证的环境、认证、HTTPS、URL 拆成凸起大卡片；不将响应/请求正文挤成小区域。
- 不做全局毛玻璃、霓虹、扫描线、粒子、呼吸灯、监控大屏、持续循环动效或页面转场。
- 不通过缩小字体、截断主按钮、隐藏关键状态或三栏硬压来处理窄窗口。
- 不新增云同步、遥测、在线 CDN、浏览器内核、联网 Schema 获取、自动 SQL 执行或跨环境批量执行。
